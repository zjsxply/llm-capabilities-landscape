# 1.10 Long Context

## 1.10.1 Leaderboard

- [LongBench Leaderboard](https://longbench2.github.io/) ([code](https://github.com/THUDM/LongBench)): A public leaderboard spanning LongBench to LongBench v2, covering multi-document QA, long-range reasoning, summarization, and controlled settings such as RAG/no-context/CoT; one of the most common continuous reference points for text long-context capability.
- [HELMET Leaderboard](https://princeton-nlp.github.io/HELMET/) ([code](https://github.com/princeton-nlp/HELMET)): A long-context leaderboard organized by dimensions such as retrieval, RAG, reranking, reasoning, and learning; useful for avoiding the overuse of needle-style tasks as a proxy for long-context capability.
- [MileBench Leaderboard](https://milebench.github.io/) ([code](https://github.com/milebench/MileBench)): A multimodal long-context leaderboard, suitable for tracking model differences under long videos, image sequences, and cross-modal long inputs.
- [AcademicEval](https://github.com/ulab-uiuc/AcademicEval): A leaderboard and evaluation script set for live long-context generation, using new arXiv papers to construct tasks; suitable for evaluating model capability to generate titles, abstracts, and related work in long-paper contexts.

## 1.10.2 Bench

Note: These benchmarks often do not require a specially named solver agent. The more common form is `a benchmark-provided harness (chunking, RAG toggles, no-context controls) + pluggable context compression/retrieval components`. Long-term memory across sessions and tasks is listed separately in [1.15 Memory](01-15-memory.zh.md); this section only keeps projects directly related to one-time long inputs or context-growth processes.

- [DUDE](https://arxiv.org/abs/2305.08455): Evaluates the effect of image-text long context on document understanding; the core idea is to use mixed image-text long input as the main load and emphasize evidence alignment.
- [L-Eval](https://arxiv.org/abs/2307.11088) ([code](https://github.com/OpenLMLab/LEval)): What it evaluates: long-context QA, summarization, and closed-book/open-book tasks; core idea: establish a standardized long-context evaluation protocol, with early distinctions among context length, task type, and input dependence.
- [LongBench](https://arxiv.org/abs/2308.14508): Evaluates task completion quality under long context across a multitask set; the core idea is to compare `long input vs. truncation/no context` with unified data and scripts, exposing long-range dependency failure modes. ([code](https://github.com/THUDM/LongBench))
- [BAMBOO](https://arxiv.org/abs/2309.13345) ([code](https://github.com/RUCAIBox/BAMBOO)): What it evaluates: long-text modeling capability, including cross-segment reasoning, summarization, and information localization; core idea: use a multitask set to diagnose LLM weaknesses in long-text structural understanding.
- [Needle In A Haystack](https://github.com/gkamradt/LLMTest_NeedleInAHaystack): What it evaluates: single-needle retrieval in long context; core idea: bury the target segment at different depths and lengths to quickly expose the gap between the "claimed window" and the "usable window."
- [LV-Eval](https://arxiv.org/abs/2402.05136) ([code](https://github.com/infinigence/LVEval)): What it evaluates: long-context performance across different length ranges up to 256K; core idea: use length levels for more balanced comparison and avoid evaluating only at a single length point.
- [InfinityBench (∞Bench)](https://arxiv.org/abs/2402.13718) ([code](https://github.com/OpenBMB/InfiniteBench)): What it evaluates: capability on ultra-long context tasks exceeding 100K tokens; core idea: push evaluation length limits into larger ranges and explicitly expose degradation curves and the impact of truncation strategies under long input.
- [Counting-Stars](https://arxiv.org/abs/2403.11802) ([code](https://github.com/nick7nlp/Counting-Stars)): What it evaluates: multi-evidence retrieval and reasoning in long contexts. Core idea: vary evidence position and count so models must collect distributed clues rather than solve a single-needle lookup.
- [NovelQA](https://arxiv.org/abs/2403.12766) ([project page](https://novelqa.github.io/), [dataset](https://huggingface.co/datasets/NovelQA/NovelQA)): What it evaluates: QA over book-length novels beyond 200K tokens. Core idea: require long-range character, event, and detail understanding so models are tested on narrative evidence spread across an entire work rather than on isolated needles.
- [RULER](https://arxiv.org/abs/2404.06654) ([code](https://github.com/hsiehjackson/RULER)): What it evaluates: the "real usable context length" of long-context models; core idea: systematically diagnose the gap between "claimed window size" and "usable window size" with multiple needle/dependency forms.
- [MileBench](https://arxiv.org/abs/2404.18532) ([code](https://github.com/milebench/MileBench)): What it evaluates: multimodal long-context model performance on long videos, long image-text sequences, and cross-modal retrieval/reasoning; core idea: extend long-context pressure from pure text to multimodal input and provide a public leaderboard for alignment.
- [MRCR](https://huggingface.co/datasets/openai/mrcr): What it evaluates: multi-needle coreference retrieval and localization in long context; core idea: place same-distribution requests with `2 / 4 / 8 needles` into long conversations and require the model to return the target segment in the specified order, testing real long-range distinction and indexing capability.
- [GraphWalks](https://huggingface.co/datasets/openai/graphwalks): What it evaluates: graph-traversal-style multi-hop reasoning in long context; core idea: encode graph operations such as BFS and parents as structured tasks in long prompts, testing whether models can maintain structural state and execute multi-step reasoning correctly in long input.
- [MMLongBench-Doc](https://arxiv.org/abs/2407.01523): Evaluates long-document multimodal understanding; the core idea is to use document-style multimodal input to test cross-page/cross-segment alignment and summary compression.
- [FRAMES](https://arxiv.org/abs/2409.12941) (dataset: [google/frames-benchmark](https://huggingface.co/datasets/google/frames-benchmark)): What it evaluates: factuality, retrieval, and multi-hop reasoning in retrieval-augmented and long-document environments; core idea: use questions that require integrating evidence across multiple documents to jointly measure `factuality + retrieval + reasoning`.
- [HELMET](https://arxiv.org/abs/2410.02694) ([code](https://github.com/princeton-nlp/HELMET)): What it evaluates: a multidimensional long-context evaluation set; core idea: combine dimensions such as retrieval, RAG, reranking, reasoning, and learning, avoiding the use of only needle-style tasks as a proxy for long-context capability.
- [LongBench v2](https://arxiv.org/abs/2412.15204): Evaluates updated long-context task families and stronger control protocols; the core idea is to make toggles such as `--rag N / --no_context / --cot` explicit, strengthening controllable variables in the benchmark-side harness. ([code](https://github.com/THUDM/LongBench))
- [LongDocURL](https://arxiv.org/abs/2412.18424): Evaluates information localization and citation consistency over long documents plus URLs/citation chains; the core idea is to make alignment between external references (URLs) and long-document evidence central to scoring.
- [NoLiMa](https://arxiv.org/abs/2502.05167): What it evaluates: long-context understanding beyond literal matching; core idea: reduce needle-style retrieval shortcuts through rewriting, indirect reference, and non-literal clues, emphasizing true semantic localization and reasoning.
- [ETHIC](https://aclanthology.org/2025.naacl-long.283/) ([code](https://github.com/dmis-lab/ETHIC)): What it evaluates: long-context tasks with high information coverage. Core idea: force models to use many relevant pieces of a long input, reducing the bias toward benchmarks answerable from one retrieved span.
- [MMLongBench](https://arxiv.org/abs/2505.10610): Evaluates a multimodal long-context task family; the core idea is to make robustness under mixed `long visual / long text` input reproducible.
- [ToolHaystack](https://arxiv.org/abs/2505.23662): What it evaluates: information retention and invocation decisions for tool-augmented models in long-term interaction; core idea: extend haystack stress tests to realistic multi-turn tool-use settings and observe alignment among historical evidence, tool results, and the current goal.
- [LongBioBench](https://arxiv.org/abs/2506.02921) ([code](https://github.com/Thomasyyj/LongBio-Benchmark), [dataset](https://huggingface.co/datasets/thomasyyj/LongBioBench_Sample)): What it evaluates: controllable long-context understanding over biographical narratives. Core idea: construct coherent long-context examinations where target facts are meaningfully embedded, making difficulty and evidence position easier to control than in purely synthetic needle tasks.
- [PRELUDE](https://arxiv.org/abs/2508.09848): What it evaluates: long-context tasks requiring global understanding and cross-segment reasoning; core idea: make questions depend on the overall document structure and combinations of distant evidence, reducing the evaluation bias that local segment retrieval alone can answer.
- [LongLeader](https://arxiv.org/abs/2509.23161): What it evaluates: a comprehensive long-context leaderboard and evaluation framework. Core idea: unify ranking criteria across tasks, length ranges, and metrics, avoiding overrepresentation of long-context capability by a single LongBench/needle task.
- [LiteraryQA](https://arxiv.org/abs/2510.13494): Evaluates long-document narrative question answering on cleaned literary works. Core idea: repair noisy NarrativeQA-style samples and study automatic metrics so long-context narrative understanding is measured with more reliable evidence.
- [AcademicEval](https://arxiv.org/abs/2510.17725) ([code](https://github.com/ulab-uiuc/AcademicEval); [dataset](https://huggingface.co/datasets/ulab-ai/AcademicEval)): What it evaluates: long-context generation tasks based on new arXiv papers; core idea: continuously connect sources to new papers and automatically construct tasks such as Title, Abstract, Introduction, and Related Work, reducing label leakage and covering hierarchical abstraction capability.
- [LooGLE v2](https://arxiv.org/abs/2510.22548) ([code](https://github.com/MuLabPKU/LooGLE-v2), [dataset](https://huggingface.co/datasets/MuLabPKU/LooGLE-v2)): What it evaluates: real long-text understanding from 16K to 2M tokens. Core idea: use long-document tasks in legal, finance, gaming, and code domains to test distant dependencies and global understanding, avoiding the use of only needle retrieval as a proxy for long-context capability.
- [SYNC](https://doi.org/10.18653/v1/2025.emnlp-main.1707): Evaluates long-context understanding with synthetic, controlled tasks. Core idea: isolate context-length and reasoning variables so model comparisons are less confounded by uncontrolled document content or task construction.
- [CL-Bench](https://arxiv.org/abs/2602.03587): Evaluates long-context learning and memory-organization capability; the core idea is to use a more systematic context-learning task family to make "what to remember, when to use it, and how to cite it" comparable.
- [LOCA-bench](https://arxiv.org/abs/2602.07962) ([code](https://github.com/hkust-nlp/LOCA-bench)): What it evaluates: robustness of language agents under continuously growing context; core idea: turn long context from "single-shot input" into a "controlled growth process," specifically testing failure boundaries of memory/compression/retrieval strategies.
- [YC-Bench](https://arxiv.org/abs/2604.01212): What it evaluates: long-term planning and consistent execution; core idea: make agents repeatedly use historical goals, resource states, and intermediate decisions in ongoing management-style tasks, observing the real benefits of context truncation, scratchpads, and memory strategies.

## 1.10.3 Agent Harness

Note: In the public ecosystem, there are not many solver agents named only for a specific long-context benchmark. More common are reusable long-horizon agent practices such as segmented loading, state summaries, failed-branch logging, and pluggable compression/retrieval components.

- [LLMLingua](https://arxiv.org/abs/2310.05736) ([code](https://github.com/microsoft/LLMLingua)): A pluggable context-compression component, often used in long-context agents to reduce irrelevant token interference and improve effective information density.
- [LongLLMLingua](https://arxiv.org/abs/2310.06839) ([code](https://github.com/microsoft/LLMLingua)): Compression and reordering strategies for longer inputs, emphasizing retention of key reasoning evidence under high compression ratios.
- [RAPTOR](https://arxiv.org/abs/2401.18059) ([code](https://github.com/parthsarthi03/raptor)): Organizes document memory with recursive summary trees, allowing agents to retrieve and aggregate evidence across context chunks at different granularities.
- [LongAgent](https://arxiv.org/abs/2402.11550) ([evaluation code/data](https://github.com/zuucan/needleinahaystack-plus)): A multi-agent collaborative long-context harness; the core idea is to assign ultra-long texts to multiple member agents and have a leader agent aggregate local evidence, making it suitable as an alternative to stuffing the entire input into one prompt.
- [HippoRAG](https://arxiv.org/abs/2405.14831) ([code](https://github.com/OSU-NLP-Group/HippoRAG)): Adds knowledge-graph-like association and hippocampus-inspired retrieval mechanisms to RAG, suitable for long-range factual association and multi-hop evidence organization.
- [Chain-of-Agents](https://arxiv.org/abs/2406.02818) ([unofficial implementation](https://github.com/rudrankriyam/Chain-of-Agents)): Splits long input into worker agents that process segments serially and pass intermediate messages, then has a manager agent summarize the final answer; suitable for long-document QA and summarization tasks.
- [Graph of Agents](https://arxiv.org/abs/2509.06644) ([code](https://github.com/tjoo512/graph-of-agents)): A graph-style multi-agent collaboration harness for long context; the core idea is to organize text chunks, local agent outputs, and aggregation nodes into a scalable graph structure, replacing a single long prompt with local processing and cross-node aggregation.

## 1.10.4 Skill

- [long-context](https://github.com/davila7/claude-code-templates/tree/main/cli-tool/components/skills/ai-research/emerging-techniques-long-context) directly targets long-context compression, summarization, and retrieval organization.
- [long-context](https://skills.sh/davila7/claude-code-templates/long-context) is suitable for summarization, compression, and retrieval organization under long context.
- [context-compression](https://skills.sh/sickn33/antigravity-awesome-skills/context-compression) is suitable for context pruning under high token pressure.
- [token-saver-context-compression](https://skills.sh/oimiragieo/agent-studio/token-saver-context-compression) is suitable for context compression with budget constraints as the goal.
- [ai-rag-pipeline](https://skills.sh/inferen-sh/skills/ai-rag-pipeline) is suitable for converting long-document tasks into retrieval-augmented workflows.
- [langchain-rag](https://skills.sh/langchain-ai/langchain-skills/langchain-rag) is suitable for converting long-document tasks into maintainable retrieval-augmented pipelines.
- [agent-context-loader](https://skills.sh/jeremylongshore/claude-code-plugins-plus-skills/agent-context-loader) is suitable for loading repository or document context in batches.
- [gemini](https://skills.sh/zpankz/mcp-skillset/gemini) belongs to the "long-window delegation/external execution" class of skills: it delegates long-context tasks to a large-window model, leaning toward a harness-level external execution strategy.
