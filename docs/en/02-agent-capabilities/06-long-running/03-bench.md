# 2.6.3 Bench

- [AssistantBench](https://arxiv.org/abs/2407.15711) ([project page](https://assistantbench.github.io/)): Evaluates realistic, time-consuming open-web assistant tasks. Core idea: make agents work on tasks such as property monitoring and merchant search that require sustained browsing and multi-step filtering, then use automatic evaluation to check final results, exposing early instability of web agents on long real-world tasks.
- [Vending-Bench](https://arxiv.org/abs/2502.15840): Evaluates consistency and stability of long-running autonomous agents over very long horizons, using "automated vending-machine operation" as a simplified business scenario, with a single run reaching over 20M tokens. Core idea: stretch decision chains where each step is simple but long-range coupled, explicitly exposing long-horizon failure modes such as high variance, meltdown loops, and difficulty recovering from bad states.
- [METR Time Horizon](https://arxiv.org/abs/2503.14499) ([open analysis code](https://github.com/METR/eval-analysis-public)): Evaluates how long a human-duration task AI agents can reliably complete. Core idea: calibrate task difficulty by qualified human completion time, then estimate p50/p80 time horizons from success-rate curves, forming a long-term autonomy scale that can update with models and agent systems.
- [RealWebAssist](https://arxiv.org/abs/2504.10445) ([open-source code](https://github.com/SCAI-JHU/RealWebAssist)): Evaluates long-horizon web assistance for real users. Core idea: split user needs that may be supplemented, corrected, or ambiguously expressed into sequential instructions, testing whether agents can maintain goals, identify clarification needs, and keep making progress during long interactions.
- [OSWorld-Human](https://arxiv.org/abs/2506.16042) ([OSWorld-Human Efficiency Leaderboard](https://github.com/WukLab/osworld-human); [open-source code](https://github.com/WukLab/osworld-human)): Evaluates computer-use agent efficiency against human reference trajectories. Core idea: add human traces and metrics such as weighted excess steps beyond OSWorld success rate, identifying long-horizon GUI agents that can complete tasks but execute them very inefficiently.
- [OdysseyBench](https://arxiv.org/abs/2508.09124) ([open-source code](https://github.com/microsoft/OdysseyBench)): Evaluates memory and context reuse in long-horizon office productivity workflows. Core idea: build cross-stage state dependencies around documents, email, calendars, and spreadsheets, specifically checking whether agents can correctly refer to early results after multi-step execution.
- [Gaia2](https://arxiv.org/abs/2509.17158) ([open-source code](https://github.com/facebookresearch/meta-agents-research-environments)): Evaluates realistic agent environments that are dynamic, asynchronous, and time-varying. Core idea: move tasks beyond one-shot QA into changing environmental states, notifications, and external-system interactions, requiring agents to maintain goals, update plans, and adapt to new information in long-horizon context.
- [UltraHorizon](https://arxiv.org/abs/2509.21766) ([code](https://github.com/StarDewXXX/UltraHorizon)): Evaluates ultra-long-horizon agents in partially observable simulated environments. Core idea: stretch goal decomposition, exploration, and state tracking over very long action sequences so task success depends on persistent planning rather than local tool-use competence alone.
- [HAL / Holistic Agent Leaderboard](https://arxiv.org/abs/2510.11977) ([HAL Long-Horizon Tracks](https://hal.cs.princeton.edu/); [open-source code](https://github.com/princeton-pli/hal-harness)): Evaluates unified long-horizon agent comparison across AssistantBench, GAIA, Online Mind2Web, and other tasks. Core idea: put accuracy, cost, runtime, and traces into the same leaderboard/harness to compare the generality of different long-horizon agent scaffolds.
- [DeepPlanning](https://arxiv.org/abs/2601.18137) ([project page](https://qwenlm.github.io/Qwen-Agent/en/benchmarks/deepplanning/)): Evaluates long-horizon agentic planning and multi-step execution. Core idea: use tasks requiring deep decomposition, constraint tracking, and staged backfilling to test whether agents can reliably map high-level goals into long action sequences.
- [OS-Marathon](https://arxiv.org/abs/2601.20650) ([project page](https://os-marathon.github.io/)): Evaluates computer-use agent stability in long-running, repetitive GUI tasks. Core idea: lengthen desktop tasks that are not hard step by step but are long in duration and accumulate state, observing pace maintenance, memory contamination, early stopping, and error-recovery failures.
- [AgentLongBench](https://arxiv.org/abs/2601.20730): Evaluates dynamic-environment episodes for long-context agents. Core idea: turn static retrieval questions into environment rollouts, specifically testing decay in multi-round feedback, nonlinear reasoning, and information integration over long chains.
- [TRIP-Bench](https://arxiv.org/abs/2602.01675): Evaluates long-horizon multi-turn agents in realistic travel planning. Core idea: use 18 tools, 40+ travel constraints, up to 15 rounds of user interaction, and 150+ tool calls to test global constraint maintenance, adaptation to changing requirements, and version revision under long context.
- [EcoGym](https://arxiv.org/abs/2602.09514) ([open-source code](https://github.com/OPPO-PersonalAI/EcoGym)): Evaluates long-horizon `plan-and-execute` ability in interactive economic systems. Core idea: provide `Vending / Freelance / Operation` environments under a unified interface, using 1000+ step action budgets to assess long-term strategy consistency, robustness, and returns.
- [LongCLI-Bench](https://arxiv.org/abs/2602.14337) ([open-source code](https://github.com/finyorko/longcli-bench)): Evaluates long-horizon agentic programming in command-line environments. Core idea: use CLI workflows with longer task spans, fine-grained intermediate metrics, and lower contamination risk to evaluate whether coding agents can keep planning, executing, debugging, and recovering.
- [MMR-Life](https://arxiv.org/abs/2603.06746) ([open-source code](https://github.com/BugMakerzzz/MMR-Life)): Evaluates multimodal, multi-perspective reasoning for long-context daily-life agents. Core idea: use real-world long-duration, multi-view, multimodal records to test whether agents can preserve, retrieve, and combine life-scenario evidence across time.
- [RetailBench](https://arxiv.org/abs/2603.16453): Evaluates long-horizon autonomous decision-making and strategy stability in realistic retail environments. Core idea: test whether agents can separately maintain high-level strategy and low-level execution under stochastic demand and evolving external conditions, preserving long-term operational consistency as complexity rises.
- [HORIZON](https://arxiv.org/abs/2604.11978) ([leaderboard](https://xwang2775.github.io/horizon-leaderboard/)): Diagnoses long-horizon agent failure across domains. Core idea: construct cross-domain tasks and use trajectory-grounded failure attribution so degradation can be localized by planning, memory, tool use, or recovery behavior rather than reported only as final failure.
- [ClawMark](https://arxiv.org/abs/2604.23781) ([project page](https://claw-mark.com/); [open-source code](https://github.com/evolvent-ai/ClawMark)): Evaluates multimodal coworker-style agents over multi-day calendar time. Core idea: use realistic schedules, messages, files, and external-event constraints over 1 to 3 days to assess whether agents can wait, remind, resume across days, and handle delayed feedback.
- [Odysseys](https://arxiv.org/abs/2604.24964) ([project page](https://odysseys-website.pages.dev/)): Evaluates long-horizon agent tasks on real websites. Core idea: put real websites, multi-stage goals, state dependencies, and error recovery into the same execution trajectory, testing whether web agents can maintain task consistency over longer spans.
- [π-Bench](https://arxiv.org/abs/2605.14678): Evaluates long-term preferences, implicit intent, and cross-session action for proactive personal-assistant agents. Core idea: make agents decide when to act proactively, when to wait for confirmation, and how to maintain user preferences and task boundaries across multi-turn personal-affairs scenarios that continuously evolve.
- [Vending-Bench 2](https://andonlabs.com/evals/vending-bench-2): Evaluates long-horizon business-operation agents in a newer public version of Andon Labs' vending-machine evaluation. Core idea: keep the one-year simulated business setting from Vending-Bench while adding more realistic messiness such as adversarial suppliers, negotiation, delivery delays, supplier failures, refunds, and clearer money-balance scoring.
