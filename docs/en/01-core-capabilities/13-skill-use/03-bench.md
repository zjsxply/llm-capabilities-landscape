# 1.13.3 Bench

- [LifelongAgentBench](https://arxiv.org/abs/2505.11942): What it evaluates: whether LLM agents can learn, remember, and reuse skills across long task sequences.
  Core idea: chain tasks as episodes so that agents use past experience, tool-operation patterns, and transferable skills on new tasks instead of only planning within a single task.
- [SkillVerse : Assessing and Enhancing LLMs with Tree Evaluation](https://arxiv.org/abs/2506.00319): Assesses language models with tree-structured skill evaluation; core idea: diagnose capability gaps at a granular skill level rather than reporting only aggregate benchmark scores.
- [StuLife / Experience-Driven Lifelong Learning](https://arxiv.org/abs/2508.19005): What it evaluates: whether self-evolving agents learn, remember, and transfer reusable skills in a dynamic long-horizon environment. Core idea: combine exploration, long-term memory, skill abstraction, and later validation in one sequential protocol.
- [EvoTest: Evolutionary Test-Time Learning for Self-Improving Agentic Systems](https://arxiv.org/abs/2510.13220): Test-time learning benchmark: Jericho-style benchmark for learning skills on the fly. Core idea: measure whether agents acquire useful capabilities during deployment.
- [In-Context Skill Composition](https://arxiv.org/abs/2510.22993): What it evaluates: whether language models can compose demonstrated basic skills in context. Core idea: test recognition and assembly of reusable primitive skills without additional training.
- [Agent-Skill Prompt Injection](https://arxiv.org/abs/2510.26328): What it evaluates: prompt injection through persistent agent-skill artifacts. Core idea: treat skills as executable context that can carry attacker instructions into later agent runs.
- [Single-Agent with Skills](https://arxiv.org/abs/2601.04748): What it evaluates: when skill-augmented single agents can replace multi-agent systems and when they fail.
  Core idea: use a comparative task protocol to separate gains from reusable skills from gains that require multi-agent decomposition.
- [Agent Skills in the Wild](https://arxiv.org/abs/2601.10338): What it evaluates: large-scale security vulnerabilities in public agent skills. Core idea: scan marketplace skills with a vulnerability taxonomy covering prompt injection, data exfiltration, privilege escalation, and supply-chain risks.
- [Malicious Agent Skills in the Wild](https://arxiv.org/abs/2602.06547): What it evaluates: behaviorally verified malicious third-party skills. Core idea: build a labeled malicious-skill dataset from community registries and characterize attack archetypes, kill-chain phases, and removal outcomes.
- [When Skills Lie: Hidden-Comment Injection in LLM Agents](https://arxiv.org/abs/2602.10498): Studies hidden-comment injection in LLM-agent skills, treating persistent skill files as an attack surface for later runs.
- [SkillsBench](https://arxiv.org/abs/2602.12670) ([code](https://github.com/benchflow-ai/skillsbench); [website](https://www.skillsbench.ai/); [official leaderboard](https://www.skillsbench.ai/leaderboard)): What it evaluates: whether agents achieve stable task-success gains when using human-written or self-generated skills.
  Core idea: make skill value measurable through a three-way comparison of `no skill / curated skill / self-generated skill`; the paper version covers 86 tasks across 11 domains, while the current website shows 84 tasks.
- [SkillJect](https://arxiv.org/abs/2602.14211): What it evaluates: stealthy prompt injection through skill files in coding agents. Core idea: use trace-driven closed-loop refinement to adapt malicious skills against real coding-agent trajectories, extending skill-safety evaluation from static malicious instructions to iterative attack optimization.
- [SkillInject](https://arxiv.org/abs/2602.20156): What it evaluates: whether agents are vulnerable to prompt injection embedded in skill files. Core idea: treat reusable skills as an explicit attack surface and measure whether malicious instructions redirect agent behavior during execution.
- [SkillCraft](https://arxiv.org/abs/2603.00718) ([code](https://github.com/shiqichen17/SkillCraft); [project page](https://skillcraft-website.github.io/page/)): What it evaluates: whether agents can abstract atomic tools into reusable skills and cache and reuse them across long-horizon tasks.
  Core idea: stress-test skill abstraction through `quantitative scaling` and `structural scaling`; it considers not only instance-level success but also efficiency gains from skill reuse.
- [Clawdrain: Exploiting Tool-Calling Chains for Stealthy Token Exhaustion in OpenClaw Agents](https://arxiv.org/abs/2603.00902): Defines a token-exhaustion attack over tool-calling chains in OpenClaw-style agents, adding a skill and tool safety stress test.
- [Tool-Genesis](https://arxiv.org/abs/2603.05578): What it evaluates: task-driven tool creation by self-evolving agents. Core idea: test whether agents can infer interfaces, implement executable logic, and use newly created tools from abstract task requirements.
- [SWE-Skills-Bench](https://arxiv.org/abs/2603.15401) ([code](https://github.com/GeniusHTX/SWE-Skills-Bench); [dataset](https://huggingface.co/datasets/GeniusHTX/SWE-Skills-Bench)): What it evaluates: whether agent skills truly help on real software engineering tasks.
  Core idea: shift the evaluation target from "can a coding agent fix code" to "does a given skill improve the success rate, efficiency, and behavior quality of software engineering agents".
- [Repository-Context Skill Classification](https://arxiv.org/abs/2603.16572): What it evaluates: malicious-versus-benign skill classification with repository context. Core idea: judge skills using code and surrounding repository evidence rather than marketplace metadata alone.
- [SkillProbe](https://arxiv.org/abs/2603.21019): What it evaluates: security risks in emerging agent-skill marketplaces. Core idea: use multi-agent auditing to detect semantic-behavior inconsistency and cross-skill compositional risks.
- ["Elementary, My Dear Watson."Detecting Malicious Skills via Neuro-Symbolic Reasoning across Heterogeneous Artifacts](https://arxiv.org/abs/2603.27204): Uses neuro-symbolic reasoning across heterogeneous artifacts to detect malicious agent skills, extending skill-safety evaluation beyond text-only manifests.
- [SkillTester](https://arxiv.org/abs/2603.28815) ([project page](https://skilltester.ai/); [code](https://github.com/skilltester-ai/skilltester)): What it evaluates: utility and security of agent skills.
  Core idea: compare baseline and with-skill executions while also probing skills for security issues, making skill usefulness and skill risk visible in one benchmark.
- [Credential Leakage in Agent Skills](https://arxiv.org/abs/2604.03070): What it evaluates: credential exposure in LLM-agent skill artifacts. Core idea: audit skills for secrets, unsafe credential handling, and leakage patterns that ordinary task-success metrics miss.
- [Agentic Skills in the Wild](https://arxiv.org/abs/2604.04323): What it evaluates: whether skills still help when agents search for, select, and use skills that do not perfectly match the task in a real skill ecosystem.
  Core idea: relax the "ideal skill is directly provided" setting into retrieval, noise, and adaptation pressure, then measure how skill utility degrades under realistic settings.
- [SkillTrojan](https://arxiv.org/abs/2604.06811): What it evaluates: backdoor attacks on skill-based agent systems. Core idea: treat persistent skills as reusable attack surfaces whose hidden behavior can survive across later invocations.
- [STARS / SIA-Bench](https://arxiv.org/abs/2604.10286): What it evaluates: request-conditioned skill invocation safety. Core idea: score user request, candidate skill, and runtime context together before invocation using dedicated invocation records.
- [HarmfulSkillBench](https://arxiv.org/abs/2604.15415): What it evaluates: harmful skills that can weaponize agents across risk domains. Core idea: measure harmful skill prevalence and agent misuse paths in open skill ecosystems, rather than only scanning for ordinary vulnerabilities.
- [SkillFlow Lifelong Benchmark](https://arxiv.org/abs/2604.17308): What it evaluates: lifelong skill discovery, repair, and evolution by autonomous agents. Core idea: run sequential task families where agents start without skills, patch skills from trajectories, and carry the updated library forward.
- [SkillLearnBench](https://arxiv.org/abs/2604.20087) ([code](https://github.com/cxcscmu/SkillLearnBench)): What it evaluates: continual skill learning and generation; core idea: evaluate skill quality, execution trajectories, and task outcomes together to see whether reusable skills are learned reliably.
- [MedSkillAudit](https://arxiv.org/abs/2604.20441): What it evaluates: safety and reliability of medical research-agent skills. Core idea: audit whether domain skills remain relevant, safe, and reliable where misuse has high cost.
- [Claw-Eval-Live](https://arxiv.org/abs/2604.28139) ([project page](https://claw-eval-live.github.io/); [code](https://github.com/Claw-Eval-Live/Claw-Eval-Live)): What it evaluates: continuously updated real workflow-agent tasks that explicitly use ClawHub skill signals. Core idea: place skill discovery, installation, invocation, and verification inside a periodically refreshed task distribution, complementing the static comparisons in SkillsBench.
- [SkillRet](https://arxiv.org/abs/2605.05726): What it evaluates: large-scale retrieval over agent skill libraries; core idea: treat skill selection as a retrieval problem and evaluate long queries, noisy libraries, and NDCG / recall.
- [FORTIS](https://arxiv.org/abs/2605.09163): What it evaluates: whether agent skills cross least-privilege boundaries.
  Core idea: split evaluation into "whether the minimally sufficient skill is selected" and "whether execution expands to tools or actions outside that skill", elevating the skill layer from an organizational abstraction to a measurable permission boundary.
- [Dependency Steering](https://arxiv.org/abs/2605.09594): What it evaluates: whether malicious skills can steer coding agents toward attacker-chosen dependencies.
  Core idea: treat persistent skill files as a software-supply-chain attack surface and measure how skill content changes dependency selection during coding workflows.
- [Skill Description Deception Attack](https://arxiv.org/abs/2605.09889): Evaluates whether task routing in Internet-of-Agents settings can be manipulated through deceptive self-declared skill descriptions. Core idea: formalize SDD attacks and generate deceptive descriptions to measure routing bias and reliability degradation.
- [SkillSafetyBench](https://arxiv.org/abs/2605.12015) ([project page](https://jinchang1223.github.io/skill-safety-bench-website/); [code](https://github.com/AI45Lab/skill-safety-bench)): What it evaluates: whether agents facing a skill-facing attack surface can be induced by third-party skills, local materials, or local artifacts into unsafe actions.
  Core idea: combine ordinary tasks, risk domains, malicious or benign skill materials, and rule validators in a runnable environment, showing that skill safety cannot rely only on model-level alignment evaluations.
- [Code-Backed Skill Description Audit](https://arxiv.org/abs/2605.12875): What it evaluates: undisclosed security behavior in code-backed skills. Core idea: compare source-level security-property evidence against the declared skill description to find hidden behavior.
- [AgentTrap](https://arxiv.org/abs/2605.13940) ([code](https://github.com/zhmzm/AgentTrap); [dataset](https://huggingface.co/datasets/zhmzm/AgentTrap)): What it evaluates: whether agents blindly execute malicious runtime behavior embedded in third-party skills.
  Core idea: combine ordinary user tasks, malicious or benign skill packages, and sandboxed execution environments, then judge attack success, blocking, non-triggering, and no-evidence outcomes from full trajectories.
- [Payload-less Skills](https://arxiv.org/abs/2605.14460): What it evaluates: payload-less supply-chain attacks through agent skills. Core idea: show that benign-looking compliance instructions can steer coding agents at runtime without explicit malicious code payloads.
- [SkillGenBench](https://arxiv.org/abs/2605.18693): What it evaluates: the skill generation pipeline of LLM agents; core idea: go beyond final task success by evaluating skill distillation, executability, generalization, and later reuse.
- [Skill Availability and Presentation Granularity](https://arxiv.org/abs/2605.31408): Uses a controlled SkillsBench study to isolate how skill documentation availability and granularity affect agent success. Core idea: run a pinned 30-task domain-balanced subset under six skill conditions and multiple trials, separating the value of having skills from the way those skills are presented.
- [MMG2Skill-Bench](https://arxiv.org/abs/2606.01993): What it evaluates: guide-to-skill learning from in-the-wild multimodal guides. Core idea: test whether agents can convert noisy human-oriented guides into executable skills, use them across GUI control, open-ended gameplay, and strategic card-play tasks, and improve those skills from observable trajectories rather than benchmark scores.
- [R3-Skill / Skill Is Not Document](https://arxiv.org/abs/2606.03565): Benchmarks query-conditioned agent skill routing with a bilingual R3-Skill benchmark. Core idea: evaluate compatibility between a user query and candidate skill rather than treating skills as ordinary documents, and pair the benchmark with a two-stage retriever for routing.
- [SkillResolve-Bench](https://arxiv.org/abs/2606.10388): Measures same-capability ambiguity in agent skill retrieval. Core idea: release 661 helpful/risky skill pairs, a 7,982-candidate pool, and HSR@K-style metrics so retrieval systems are tested on confusing near-matches, not just obvious relevant skills.
- [Letta Context-Bench Skills Suite](https://leaderboard.letta.com/): What it evaluates: skill-suite behavior inside an agentic context-management leaderboard. Core idea: compare whether agents can select and apply context packages or skills during tasks, complementing direct skill-use benchmarks such as SkillsBench.
- [MM Claw skill-compliance suite](https://www.minimax.io/news/minimax-m27-en) (model-card-only; no standalone public release confirmed): What it evaluates: whether an agent can keep following and reusing more than 40 complex skills during extended OpenClaw-style work. Core idea: treat skill adherence itself as an evaluation signal, complementing public skill-search and skill-injection benchmarks.
- [PinchBench](https://pinchbench.com/about) ([code](https://github.com/pinchbench/skill)): Better treated as a practical supplementary benchmark for skill use rather than a purely academic "skills benchmark".
  It primarily evaluates the overall execution of OpenClaw agents on real tasks, but its task set explicitly includes `ClawHub skill installation` and `skill search/installation` scenarios, filling in skill integration and invocation capability in product ecosystems.
