# 2.1.3 Bench

- [HumanEval](https://arxiv.org/abs/2107.03374): What it evaluates: executable unit-test correctness for Python function-level code generation. Core idea: use docstring prompts and hidden tests to measure functional correctness, forming a baseline reference for later code-generation evaluation and pass@k reporting. ([code](https://github.com/openai/human-eval))
- [LiveCodeBench v6](https://arxiv.org/abs/2403.07974): What it evaluates: continuously updated, contamination-aware code evaluation, including problems from contest platforms. Core idea: provide a more credible comparison baseline for "coding ability" through dynamic sampling and contamination control. ([leaderboard](https://livecodebench.github.io/leaderboard.html), [code](https://github.com/LiveCodeBench/LiveCodeBench))
- [USACO](https://arxiv.org/abs/2404.10952): What it evaluates: competitive-programming reasoning and implementation on USA Computing Olympiad problems. Core idea: organize problems, samples, hidden tests, and tiered difficulty into executable evaluation to observe long-horizon bottlenecks in Olympiad-style programming. ([code](https://github.com/princeton-nlp/USACO))
- [A Performance Study of LLM-Generated Code on Leetcode](https://arxiv.org/abs/2407.21579): Studies LLM-generated code performance on LeetCode-style programming tasks.
- [CodeElo](https://arxiv.org/abs/2501.01257): What it evaluates: Elo-style comparable scoring for contest-level code generation. Core idea: use an evaluation protocol closer to "matches/ranking" so model performance yields more stable relative-ordering signals. ([leaderboard](https://codeelo-bench.github.io/))
- [ProBench](https://arxiv.org/abs/2502.20868): What it evaluates: ICPC-inspired competitive-programming evaluation with problems from Codeforces, Luogu, and Nowcoder in the second half of 2024. Core idea: use real online-judge submissions, difficulty tiers, and algorithm tags to analyze chain-of-thought, error types, and reasoning depth.
- [Codehacks: A Dataset of Adversarial Tests for Competitive Programming Problems Obtained from Codeforces](https://arxiv.org/abs/2503.23466): Builds adversarial tests for competitive-programming problems from Codeforces.
- [LeetCodeDataset: A Temporal Dataset for Robust Evaluation and Efficient Training of Code LLMs](https://arxiv.org/abs/2504.14655): A temporal coding dataset for robust evaluation and training. Core idea: use time-aware LeetCode data to reduce leakage risk and support more realistic code-generation evaluation.
- [CPRet](https://arxiv.org/abs/2505.12925): Evaluates retrieval of similar and duplicate competitive-programming problems. Core idea: provide text-code, code-code, problem-duplicate, and simplified-to-full retrieval tasks, then use similarity analysis to diagnose inflated pass rates in coding benchmarks.
- [ELABORATION](https://arxiv.org/abs/2505.16667): Evaluates human-LLM collaboration in competitive programming. Core idea: provide a feedback taxonomy and annotated programming tasks so simulated or real human feedback can be tested across the contest-solving process.
- [ICPC-Eval](https://arxiv.org/abs/2506.04894) ([code](https://github.com/RUCAIBox/Slow_Thinking_with_LLMs)): What it evaluates: reasoning and local repair capability on ICPC-style contest problems. Core idea: use a problem set closer to real ICPC scenarios and Refine@K evaluation to include multi-round correction in the metrics.
- [TCGBench](https://arxiv.org/abs/2506.06821): Evaluates whether LLMs can generate valid and targeted test-case generators for competition-level programming problems, including generators that expose bugs in human code.
- [ALE-Bench](https://arxiv.org/abs/2506.09050): What it evaluates: long-horizon, score-based algorithm-engineering tasks from AtCoder Heuristic Contest. Core idea: move from "AC/WA" to continuous scoring and iterative optimization, evaluating long-term trial-and-error ability on routing, scheduling, and other problems without exact optima. ([leaderboard](https://sakanaai.github.io/ALE-Bench-Leaderboard/), [code](https://github.com/SakanaAI/ALE-Bench), [dataset](https://huggingface.co/datasets/SakanaAI/ALE-Bench))
- [OIBench](https://arxiv.org/abs/2506.10481): A challenging Olympiad-in-Informatics benchmark with original problems, contamination analysis, and time/space completion curves for comparing reasoning models against human participants.
- [Advancing Large Language Models in Code Generation: Usaco Benchmark and Bug Mitigation Insights](https://doi.org/10.1109/icpc66645.2025.00057): Uses USACO-style programming tasks and bug-mitigation analysis to benchmark code generation.
- [CodeContests](https://github.com/google-deepmind/code_contests): What it evaluates: a competitive-programming dataset and execution-evaluation substrate, including statements, tests, and correct/incorrect solutions. Core idea: convert contest problems into a runnable judging format for training and evaluating harder algorithmic code generation.
- [LiveCodeBench Pro](https://arxiv.org/abs/2506.11928): What it evaluates: harder contamination-controlled code-generation evaluation centered on competitive algorithm problems. Core idea: increase problem difficulty and judging strength on top of LiveCodeBench's dynamic problem-source design to distinguish the upper bounds of frontier coding agents. ([leaderboard](https://livecodebenchpro.com/), [code](https://github.com/GavinZhengOI/LiveCodeBench-Pro))
- [Humanity's Last Code Exam (HLCE)](https://arxiv.org/abs/2506.12713): What it evaluates: executable evaluation on an extremely hard set of ICPC World Finals and IOI problems. Core idea: widen upper-bound gaps through harder problem sources and strict execution evaluation. ([leaderboard](https://humanity-s-last-code-exam.github.io/website/), [code](https://github.com/Humanity-s-Last-Code-Exam/HLCE))
- [Structured Program Synthesis using LLMs: Results and Insights from the IPARC Challenge](https://arxiv.org/abs/2506.13820): What it evaluates: a controlled program-synthesis challenge inspired by ARC-style abstraction tasks.
- [OJBench](https://arxiv.org/abs/2506.16395) ([code](https://github.com/He-Ren/OJBench)): What it evaluates: code reasoning and execution correctness on NOI/ICPC-style contest problems. Core idea: turn contest-level hard problems into a stable benchmark with 232 bilingual Chinese-English problems.
- [AlgoSimBench](https://arxiv.org/abs/2507.15378): Evaluates whether models identify algorithmically similar competitive-programming problems. Core idea: use fine-grained algorithm tags and distractors that are textually similar but algorithmically different to separate surface matching from reusable algorithmic reasoning.
- [COMPASS](https://arxiv.org/abs/2508.13757): What it evaluates: correctness, efficiency, and code quality for contest-problem code generation. Core idea: evaluate time efficiency and implementation quality alongside AC in one protocol.
- [AetherCode](https://arxiv.org/abs/2508.16402): What it evaluates: ability to win top programming competitions, closer to IOI/ICPC-level hard problems and judging. Core idea: treat whether the test set can distinguish correct from incorrect solutions as a core evaluation object, avoiding false positives from weak tests.
- [ICPC Benchmark / Zolve](https://arxiv.org/abs/2509.00629) ([code and data](https://github.com/kraritt/zolve)): Evaluates hard competitive-programming problems from ICPC contests. Core idea: pair official analyses, reference solutions, and hidden tests with multi-turn self-judging, reflection, and episodic retrieval, exposing where frontier models still need targeted guidance.
- [LiveOIBench](https://arxiv.org/abs/2510.09595): What it evaluates: long reasoning, algorithm design, and code execution on Olympiad-in-Informatics-style tasks. Core idea: complement ICPC/Codeforces-only distributions with OI hard-problem distributions, adding stronger pressure from construction, data structures, and algorithmic reasoning. ([leaderboard](https://liveoibench.github.io/leaderboard.html))
- [Holistic Agent Leaderboard (HAL)](https://arxiv.org/abs/2510.11977) ([leaderboard](https://hal.cs.princeton.edu/), [code](https://github.com/princeton-pli/hal-harness)): What it evaluates: unified cross-benchmark agent evaluation, including competitive-programming subtasks such as USACO. Core idea: use a unified CLI, cost/time records, and leaderboard submission process so competitive-programming results can be compared with SWE, web, and real-world tasks.
- [UniCode](https://arxiv.org/abs/2510.17868): What it evaluates: code reasoning under generative benchmark augmentation. Core idea: transform seed programming problems across multiple dimensions, generate reliable tests, and track shortcut failures such as reverting to memorized seed logic instead of following the modified specification.
- [FrontierCS: Evolving Challenges for Evolving Intelligence](https://arxiv.org/abs/2512.15699): benchmarks open-ended computer-science problems with executable submissions and objective evaluators, spanning algorithmic and research tracks. ([challenge site](https://frontier-cs.org/))
- [Idea First, Code Later](https://arxiv.org/abs/2601.11332): What it evaluates: the separability of "algorithm idea" and "code implementation" in ICPC-style problems. Core idea: introduce 83 problems with gold editorials and complete tests, evaluating natural-language editorials first and code implementation later so AC does not hide the bottleneck.
- [DePro: Understanding the Role of LLMs in Debugging Competitive Programming Code](https://arxiv.org/abs/2603.19399): Adds a benchmark or evaluation artifact for competitive programming: study of LLM debugging for competitive-programming code.
- [VeriContest](https://arxiv.org/abs/2605.08553): What it evaluates: verifiable code generation on LeetCode and Codeforces problems. Core idea: combine natural-language statements, expert-verified formal specifications, AC Rust code, Verus proofs, and positive/negative tests to evaluate specification, code, proof, and end-to-end verified synthesis separately.
