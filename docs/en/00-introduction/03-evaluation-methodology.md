# 0.3 Evaluation Methodology

> Parent chapter: 0. Introduction

As models and agents iterate faster, the main risks of static benchmarks are no longer just that questions are too easy. They also include question leakage, training contamination, leaderboard overfitting, judge drift, opaque evaluation protocols, unreproducible dynamic environments, and the illusion of "high score but not deployable." Reliable evaluation needs to examine four things at once: whether tasks are still fresh, whether metrics are interpretable, whether the evaluation process is reproducible, and whether the leaderboard can distinguish model capability, harness design, and changes in environment state.

## 0.3.1 Agent Eval Platforms

- [HELM](https://crfm.stanford.edu/helm/latest/) ([paper](https://arxiv.org/abs/2211.09110); [open-source code](https://github.com/stanford-crfm/helm)): A holistic model-evaluation platform; useful as an early reference for transparent scenarios, metrics, raw prompts/completions, and multi-metric reporting.
- [lm-evaluation-harness](https://arxiv.org/abs/2405.14782) ([open-source code](https://github.com/EleutherAI/lm-evaluation-harness)): EleutherAI's widely used task harness; useful for reproducible task implementations, model adapters, and documenting evaluation-setup sensitivity.
- [The AI Agent Index](https://arxiv.org/abs/2502.01635): Documents deployed agentic systems by base model, reasoning implementation, tool use, domain, evaluation reporting, and guardrail disclosure, making public transparency itself an evaluation object.
- [Harbor](https://www.harborframework.com/) ([open-source code](https://github.com/harbor-framework/harbor); related benchmark: [Terminal-Bench](https://arxiv.org/abs/2601.11868)): A framework for running agent evaluations and creating sandboxed environments; useful for Terminal-Bench-style tasks, trajectories, and RL environment packaging.
- [BenchFlow](https://www.benchflow.ai/) ([open-source code](https://github.com/benchflow-ai/benchflow); related benchmark: [SkillsBench](https://arxiv.org/abs/2602.12670)): An agent-evaluation runtime for packaging tasks and high-fidelity environments; useful for reproducible skill and RL-style evaluation workflows.
- [PROTEA](https://arxiv.org/abs/2605.18032): Provides offline test-driven refinement for multi-agent LLM workflows. Core idea: execute a workflow graph, score intermediate nodes, and localize errors so workflow debugging is not reduced to final-answer judging.
- [TwinRouterBench](https://arxiv.org/abs/2605.18859): Evaluates step-level model routing for agentic LLM systems. Core idea: combine static and live dynamic routing tests from intermediate agent prefixes, downgrade-and-cascade protocols, and deterministic scoring.
- [DecisionBench](https://arxiv.org/abs/2605.19099): Benchmarks emergent delegation in long-horizon agent workflows. Core idea: add a peer-model pool and call-model interface over GAIA, tau-bench, and BFCL-style tasks to measure when agents delegate, route, and recover effectively.
- [OpenCompass](https://opencompass.org.cn/) ([paper](https://arxiv.org/abs/2605.19276); [open-source code](https://github.com/open-compass/opencompass)): A universal LLM evaluation platform with distributed execution, benchmark hubs, multiple evaluator types, and result visualization.
- [OpenJudge](https://openjudge.me/) ([open-source code](https://github.com/agentscope-ai/OpenJudge)): An open-source evaluation framework for AI applications with ready-made graders for relevance, hallucination, tool selection, memory, planning, trajectory quality, code, math, and multimodal outputs; useful when an agent benchmark needs reusable graders, rubric generation, and reward signals rather than only a fixed task set.
- [PawBench](https://agentscope-ai.github.io/PawBench/) ([open-source code](https://github.com/agentscope-ai/PawBench); ecosystem: [OpenJudge](https://github.com/agentscope-ai/OpenJudge)): A model-harness co-evaluation benchmark for agentic AI. PawBench v1.0 runs 150 tasks across 9 models and 3 harnesses, keeps public prompts, graders, task labels, submissions, slice views, transcripts, and workspace artifacts, and shows that harness choice can change the realized capability of the same model.
- [OpenAI Evals](https://github.com/openai/evals) and [simple-evals](https://github.com/openai/simple-evals): Open evaluation registries and lightweight suites for repeatable LLM-system checks; useful for custom task definitions, public eval recipes, and regression testing.
- [Inspect AI](https://inspect.aisi.org.uk/) ([open-source code](https://github.com/UKGovernmentBEIS/inspect_ai)): AISI's open framework for model and agent evaluations; useful for solvers, tools, scorers, sandboxes, logs, and audit-ready eval sets.
- [OpenEvals](https://github.com/langchain-ai/openevals) and [AgentEvals](https://github.com/langchain-ai/agentevals): LangChain packages for app-level evaluators and agent-trajectory evaluators; useful for reusable judge functions, trajectory matching, and regression checks on agent behavior.
- Engineering-side complements include [DeepEval](https://deepeval.com/) ([open-source code](https://github.com/confident-ai/deepeval)), [promptfoo](https://www.promptfoo.dev/) ([open-source code](https://github.com/promptfoo/promptfoo)), [Giskard](https://docs.giskard.ai/) ([open-source code](https://github.com/Giskard-AI/giskard-oss)), and [LightEval](https://huggingface.co/docs/lighteval/en/index) ([open-source code](https://github.com/huggingface/lighteval)); these are more application-regression and testing tools than benchmark entries, but they matter for closing the loop between benchmark design, CI, and deployed-agent reliability.

## 0.3.2 Dynamic and Reliable Benchmarks

- [LatestEval](https://arxiv.org/abs/2312.12343): builds reading-comprehension evaluations from the latest news and time-sensitive material; its core value is turning "has the model seen the question" into a time-slice issue.
- [DARG](https://arxiv.org/abs/2406.17271): dynamically evaluates LLM reasoning with an adaptive reasoning graph; the core idea is to generate follow-up questions based on a model's answer path, reducing the ability to game fixed prompt templates.
- [LiveBench](https://arxiv.org/abs/2406.19314) ([open-source code](https://github.com/LiveBench/LiveBench); [Leaderboard](https://livebench.ai/)): Maintains a rolling question stream across math, coding, language, reasoning, data analysis, and instruction following, so public benchmark items age out of the main evidence base rather than staying fixed indefinitely.
- [BenchmarkCards](https://arxiv.org/abs/2410.12974) ([open-source code](https://github.com/SokolAnn/BenchmarkCards)): a standardized benchmark documentation framework. When reading a new benchmark, it can be used to check whether task goals, data sources, metrics, limitations, risks, and applicability boundaries are clearly stated.

## 0.3.3 Usage Advice

When reading a new benchmark, first check whether it explains data sources, sampling time, contamination controls, question refresh mechanisms, failed-sample audits, judge calibration, environment snapshots, and leaderboard submission protocols. For agent benchmarks, additionally check whether they preserve full trajectories, tool calls, environment state, cost, runtime, and multi-run variance; otherwise, leaderboard rankings can easily mix in harness engineering, environmental chance, and scoring shortcuts.
