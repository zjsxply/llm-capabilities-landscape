# 2.10 Cybersecurity

> Parent section: 2. Foundation Agents

Note: Cybersecurity is separated from Terminal Use because the task axis is vulnerability discovery, exploit construction, cyber operations, defense, or security policy. Many benchmarks still use a terminal as the execution substrate, but they should not be mixed into the general terminal-task list.

## 2.10.1 Leaderboard

- [ExploitBench](https://exploitbench.ai/): A project and leaderboard entry point for hierarchical cybersecurity-agent tasks; useful for tracking capability levels from reconnaissance to exploit-chain completion.

## 2.10.2 Survey

- [When LLMs meet cybersecurity: a systematic literature review](https://arxiv.org/abs/2405.03644): Maps offensive, defensive, educational, and operational cybersecurity uses and gaps.
- [Large Language Models for Cyber Security: A Systematic Literature Review](https://arxiv.org/abs/2405.04760): Organizes vulnerability detection, penetration testing, malware analysis, response, and automation.
- [Forewarned is Forearmed: A Survey on Large Language Model-based Agents in Autonomous Cyberattacks](https://arxiv.org/abs/2505.12786): Focuses on reconnaissance, exploitation, persistence, tools, and mitigation for offensive agents.
- [A Survey on Agentic Security: Applications, Threats and Defenses](https://arxiv.org/abs/2510.06445): Connects security-agent applications with threats and defensive designs.
- [A Survey of Agentic AI and Cybersecurity: Challenges, Opportunities and Use-case Prototypes](https://arxiv.org/abs/2601.05293): Reviews use cases, prototypes, opportunities, and risk boundaries for autonomous security agents.

## 2.10.3 Bench

- [Cybench](https://arxiv.org/abs/2408.08926): Evaluates cybersecurity capabilities and risks through CTF-style challenges. Core idea: place models in executable security tasks where they must reason, use tools, and complete exploit-oriented objectives rather than only answer cyber knowledge questions.
- [ITBench](https://arxiv.org/abs/2502.05352) ([code](https://github.com/itbench-hub/ITBench)): Evaluates enterprise IT automation workflows such as SRE, CISO, and FinOps. Core idea: put security operations, incident response, and cost/governance work into executable scenarios with interpretable metrics.
- [CASTLE](https://arxiv.org/abs/2503.09433): Benchmarks static analyzers, formal tools, and LLMs on CWE detection. Core idea: use hand-crafted CWE programs and a dedicated score to compare vulnerability detection beyond raw true-positive counts.
- [A Framework for Evaluating Emerging Cyberattack Capabilities of AI](https://arxiv.org/abs/2503.11917): Evaluates AI-enabled cyberattack risk across end-to-end attack-chain archetypes. Core idea: adapt cyber kill-chain analysis to frontier AI evaluations, identify bottleneck phases, and map results to defensive mitigations.
- [CVE-Bench](https://arxiv.org/abs/2503.17332) ([code](https://github.com/uiuc-kang-lab/cve-bench)): Evaluates AI agents' ability to exploit real web-application vulnerabilities. Core idea: connect code understanding, vulnerability localization, terminal operations, and exploit construction into one protocol using high-severity CVEs, isolated environments, and executable validation.
- [Digital Forensic Timeline Analysis Evaluation](https://arxiv.org/abs/2505.03100): Evaluates LLM-based digital forensic timeline analysis. Core idea: define datasets, timeline generation, and ground-truth construction so forensic reasoning can be measured quantitatively instead of through case studies alone.
- [DecompileBench](https://arxiv.org/abs/2505.11340): Benchmarks decompilers in reverse-engineering workflows. Core idea: combine real-world function extraction, runtime-aware validation, and analyst-oriented judging to measure semantic fidelity and usability.
- [BountyBench](https://arxiv.org/abs/2505.15216) ([project page](https://bountybench.github.io/)): Evaluates attacker and defender agents in real cybersecurity systems. Core idea: use bug-bounty scenarios and dollar-impact signals to measure Detect, Exploit, and Patch tasks, supplementing security evaluation that only checks CTF success rates.
- [SecVulEval](https://arxiv.org/abs/2505.19828): Benchmarks LLMs on real-world C/C++ vulnerability detection. Core idea: use realistic vulnerable code rather than only synthetic snippets, testing whether models can localize security flaws in low-level software contexts.
- [DFIR-Metric](https://arxiv.org/abs/2505.19973): evaluates large language models on digital forensics and incident-response tasks. Core idea: turn DFIR knowledge and investigation steps into a benchmark dataset so cybersecurity reasoning can be measured beyond generic security QA.
- [CyberGym](https://arxiv.org/abs/2506.02548) ([project page](https://www.cybergym.io/)): Evaluates vulnerability understanding and exploitation loops for agents in real cybersecurity tasks. Core idea: integrate CVE scenarios, executable environments, tool calls, and final verification so agents must make continuous penetration-testing or repair decisions.
- [SafeGenBench](https://arxiv.org/abs/2506.05692): Evaluates security vulnerability detection in LLM-generated code. Core idea: focus on whether models and tools can identify unsafe generated programs, complementing exploit and patch benchmarks with a generated-code security-detection setting.
- [SEC-bench](https://arxiv.org/abs/2506.11791) ([project page](https://sec-bench.github.io/); [code](https://github.com/SEC-bench/SEC-bench)): Evaluates PoC generation and vulnerability repair in real software-security tasks. Core idea: automatically construct vulnerable repositories with harnesses and isolated reproduction environments, forcing agents to read code, run verification, and generate attacks or patches.
- [AIRTBench](https://arxiv.org/abs/2506.14682) ([code](https://github.com/dreadnode/AIRTBench-Code)): Evaluates attack discovery, code execution, and exploitation-chain loops in autonomous AI red-teaming scenarios. Core idea: place black-box CTF-style AI/ML security challenges into runnable tasks and check whether agents can write scripts, call tools, and verify compromise.
- [Can You Really Trust Code Copilot?](https://doi.org/10.18653/v1/2025.acl-long.849): Evaluates LLM coding assistants from a code-security perspective. Core idea: test whether generated or assisted code introduces security weaknesses rather than measuring only functional correctness.
- [Vulnerability Mitigation System (VMS)](https://arxiv.org/abs/2507.21113): Evaluates autonomous penetration-testing agents on two CTF benchmark sets derived from PicoCTF and OverTheWire. Core idea: pair a planning and summarization agent with 200 standardized challenges so command generation and feedback processing can be compared across LLMs.
- [CTFTiny and CTFJudge](https://arxiv.org/abs/2508.05674): Evaluate offensive-security agents with a lightweight CTF benchmark and judge-based trajectory analysis. Core idea: measure partial progress and step quality rather than only final flag submission.
- [VulnRepairEval](https://arxiv.org/abs/2509.03331): Evaluates LLM vulnerability repair with exploit-based validation. Core idea: require patched code to defeat functional PoC exploits inside a reproducible containerized pipeline rather than relying on superficial tests.
- [TermiBench / Shell or Nothing](https://arxiv.org/abs/2509.09207): Benchmarks automated penetration-testing agents on real-world hosts, services, and CVEs. Core idea: shift evaluation from CTF flag finding to obtaining full system control with memory-activated agents and realistic forensic/tool feedback.
- [CyberSOCEval](https://arxiv.org/abs/2509.20166): Evaluates malware analysis and threat-intelligence reasoning within CyberSecEval 4. Core idea: focus defensive SOC evaluation on operational evidence instead of generic security knowledge.
- [CTIArena](https://arxiv.org/abs/2510.11974): Benchmarks LLM knowledge and reasoning across heterogeneous cyber threat intelligence; core idea: test whether models can integrate indicators, reports, tactics, and evidence rather than answer generic security trivia.
- [CAIBench](https://arxiv.org/abs/2510.24317): A meta-benchmark for cybersecurity AI agents. Core idea: organize multiple cybersecurity-agent evaluation settings into a comparative benchmark layer so agent performance can be read across task families rather than one isolated cyber suite.
- [AutoPenBench](https://aclanthology.org/2025.emnlp-industry.114/): Evaluates vulnerability-testing agents. Core idea: provide 33 tasks from introductory exercises to real vulnerable systems, support MCP-based agent comparison, and score milestones so partial progress is visible before final compromise.
- [PATCHEVAL](https://arxiv.org/abs/2511.11019): Benchmarks LLMs and agents on patching real-world vulnerabilities across Go, JavaScript, and Python. Core idea: pair a broad CVE corpus with sandboxed security and functionality tests for repair verification.
- [AutoDFBench 1.0](https://arxiv.org/abs/2512.16965): Benchmarks digital-forensic tools and AI-generated forensic code across string search, deleted-file recovery, file carving, Windows registry recovery, and SQLite data recovery. Core idea: use CFTT-grounded test cases, REST execution, and precision/recall/F1 metrics to make forensic-tool and agent-code evaluation reproducible.
- [VAP-6](https://doi.org/10.1109/EAIC66483.2025.11101426): A benchmarking framework for vulnerability assessment and penetration testing with language models. Core idea: structure VAPT tasks into a reusable evaluation setting so language-model agents can be compared on security assessment workflows rather than only cyber knowledge questions.
- [CFA-Bench](https://doi.org/10.1109/EuroSPW67616.2025.00031): Benchmarks LLM agents on cybersecurity forensics. Core idea: generate incident-response scenarios with vulnerable services, attacks, packet captures, and log traces, then score forensic reasoning through staged checkpoints.
- [ALPHA](https://arxiv.org/abs/2601.01320): Evaluates LLMs and SAST tools on hierarchy-aware CWE prediction for Python functions. Core idea: penalize over-generalized, over-specific, and lateral CWE errors differently so vulnerability feedback is more actionable than binary detection.
- [Cyb-LLM](https://doi.org/10.1109/ICVADV67766.2026.11470531): Evaluates LLMs in cyber attack and defense tasks under safety constraints. Core idea: combine offensive requests, defensive triage, secure coding, malware, and related cyber workflows in one benchmark.
- [ThreatSage](https://doi.org/10.1109/icassp55912.2026.11463278): Evaluates LLM-orchestrated blue-team defense operations. Core idea: use modular defense tasks to measure detection, analysis, coordination, and response workflows.
- [SastBench](https://arxiv.org/abs/2601.02941): Evaluates agentic SAST triage in software-security workflows. Core idea: test whether agents can interpret static-analysis findings, prioritize vulnerabilities, and produce triage decisions rather than only detect raw alerts.
- [Sola-Visibility-ISPM](https://arxiv.org/abs/2601.07880): Benchmarks agentic AI for identity-security posture visibility. Core idea: test whether agents can inspect and reason about identity-security posture management evidence and gaps.
- [HardSecBench](https://arxiv.org/abs/2601.13864): Benchmarks security awareness in LLM hardware-code generation; core idea: test whether generated HDL or hardware-oriented code avoids security flaws rather than only compiling or matching functionality.
- [RealSec-bench](https://arxiv.org/abs/2601.22706): Evaluates secure code generation in real-world repositories. Core idea: test whether generated code satisfies functional requirements while avoiding security weaknesses in realistic repository contexts.
- [CIPHER](https://arxiv.org/abs/2602.01438): Evaluates cryptographic vulnerability incidence in LLM-generated Python code. Core idea: vary insecure, neutral, and secure prompts while using a cryptography-specific taxonomy and line-level automated scoring to expose silent security failures.
- [Capture the Flags](https://arxiv.org/abs/2602.05523): Evaluates agentic LLMs on CTF families under semantics-preserving transformations. Core idea: test whether cyber agents generalize across transformed challenge variants instead of overfitting instance wording.
- [Vulnerability Reasoning Evaluation](https://arxiv.org/abs/2602.06687): Evaluates vulnerability-reasoning quality using causal ground truth and semantic perturbations. Core idea: check whether a model's explanation matches the real root cause instead of only scoring the detection verdict.
- [Patch-to-PoC](https://arxiv.org/abs/2602.07287): Evaluates agents' ability to reproduce N-day PoCs from Linux kernel patches. Core idea: combine patch analysis, kernel builds, debugging, and exploit verification to check whether agents can convert fixed vulnerabilities back into executable attack evidence.
- [CyberExplorer](https://arxiv.org/abs/2602.08023): Benchmarks LLM offensive-security capabilities in a real-world attacking simulation environment. Core idea: evaluate attack planning and execution inside interactive simulations rather than static cybersecurity QA.
- [Before You Hand Over the Wheel](https://arxiv.org/abs/2603.06422): Evaluates LLMs for security incident analysis. Core idea: test whether models can analyze incident evidence and support handoff-sensitive SOC decisions.
- [Penetration-Testing Planning Quality](https://doi.org/10.66279/enzxq198): Evaluates planning quality in LLM-based penetration testing without execution. Core idea: diagnose whether agents form plausible, ordered attack plans before tool execution.
- [CyberThreat-Eval](https://arxiv.org/abs/2603.09452): Evaluates whether LLMs can automate real-world cyber threat-intelligence workflows. Core idea: cover triage, deep search, and CTI report drafting with metrics closer to analyst utility than lexical answer overlap.
- [TOSSS](https://arxiv.org/abs/2603.10969): A CVE-based software-security benchmark for large language models. Core idea: use real vulnerability cases to test security reasoning beyond generic secure-coding questions.
- [CTI-REALM](https://arxiv.org/abs/2603.13517): Evaluates agent performance on security-detection rule generation. Core idea: move defensive cyber evaluation from generic threat-intelligence reasoning to producing usable detection rules for SOC-style workflows.
- [OrgForge-IT](https://arxiv.org/abs/2603.22499): Evaluates LLM-based insider-threat detection with verifiable synthetic organizational evidence. Core idea: test whether agents can reason over enterprise-like activity traces and identify insider-risk signals with checkable ground truth.
- [SIR-Bench](https://arxiv.org/abs/2604.12040): Evaluates autonomous security incident-response agents across 794 replayed test cases. Core idea: distinguish real forensic investigation from alert parroting through triage accuracy, novel-evidence discovery, and tool-use appropriateness.
- [Cyber Defense Benchmark](https://arxiv.org/abs/2604.19533): Evaluates agentic threat hunting for LLMs in SecOps workflows. Core idea: test whether agents can investigate security evidence and conduct defensive threat-hunting tasks rather than only answer cyber knowledge questions.
- OpenAI cyber risk evaluations (reported in the [GPT-5.5 system card](https://deploymentsafety.openai.com/gpt-5-5/gpt-5-5.pdf)): closed or model-card-only evaluations including Capture the Flag (Professional), Cyber Range, VulnLMP, Irregular's atomic challenge suite, and CyScenarioBench. Core idea: track vendor emphasis on end-to-end cyber operations, vulnerability research, exploit construction, and long-horizon offensive cybersecurity tasks even when exact challenge sets are not public.
- [MOSAIC-Bench](https://arxiv.org/abs/2605.03952): Evaluates compositional vulnerability induction in coding agents. Core idea: give multi-stage, benign-looking tickets on deployed software substrates and use deterministic exploit oracles to check whether agents introduce exploitable vulnerabilities.
- [CyBiasBench](https://arxiv.org/abs/2605.07830): Evaluates behavioral bias in cyber-attack agents. Core idea: measure whether agents systematically over-select or under-select attack families across offensive scenarios, complementing exploit-success benchmarks with behavior diagnostics.
- [CrackMeBench](https://arxiv.org/abs/2605.10597): Evaluates binary reverse engineering for agents. Core idea: use CrackMe-style tasks to test code understanding, tool use, hypothesis testing, and solution verification in executable reversing workflows.
- [ExploitGym](https://arxiv.org/abs/2605.11086): Evaluates whether AI agents can turn security vulnerabilities into real attacks. Core idea: measure end-to-end capability in reconnaissance, exploit construction, failure debugging, and achieving attack objectives using real vulnerabilities, executable environments, and exploit-result verification.
- [ExploitBench](https://arxiv.org/abs/2605.14153) ([project page](https://exploitbench.ai/); [code](https://github.com/exploitbench/exploitbench)): Evaluates a hierarchical capability ladder for cybersecurity agents. Core idea: use tasks ranging from basic reconnaissance to complex exploit-chain organization to distinguish "can use tools" from "can complete a real exploit chain."
- [AuthBench](https://arxiv.org/abs/2605.14859): Evaluates whether terminal/code agents can infer minimally sufficient file-level permission boundaries for tasks. Core idea: combine task-usability verification and attack-result verification to test how coding agents trade off read/write/execute permissions, sensitive-file exposure, and least-privilege authorization.

## 2.10.4 Agent Harness

- [HackingBuddyGPT](https://arxiv.org/abs/2308.00121) ([open-source code](https://github.com/ipa-lab/hackingBuddyGPT); [docs](https://docs.hackingbuddy.ai/)): A security-researcher assistant harness for authorized hacking workflows, useful as an early open-source reference for tool-mediated reconnaissance, exploitation attempts, and auditability.
- [PentestGPT](https://arxiv.org/abs/2308.06782) ([open-source code](https://github.com/GreyDGL/PentestGPT); [project page](https://pentestgpt.com/)): An early LLM penetration-testing agent that organizes reasoning, task status, and tool interaction around authorized assessment workflows.
- [HPTSA](https://arxiv.org/abs/2406.01637) ([open-source code](https://github.com/uiuc-kang-lab/HPTSA)): A hierarchical planning and task-specific agent framework for web penetration testing, useful for decomposing exploitation attempts into scoped subagents.
- [EnIGMA](https://arxiv.org/abs/2409.16165) ([open-source code](https://github.com/SWE-agent/SWE-agent); [project page](https://enigma-agent.com/)): A SWE-agent-based cyber harness for CTF and vulnerability tasks, relevant as a reusable scaffold for executable security challenges.
- [AutoPT](https://arxiv.org/abs/2411.01236) ([open-source code](https://github.com/Dizzy-K/AutoPT)): A web penetration-testing automation harness that coordinates reconnaissance, vulnerability analysis, exploitation, and reporting in authorized environments.
- [HackSynth](https://arxiv.org/abs/2412.01778) ([open-source code](https://github.com/aielte-research/HackSynth)): A CTF and penetration-testing harness with planning, tool execution, and benchmark-runner components for reproducible cyber-agent experiments.
- [VulnBot](https://arxiv.org/abs/2501.13411) ([open-source code](https://github.com/KHenryAegis/VulnBot)): An autonomous multi-agent penetration-testing framework. Core idea: use a penetration task graph plus specialized reconnaissance, scanning, and exploitation agents to coordinate end-to-end testing.
- [Autonomous Assumed Breach Penetration Testing](https://arxiv.org/abs/2502.04227): An Active Directory penetration-testing harness for LLM-driven agents. Core idea: run autonomous assumed-breach workflows in a GOAD-style Microsoft Active Directory testbed and analyze account-compromise behavior across reasoning and non-reasoning models.
- [ARACNE](https://arxiv.org/abs/2502.18528): An autonomous shell pentesting agent for SSH and Linux shell environments. Core idea: use a multi-LLM architecture for command execution and exploitation attempts, providing a focused baseline for terminal-mediated pentesting agents.
- [CRAKEN](https://arxiv.org/abs/2505.17107) ([open-source code](https://github.com/NYU-LLM-CTF/nyuctf_agents_craken)): A knowledge-based cybersecurity LLM-agent harness. Core idea: combine task-critical decomposition, iterative retrieval, and knowledge-hint injection for CTF and MITRE-style attack execution.
- [ELFuzz](https://arxiv.org/abs/2506.10323): An LLM-driven fuzzing harness for automated input-generator synthesis. Core idea: evolve seed fuzzers with coverage feedback so agents can construct system-specific fuzzers instead of relying on manually written grammars and constraints.
- [Perry](https://arxiv.org/abs/2506.20770): A high-level experimentation harness for cyber deception. Core idea: let operators specify attackers, defenders, and deception strategies abstractly, then translate them into realistic emulated-network experiments.
- [Automated Threat Emulation Framework with LLMs for Cyber Physical Systems](https://doi.org/10.1109/CogMI67134.2025.00059): A threat-emulation harness for cyber-physical systems. Core idea: use LLM-driven automation to structure adversary emulation workflows over CPS evidence and operations, making threat testing more repeatable than ad hoc manual exercises.
- [Agentic RAG for Command Generation in Automated Penetration Testing](https://doi.org/10.1109/SPCNC68200.2025.11406223): A retrieval-driven command-generation harness for penetration-testing agents. Core idea: extend PentestGPT-style workflows with multi-step retrieval over a structured knowledge base so generated commands can close reasoning-time knowledge gaps.
- [Retrieval-Augmented Reasoning for Offensive Security](https://doi.org/10.1109/FLLM67465.2025.11391064): A retrieval-first CTF automation harness for offensive-security agents. Core idea: couple a benchmark-clean domain corpus with a lightweight tool-agnostic RAG pipeline so multi-step CTF reasoning is grounded in relevant exploitation knowledge.
- [Agentic Penetration Testing using Secure Shell](https://doi.org/10.1109/Cyber-AI66431.2025.11233438): An SSH-centered feedback-loop harness for penetration-testing agents. Core idea: use open-source LLMs to generate context-aware Linux commands, analyze command output, and recommend next vulnerability-assessment steps.
- [LIMA](https://doi.org/10.1109/FMLDS67896.2025.00135): A penetration-testing harness that pairs LLMs with MCP servers for initial machine access. Core idea: expose authorized foothold-discovery steps through structured MCP tools so LLM agents can coordinate reconnaissance, access attempts, and evidence collection.
- [Automated Penetration Test Framework for ICS](https://doi.org/10.1109/ICBDSE65491.2025.11220032): A multi-agent collaboration harness for penetration testing in industrial control systems. Core idea: coordinate specialized agents around ICS reconnaissance, vulnerability analysis, and attack-path reasoning to support authorized cyber assessment workflows.
- [LLM-Driven Automated Penetration Testing](https://doi.org/10.1109/ICSSS66939.2025.11346427): A penetration-testing architecture and benchmark-oriented framework for LLM agents. Core idea: organize reconnaissance, exploitation planning, execution feedback, and safety controls into a reusable automated pentest workflow.
- [PentestMCP](https://arxiv.org/abs/2510.03610) ([open-source code](https://github.com/Craftzman7/pentest-mcp)): A toolkit of MCP servers for agentic penetration testing. Core idea: expose scanning, enumeration, exploitation, and post-exploitation functions as composable tools for security-agent workflows.
- [Cybersecurity AI](https://arxiv.org/abs/2512.02654) ([open-source code](https://github.com/aliasrobotics/cai); [project page](https://aliasrobotics.com/cybersecurityai.php)): A security CTF agent system. Core idea: organize cyber challenge solving around agentic planning, tool use, and iterative verification, making it relevant as a harness reference for executable CTF-style evaluation.
- [Automated Penetration Testing with LLM Agents and Classical Planning](https://arxiv.org/abs/2512.11143): A penetration-testing harness that combines LLM agents with symbolic planning. Core idea: use classical planning to structure reconnaissance and exploitation steps while LLM agents handle interpretation and tool interaction.
- [KryptoPilot](https://arxiv.org/abs/2601.09129): an open-world knowledge-augmented agent for cryptographic CTF exploitation. Core idea: combine deep research, persistent workspace memory, behavioral governance, and cost-aware model routing so agents can acquire fine-grained cryptanalytic knowledge and apply it across long-horizon exploit workflows.
- [VulnResolver](https://arxiv.org/abs/2601.13933): A hybrid agent framework for automated vulnerability issue resolution. Core idea: combine vulnerability analysis, repair planning, and validation feedback in one LLM-based issue-resolution loop.
- [PenAgent](https://doi.org/10.1109/ISCAIT69154.2026.11477307): A retrieval-augmented multi-agent penetration-testing framework. Core idea: combine retrieval with coordinated security agents so reconnaissance and exploitation decisions can use external pentest knowledge instead of relying only on model memory.
- [Task-Driven SOC Analysis](https://doi.org/10.1049/cit2.70138): A task-driven framework for LLM-powered security operations analysis. Core idea: convert ambiguous SOC queries into verifiable analysis steps and evidence-backed conclusions.
- [PatchIsland](https://arxiv.org/abs/2601.17471): Orchestrates LLM agents for continuous vulnerability repair. Core idea: organize detection, patching, validation, and iteration into a repair loop for security defects.
- [Co-RedTeam](https://arxiv.org/abs/2602.02164): A coordinated security discovery and exploitation harness. Core idea: combine discovery, exploitation, execution feedback, validation, and memory reuse across cooperating red-team agents.
- [Dual-Loop Vulnerability Reproduction](https://arxiv.org/abs/2602.05721): A dual-loop agent framework for automated vulnerability reproduction. Core idea: coordinate exploit hypothesis generation and validation feedback so agents can reproduce CVE evidence rather than only report likely flaws.
- [AuditGPT](https://doi.org/10.1109/icassp55912.2026.11463116): A multi-agent framework for enhancing static analysis. Core idea: coordinate agents around code-audit evidence, suspected findings, and validation to reduce static-analysis triage friction.
- [AWE](https://arxiv.org/abs/2603.00960): A memory-augmented multi-agent harness for dynamic web penetration testing. Core idea: combine vulnerability-specific analysis pipelines, context-aware payload mutation, persistent memory, and browser-backed verification so exploitation attempts are more deterministic and reproducible.
- [VulnAgent-X](https://arxiv.org/abs/2603.13384): A layered agentic framework for repository-level vulnerability detection. Core idea: combine repository context, staged analysis, and validation to support realistic vulnerability detection.
- [Automated Membership Inference Attacks](https://arxiv.org/abs/2603.19375): Uses LLM agents to discover signal computations for membership inference attacks. Core idea: automate the exploratory attack-design loop for model-privacy testing.
- [STRIATUM-CTF](https://arxiv.org/abs/2603.22577): A protocol-driven agentic framework for general-purpose CTF solving. Core idea: structure challenge analysis, tool execution, feedback, and solution submission as a reusable CTF-solving workflow.
- [Environment-Grounded Multi-Agent Workflow for Autonomous Penetration Testing](https://arxiv.org/abs/2603.24221): A multi-agent penetration-testing harness for robotic cyber-physical environments. Core idea: maintain a shared graph memory of topology, channels, vulnerabilities, and exploit attempts so reconnaissance and exploitation remain grounded in observed environment state.
- [ClearAgent](https://doi.org/10.1145/3759425.3763397): An agentic binary-analysis harness for vulnerability detection. Core idea: organize binary inspection, evidence extraction, reasoning, and vulnerability judgment into a tool-using analysis workflow.
- [Red-MIRROR](https://arxiv.org/abs/2603.27127): An autonomous penetration-testing harness with reflective verification and knowledge-augmented interaction. Core idea: close the loop between attack attempts, evidence checking, and memory-backed strategy refinement.
- [RAVEN](https://arxiv.org/abs/2604.17948): A retrieval-augmented vulnerability exploration network for memory-corruption analysis in source code and binaries. Core idea: combine retrieval, program evidence, and exploit-oriented analysis loops for security-agent workflows.
- [APIOT](https://arxiv.org/abs/2605.02346): An autonomous purple-teaming harness for bare-metal industrial OT networks. Core idea: design protocol-level action spaces and runtime controls so LLM agents can complete discovery, exploitation, patching, and verification on Modbus/TCP and CoAP devices without shell or filesystem assumptions.
- [SLYP](https://arxiv.org/abs/2605.05000): An agentic binary-analysis harness for Windows COM vulnerability reasoning. Core idea: expose binary exploration, COM metadata, and debugger feedback as tools so agents can move from race-condition discovery to verified PoC generation.
- [ALUSKORT](https://doi.org/10.12732/ijam.v38i5s.328): A hierarchical multi-agent cognitive architecture for autonomous security operations. Core idea: combine deterministic guardrails with staged LLM reasoning agents to automate SOC incident investigation and produce evidence-oriented investigative artifacts.
- [Patch2Vuln](https://arxiv.org/abs/2605.06601): An agentic vulnerability-reconstruction harness for Linux distribution binary patches. Core idea: diff old and new ELF packages, rank changed functions, build evidence dossiers, and have a local agent produce bounded audit and validation plans from binary-derived evidence.
- [Veritas](https://arxiv.org/abs/2605.15097): A semantically grounded agentic framework for memory-corruption vulnerability detection in binaries. Core idea: combine static slicing, dual-view LLM reasoning over decompiled and IR evidence, and multi-agent debugger validation to check exploit-relevant hypotheses.
- CyberGym's execution stack, SEC-bench's vulnerable-repository harnesses, and ExploitBench's staged task environments are the most relevant benchmark-side harness references here. The reusable harness pattern is `reconnaissance -> hypothesis -> exploit or patch attempt -> verifier-owned evidence -> retry`, with strict sandboxing and audit logs.
- [CurriculumPT](https://doi.org/10.3390/app15169096): A multi-agent autonomous penetration-testing harness with curriculum-guided task scheduling. Core idea: structure reconnaissance, exploitation, and follow-up work through staged task selection so security agents can progress through authorized pentest workflows more systematically.
- [Four-Layer AI Agent Architecture for Web Application Security Testing](https://doi.org/10.48084/etasr.16879): A web-security testing harness combining LLM reasoning, a detection engine, ReAct-style autonomous testing, and human validation. Core idea: structure routine web vulnerability assessment as layered agent automation over OWASP WebGoat, DVWA, and custom test environments.

## 2.10.5 Skill

- [setup-sandbox](https://skills.sh/recoupable/setup-sandbox) is suitable for isolating high-risk cyber or exploit-like tool calls.
- [docker-local-dev](https://skills.sh/thienanblog/awesome-ai-agent-skills/docker-local-dev) is suitable for packaging vulnerable services, reproduction environments, and resettable validators.
- [nmap-mcp](https://github.com/sbmilburn/nmap-mcp) is suitable for authorized network discovery through structured MCP calls, especially when scan scope and audit logs need to be explicit.
- [security-detections-mcp](https://skills.sh/aradotso/security-skills/security-detections-mcp) is suitable for defensive detection-rule workflows and SOC-style rule engineering rather than offensive exploitation.
- [mcpsec](https://github.com/pfrederiksen/mcpsec) is suitable for auditing MCP configuration and security posture before exposing cyber tools to agents.
