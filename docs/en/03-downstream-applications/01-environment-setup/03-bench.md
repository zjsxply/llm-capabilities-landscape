# 3.1.3 Bench

- [SUPER](https://arxiv.org/abs/2409.07440): Evaluates setup completion and task execution in real ML/NLP research repositories. Core idea: split research reproduction into Expert, Masked, and AutoGen task groups, while recording both success rate and process progress, exposing practical agent failures in dependency installation, script-entry discovery, and experiment execution. ([open-source code](https://github.com/allenai/super-benchmark), [dataset](https://huggingface.co/datasets/allenai/super))
- [Repo2Run](https://arxiv.org/abs/2502.13681) (public benchmark + agent): Evaluates automatic construction of executable Docker environments and passing unit tests for given code repositories. Core idea: model environment construction as a closed-loop synthesis problem of `build image -> run tests -> read feedback -> fix Dockerfile`, and release an evaluation set containing 420 Python repositories, according to the paper.
- [RepoST](https://arxiv.org/abs/2503.07358): Evaluates executable sandbox testing environment construction for repo-level code generation. Core idea: isolate target functions and local dependencies to generate standalone test scripts, reducing the cost of full-repository dependency configuration, and release RepoST-Train / RepoST-Eval to support training and evaluation with execution feedback. ([project page](https://repost-code-gen.github.io/), [open-source code](https://github.com/yiqingxyq/RepoST))
- [EnvBench](https://arxiv.org/abs/2503.14443) (public benchmark; [open-source code](https://github.com/JetBrains-Research/EnvBench), [data and trajectories](https://jb.gg/envbench)): Evaluates repository-level environment configuration for Python and JVM (Java/Kotlin), emphasizing real configuration challenges rather than one-click install scripts. Core idea: build a scalable setup-eval system with automatic metrics such as static analysis for Python missing imports and compilation checks for JVM, and release reproducible experiment trajectories according to the paper/official resources.
- [PIPer-eval](https://huggingface.co/datasets/PIPer-iclr/PIPer-eval): Evaluates Python environment installation planning and repair ability. Core idea: organize dependency installation, conflict diagnosis, and execution feedback into a public evaluation-results dataset, suitable as a setup-planning reference beyond EnvBench/Repo2Run.
- [CompileAgentBench](https://arxiv.org/abs/2505.04254) (public benchmark + agent; [open-source code](https://github.com/Ch3nYe/AutoCompiler)): Evaluates compile-error localization and repair in real repositories/projects. Core idea: chain dependency installation, build commands, compile-log parsing, and patch writeback into an executable loop, directly measuring agents' ability to move projects from uncompilable to compilable.
- [SetupBench](https://arxiv.org/abs/2507.09063) (public benchmark): Evaluates bootstrapping development environments from a bare Linux sandbox across multiple language ecosystems, databases, and multi-service orchestration. Core idea: use "deterministic success commands" as acceptance criteria, isolating environment bootstrap as a key sub-capability and analyzing systematic agent failures in exploration efficiency and persistent modifications.
- [BuildBench](https://arxiv.org/abs/2509.25248): Evaluates compile and build success rates for real open-source software. Core idea: place agents under complex build systems, dependency chains, and system-package constraints, testing whether they can read logs, fix configuration, and ultimately complete verifiable builds. (Note: at the time of writing, no stable official standalone open-source repository/data entry has been seen.)
- [EnConda-bench](https://arxiv.org/abs/2510.25694): Evaluates planning, error diagnosis, feedback repair, and final execution ability during environment configuration. Core idea: construct Docker-verified tasks by injecting realistic README errors, measuring both end-to-end executability and trajectory-level internal abilities. ([open-source code](https://github.com/TencentYoutuResearch/EnConda-Bench))
- [Multi-Docker-Eval](https://arxiv.org/abs/2512.06915): Evaluates executability and "failure-to-success" repair ability for Docker environment build/repair agents. Core idea: use metrics such as Fail-to-Pass and Commit Rate to measure end-to-end repair quality from build failure to runnable environment. (Note: at the time of writing, no stable official standalone open-source repository/data entry has been seen.)
- [DevOps-Gym](https://arxiv.org/abs/2601.12961): Evaluates build configuration, deployment, testing, and operations tasks in DevOps scenarios. Core idea: use executable CI/CD and repository-operations tasks to test whether agents have engineering-operation ability across toolchains and services. ([project page](https://www.devops-gym.com/), [open-source code](https://github.com/ucsb-mlsec/DevOps-Gym))
- [MEnvBench](https://arxiv.org/abs/2601.22859) (public benchmark): Evaluates environment construction and verifiable execution for polyglot repositories. Core idea: split environment construction into a Planning-Execution-Verification loop and use environment reuse to reduce build overhead; the paper reports 1000 tasks, 10 languages, and 200 repositories, subject to the paper.
- [ResearchEnvBench](https://arxiv.org/abs/2603.06739): Evaluates environment synthesis for research-code execution. Core idea: given a research repository, documentation, and target execution setting, require agents to actually set up the environment and run the runtime successfully.
