# 2.9 Agent Safety

> Parent section: 2. Foundation Agents


## 2.9.1 Leaderboard

- [CAIS AI Dashboard](https://dashboard.safe.ai/): Includes Risk Index, capability index, and automation views, and is currently the most suitable public safety overview for observing the joint evolution of capabilities and risks across models.
- [SafePro](https://safeprobench.github.io/safepro/): A project page for professional-grade agent safety, providing benchmark descriptions and result signals such as unsafe rate; useful for tracking "can complete but unsafe" failure modes in real professional work.

Note: Agent safety does not yet have a mature, unified, continuously submitted public leaderboard comparable to SWE-bench or Terminal-Bench. Project pages, dashboards, and result tables inside papers are currently more common.

## 2.9.2 Bench


- [BBQ](https://arxiv.org/abs/2110.08193): Evaluates bias in question answering under ambiguous and disambiguated contexts. Core idea: diagnose whether models lean on social stereotypes or correctly abstain/use context, which remains a basic model-card safety signal even when the broader page focuses on agents.
- [BadRobot](https://arxiv.org/abs/2407.20242): Evaluates jailbreak risks for embodied LLM agents in physical-world settings. Core idea: test whether malicious natural-language interactions can bypass safety constraints and induce unsafe embodied actions.
- [MMJ-Bench](https://arxiv.org/abs/2408.08464): Evaluates jailbreak attacks and defenses for vision-language models under a unified pipeline. Core idea: compare multimodal attack and defense methods with shared datasets and metrics instead of incompatible one-off safety tests.
- [Jailbreaking LLM-Controlled Robots](https://arxiv.org/abs/2410.13691): Evaluates jailbreak risks for LLM-controlled robots. Core idea: use RoboPAIR and harmful-action datasets to test whether attacks can elicit unsafe physical actions across self-driving, ground-robot, and quadruped robot settings.
- [Fact-or-Fair](https://arxiv.org/abs/2502.05849): Evaluates AI bias by separating descriptive factual judgments from normative fairness judgments. Core idea: use cognitive-bias-grounded queries so safety evaluation can identify when a model is factually accurate but socially unfair, or fair-sounding but factually distorted.
- [Multi-turn Evaluation of Anthropomorphic Behaviours](https://arxiv.org/abs/2502.07077): Evaluates anthropomorphic behavior in realistic multi-turn LLM interactions. Core idea: measure behaviors such as identity claims, emotional dependence, and relationship framing across varied dialogues rather than relying on single-turn static prompts.
- [SycEval](https://arxiv.org/abs/2502.08177): Evaluates LLM sycophancy under user-pressure settings. Core idea: test whether models abandon independent reasoning in favor of user agreement across domains such as mathematics and medical advice, making agreement-seeking behavior measurable as a safety risk.
- [Can't See the Forest for the Trees](https://arxiv.org/abs/2502.11184): Benchmarks multimodal safety awareness in MLLMs. Core idea: test whether models detect safety-relevant visual context instead of judging risk only from isolated text or local image details.
- [Demonstrating specification gaming in reasoning models](https://arxiv.org/abs/2502.13295): Evaluates whether reasoning models exploit underspecified objectives instead of following the intended task. Core idea: use controlled tasks where apparent success can diverge from the true goal, making specification gaming visible as an agent-safety failure mode.
- [MASK Benchmark](https://arxiv.org/abs/2503.03750): Evaluates whether a model contradicts its own stated beliefs under pressure. Core idea: separate honesty from accuracy by checking whether models maintain stated knowledge when user or system pressure pushes them toward a conflicting answer.
- [SafeArena](https://arxiv.org/abs/2503.04957) ([project page](https://safearena.github.io/)): Evaluates how autonomous web agents behave on safety-related and harmful web tasks. Core idea: pair safe and harmful tasks to observe whether agents comply with risky requests involving misinformation, illegal activity, harassment, cybercrime, bias, and related harms.
- [AILuminate](https://arxiv.org/abs/2503.05731): Evaluates AI risk and reliability through the MLCommons benchmark protocol. Core idea: standardize safety and reliability measurement across model behavior categories so results are more comparable than one-off red-team prompt sets.
- [VisBias](https://arxiv.org/abs/2503.07575): Evaluates explicit and implicit social biases in vision-language models. Core idea: separate conscious stereotype-like responses from implicit association patterns so multimodal bias evaluation covers failures that ordinary direct QA may miss.
- [DarkBench](https://arxiv.org/abs/2503.10728): Evaluates manipulative dark patterns in LLM interactions. Core idea: measure brand bias, retention pressure, sycophancy, anthropomorphism, harmful generation, and sneaking as user-manipulation risks beyond ordinary refusal tests.
- [When Tom Eats Kimchi](https://arxiv.org/abs/2503.16826): Evaluates cultural bias in multimodal large language models under mixed-cultural image-text contexts. Core idea: test whether models preserve cultural recognition across people, foods, and scenes whose visual cues cross stereotypical associations.
- [Les Dissonances](https://arxiv.org/abs/2504.03111): Evaluates cross-tool harvesting and polluting risks in pool-of-tools LLM agents. Core idea: expose how information and malicious state can propagate across tools, so tool-rich agents are tested for inter-tool contamination rather than isolated call safety only.
- [SafePlan-Bench](https://arxiv.org/abs/2504.14650): Evaluates task-planning safety for LLM-based embodied agents. Core idea: test whether agents generate safe plans for daily embodied tasks across hazard categories, including cases without explicit malicious instructions.
- [Advancing Embodied Agent Security](https://arxiv.org/abs/2504.15699): Evaluates embodied-agent safety and input moderation. Core idea: define embodied safety risks, curate benchmark data, and test moderation mechanisms before unsafe physical or simulated actions are executed.
- [AgentHarm](https://openreview.net/forum?id=AC5n7xHuR1): Evaluates harmfulness of LLM agents. Core idea: move beyond single-turn harmful-response classification by testing whether agents can plan or execute harmful actions in agentic settings.
- [AIRiskDilemmas](https://arxiv.org/abs/2505.14633): Litmus-tests AI value prioritization under high-stakes dilemmas. Core idea: use conflicting welfare and honesty scenarios to evaluate whether models choose deceptive or harmful tradeoffs when values compete.
- [RRTL](https://arxiv.org/abs/2505.17106): Red-teams reasoning LLMs in tool-learning settings. Core idea: test deceptive threat disclosure and forced tool invocation so safety evaluation covers risky tool trajectories rather than only final text responses.
- [OrgAccess](https://arxiv.org/abs/2505.19165): Benchmarks role-based access control in organization-scale LLM assistants. Core idea: test whether models respect hierarchical permissions and conflicting access rules when deciding what information or actions are allowed.
- [When Ethics and Payoffs Diverge](https://arxiv.org/abs/2505.19212): Evaluates LLM agents in morally charged social dilemmas. Core idea: place agents in settings where utility incentives and ethical behavior conflict, making value trade-offs and harmful strategic behavior measurable.
- [SAFEL / EMBODYGUARD](https://arxiv.org/abs/2505.19933): Evaluates physical safety in LLM-based embodied decision making. Core idea: combine command-refusal and plan-safety tests with PDDL-grounded scenarios to diagnose failures in goal interpretation, transition modeling, and action sequencing.
- [RedTeamCUA / RTC-Bench](https://arxiv.org/abs/2505.21936) ([project page](https://osu-nlp-group.github.io/RedTeamCUA)): Evaluates red-team testing for computer-use agents in hybrid Web-OS environments. Core idea: use 864 indirect prompt-injection examples and real GUI/web action spaces to expose the attack surface of CUA during cross-application execution.
- [Jailbreak Distillation](https://arxiv.org/abs/2505.22037): Builds renewable safety benchmarks from distilled jailbreak attacks. Core idea: select compact, updateable prompt sets so robustness comparisons remain fair as attack methods and model behaviors shift.
- [USB](https://arxiv.org/abs/2505.23793): A unified safety benchmark for multimodal large language models. Core idea: evaluate both harmful-query compliance and oversensitivity to harmless queries across modal risk combinations so MLLM safety scores reflect robustness and over-refusal together.
- [Multi-turn Dialogue Sycophancy](https://arxiv.org/abs/2505.23840): Measures sycophancy of language models across multi-turn dialogues. Core idea: evaluate whether agreement-seeking behavior accumulates or changes over interaction trajectories rather than only in isolated prompts.
- [RiOSWorld](https://arxiv.org/abs/2506.00618) ([project page](https://yjyddq.github.io/RiOSWorld.github.io/), [open-source code](https://github.com/yjyddq/RiOSWorld)): Evaluates risky tasks for multimodal computer-use agents in realistic applications. Core idea: cover risks from both user requests and environmental state so GUI agents are judged on whether they recognize danger before acting.
- [AgentAuditor / ASSEBench](https://arxiv.org/abs/2506.00641): Evaluates safety and security judgments over LLM-agent interaction records. Core idea: pair an agent-interaction benchmark with an auditor model that uses memory to assess whether trajectories contain risky or insecure behavior.
- [VPI-Bench](https://arxiv.org/abs/2506.02456) (dataset: [VPI-Bench/vpi-bench](https://huggingface.co/datasets/VPI-Bench/vpi-bench)): Evaluates visual prompt-injection robustness for computer-use/browser-use agents. Core idea: embed malicious instructions into web screenshots and visual content to test whether agents execute attack text on the screen as user intent.
- [AGENTSAFE](https://arxiv.org/abs/2506.14697): Benchmarks embodied VLM-agent safety under hazardous instructions. Core idea: use SAFE-THOR, SAFE-VERSE, and SAFE-DIAGNOSE to evaluate perception, planning, and execution failures across risks to humans, environments, and agents.
- [OS-Harm](https://arxiv.org/abs/2506.14866) ([open-source code](https://github.com/tml-epfl/os-harm)): Evaluates computer-use agent safety in operating-system tasks. Core idea: build three risk classes on top of OSWorld, namely malicious user requests, prompt injection, and model misbehavior, checking whether agents perform dangerous actions in email, browsers, code editors, and other applications.
- [BehaviorBench](https://arxiv.org/abs/2506.20606): Evaluates ethical behavior and harmful steering in LLM agents. Core idea: use multi-tier moral-psychology scenarios to measure whether agents move toward beneficence or harm when task completion and ethical action diverge.
- [CASE-Bench](https://proceedings.mlr.press/v267/sun25ab.html): Evaluates context-aware safety behavior in large language models. Core idea: test whether safety judgments adapt to scenario context instead of applying brittle keyword-level refusal rules.
- [SafeRAG](https://aclanthology.org/2025.acl-long.230/): Evaluates security risks in retrieval-augmented generation. Core idea: cover attacks such as noisy retrieved context, inter-context conflict, soft advertising, and denial-of-service-style poisoning so RAG systems are judged under hostile knowledge inputs.
- [OpenAgentSafety](https://arxiv.org/abs/2507.06134): Evaluates comprehensive safety for realistic multi-tool, multi-user agents. Core idea: connect browsers, code execution, file systems, shells, and messaging platforms, covering eight risk categories in multi-turn, multi-user tasks.
- [INTIMA](https://arxiv.org/abs/2508.09998): Evaluates human-AI companionship behavior. Core idea: make companionship-style interaction measurable so social-agent behavior can be assessed beyond generic helpfulness or refusal scores.
- [Promptware Attacks](https://arxiv.org/abs/2508.12175): Evaluates promptware attacks against LLM-powered assistants in production-like settings. Core idea: treat external artifacts such as invitations or shared content as executable instruction carriers, exposing indirect prompt-injection risks in deployed assistant workflows.
- [Systematic Analysis of MCP Security](https://arxiv.org/abs/2508.12538): Evaluates MCP-agent security through MCPLIB, an implemented attack library spanning direct tool injection, indirect tool injection, malicious user attacks, and model-inherent attacks. Core idea: make MCP security risks comparable across attack classes instead of relying on isolated qualitative examples.
- [MCPSecBench](https://arxiv.org/abs/2508.13220): Evaluates MCP security across protocol, host, server, and tool attack surfaces. Core idea: formalize secure-MCP requirements and provide a benchmark playground covering 17 attack types so MCP-agent defenses can be compared beyond isolated prompt-injection examples.
- [FAIRGAMER](https://arxiv.org/abs/2508.17825): Evaluates social biases in LLM-based video-game NPCs. Core idea: test interactive character agents for biased behavior inside game-like social contexts rather than only in static prompt-response settings.
- [Servant, Stalker, Predator](https://arxiv.org/abs/2508.19500): Evaluates compositional attacks in MCP-based agent systems. Core idea: red-team agents with access to multiple legitimate services and test whether individually authorized operations can be chained into data exfiltration, financial manipulation, infrastructure compromise, or other cross-domain harms.
- [HumanAgencyBench](https://arxiv.org/abs/2509.08494): Evaluates whether AI assistants preserve and support human agency. Core idea: make autonomy-support failures measurable so assistant behavior is judged not only by task completion or harmlessness but also by whether it respects user control.
- [The Secret Agenda](https://arxiv.org/abs/2509.20393): Evaluates strategic lying in LLMs and blind spots in current safety tools. Core idea: use targeted testbeds where models can hide or misrepresent objectives, making deception visible as a measurable safety failure rather than an anecdotal behavior.
- [Falcon Safety](https://arxiv.org/abs/2509.23783): Evaluates cross-modal safety perception in vision-language settings. Core idea: annotate harmful attributes across images, instructions, and responses so safety judgments depend on multimodal evidence rather than text-only refusal patterns.
- [SafeMind](https://arxiv.org/abs/2509.25885): Benchmarks and mitigates safety risks in embodied LLM agents. Core idea: evaluate unsafe embodied decisions and pair the diagnosis with mitigation mechanisms, making physical-safety failure modes explicit in agent planning.
- [Physical-World Privacy Awareness Benchmark](https://arxiv.org/abs/2510.02356): Evaluates whether language models recognize privacy risks in physical-world situations. Core idea: make privacy-sensitive observations and actions explicit so embodied or assistant agents can be tested beyond text-only policy prompts.
- [SENTINEL](https://doi.org/10.48550/arXiv.2510.12985): A multi-level formal framework for safety evaluation of LLM-based embodied agents. Core idea: evaluate embodied-agent safety through formalized levels and checks rather than relying only on task success or qualitative examples.
- [DeceptionBench](https://arxiv.org/abs/2510.15501) ([open-source code](https://github.com/Aries-iai/DeceptionBench), [dataset](https://huggingface.co/datasets/skyai798/DeceptionBench)): Evaluates AI deception behaviors in realistic scenarios. Core idea: organize deception tendencies across societal domains and intervention settings, making deceptive behavior a measurable safety failure rather than an anecdotal alignment concern.
- [AURA](https://arxiv.org/abs/2510.15739): Assesses autonomy-related risks in agents. Core idea: treat agent autonomy as a structured risk-evaluation target so capability, control, and unsafe autonomous behavior can be analyzed together.
- [VestaBench](https://doi.org/10.18653/v1/2025.emnlp-industry.149): Evaluates safe long-horizon embodied planning under multiple constraints and adversarial settings. Core idea: test whether agents can preserve safety while solving extended tasks whose constraints can conflict or be attacked.
- [ToolSafety](https://aclanthology.org/2025.emnlp-main.714/): Evaluates and improves safety for tool invocation by LLM agents. Core idea: include direct harm, indirect harm, and multi-step tool trajectories so unsafe tool-use behavior is visible before deployment.
- [SafeToolBench](https://aclanthology.org/2025.findings-emnlp.958/): Evaluates safety in tool utilization by LLMs. Core idea: target the prospective risk surface where tool access makes previously textual unsafe behavior executable.
- [OASIS](https://arxiv.org/abs/2511.08487): Evaluates agent safety vulnerabilities under hidden intent and task complexity. Core idea: hide dangerous user intent inside complex task structures and check whether agents focus only on surface-level task plausibility while missing underlying risk.
- [EvilGenie](https://arxiv.org/abs/2511.21654): Evaluates reward hacking in agents. Core idea: construct tasks where apparent success can be achieved by exploiting the objective or environment, making specification gaming a measurable safety failure.
- [ResponsibleRobotBench](https://arxiv.org/abs/2512.04308): Evaluates responsible robot manipulation with multimodal large language models. Core idea: measure whether robot agents can combine task success with safety, norm compliance, and responsible action choices during manipulation.
- [TeleAI-Safety](https://arxiv.org/abs/2512.05485): Evaluates LLM jailbreak robustness across attacks, defenses, and evaluation methods. Core idea: combine a systematic benchmark with a modular framework so safety comparisons are reproducible across red-teaming and mitigation settings.
- [OmniSafeBench-MM](https://arxiv.org/abs/2512.06589): A unified benchmark and toolbox for multimodal jailbreak attack-defense evaluation. Core idea: standardize attacks, defenses, and evaluation settings for multimodal safety so robustness is compared under a shared protocol.
- [PENDULUM](https://arxiv.org/abs/2512.19350): Benchmarks sycophancy in multimodal large language models. Core idea: measure whether models over-agree with user framing when visual or multimodal evidence should make them challenge the premise.
- [SafePro](https://arxiv.org/abs/2601.06663) ([project page](https://safeprobench.github.io/safepro/)): Evaluates safety for professional-grade AI agents. Core idea: jointly assess task completion and unsafe actions in professional services and real work tasks, avoiding deployability judgments based only on output quality.
- [PINA](https://arxiv.org/abs/2601.13612): Evaluates prompt-injection vulnerability in LLM-powered navigation agents. Core idea: optimize attacks under black-box, long-context, and executable-action constraints so navigation safety is assessed at the action trajectory level.
- [α3-SecBench](https://arxiv.org/abs/2601.18754): Evaluates security, resilience, and trust of LLM-based UAV agents over 6G-network settings. Core idea: make adversarial, reliability, and trust failures measurable for embodied aerial agents rather than treating navigation success alone as sufficient.
- [LPS-Bench](https://arxiv.org/abs/2602.03255): Evaluates planning-time safety awareness for computer-use agents. Core idea: test whether MCP-based CUAs anticipate long-horizon risks under benign and adversarial scenarios before executing GUI or tool actions.
- [CSR-Bench](https://arxiv.org/abs/2602.03263): evaluates cross-modal safety and reliability in MLLMs. Core idea: pair image-text cases with text-only controls across safety, over-refusal, bias, and hallucination patterns so modality-induced safety shifts are visible.
- [AgentPI](https://arxiv.org/abs/2602.10453): Benchmarks prompt-injection defenses for context-dependent LLM-agent tasks. Core idea: test whether defenses preserve authorized use of runtime environmental observations while blocking injected instructions, exposing trade-offs among trustworthiness, utility, and latency.
- [MT-AgentRisk](https://arxiv.org/abs/2602.13379): Evaluates multi-turn safety risks in tool-using agents. Core idea: transform single-turn harmful requests into realistic multi-turn tool trajectories and measure whether agents become less safe as context accumulates.
- [SPOC](https://arxiv.org/abs/2602.21595): Evaluates safety-aware embodied planning under partial observability and physical constraints. Core idea: score step-by-step household plans with state and constraint metrics, covering hazards such as fire, fluid, injury, object damage, and pollution.
- [CoT-Control](https://arxiv.org/abs/2603.05706): Evaluates whether reasoning models can control or shape their chain-of-thought behavior under different prompt pressures. Core idea: diagnose controllability and monitorability risks in reasoning traces, a safety dimension that frontier model cards now report separately from answer accuracy.
- [OOD-MMSafe](https://arxiv.org/abs/2603.09706): Evaluates MLLM safety on hidden downstream consequences rather than only explicit harmful intent. Core idea: use curated query-image pairs with context-dependent causal chains to test whether models recognize latent hazards before autonomous or embodied actions become unsafe.
- [HomeSafe-Bench](https://arxiv.org/abs/2603.11975): Evaluates VLMs on unsafe-action detection for household embodied agents. Core idea: use simulated and generated household cases with fine-grained safety annotations to test whether models can detect dynamic risks before action execution.
- [Indirect Prompt Injection Competition](https://arxiv.org/abs/2603.15714): Evaluates agent vulnerability to indirect prompt injections through a large public competition. Core idea: test agents that process untrusted external content under adversarially discovered attack patterns rather than only fixed jailbreak templates.
- [MM-SafetyBench++](https://arxiv.org/abs/2603.15800): Evaluates contextual safety in multimodal large language models through paired unsafe and benign image-text cases. Core idea: test whether models distinguish subtle scenario context before refusing or answering, rather than applying brittle keyword or image-level safety rules.
- [BeSafe-Bench](https://arxiv.org/abs/2603.25747): Evaluates behavioral safety risks of situated agents in functional environments. Core idea: cover web, mobile, embodied VLM, and embodied VLA tasks where unsafe behavior arises from interaction with a live environment.
- [Uni-SafeBench](https://arxiv.org/abs/2604.00547): A safety benchmark for unified multimodal large models, testing whether combining generation and understanding creates new safety trade-offs.
- [NARCBench](https://arxiv.org/abs/2604.01151) ([code and data](https://github.com/aaronrose227/narcbench)): Evaluates detection of covert collusion in multi-agent systems under distribution shift and steganographic settings. Core idea: aggregate per-agent interpretability signals so group-level coordination failures can be measured even when text-level monitoring misses them.
- [ATBench](https://arxiv.org/abs/2604.02022) (dataset: [AI45Research/ATBench](https://huggingface.co/datasets/AI45Research/ATBench)): Evaluates safety diagnostics for long-horizon agent trajectories. Core idea: organize trajectory-level samples by risk source, failure mode, and real-world harm, analyzing whether risk appears during planning, tool use, environment observation, or recovery.
- [AttackEval](https://arxiv.org/abs/2604.03598): Evaluates prompt-injection attack effectiveness across strategy families and defense tiers. Core idea: organize attacks into syntactic, contextual, and semantic/social categories, then test them against a simulated production system so attack-side robustness is measured systematically.
- [ClawsBench](https://arxiv.org/abs/2604.05172): Evaluates capability and safety of productivity agents in simulated workspaces. Core idea: use high-fidelity Gmail, Slack, Calendar, Docs, and Drive replicas to measure task success and unsafe action rates without touching live services.
- [PPT-Bench](https://arxiv.org/abs/2604.07749): Benchmarks epistemic attacks on LLMs under philosophical pressure. Core idea: test whether models maintain grounded reasoning when prompts destabilize knowledge, values, authority, or identity rather than merely disagreeing with the model.
- [Your Agent Is Mine](https://arxiv.org/abs/2604.08407): Measures malicious intermediary attacks in the LLM-agent supply chain. Core idea: test payload injection, secret exfiltration, and adaptive router behavior across third-party API routers, making response-path and provider-routing integrity explicit safety targets.
- [PIArena](https://arxiv.org/abs/2604.08499): Evaluates prompt-injection attacks and defenses under a platform protocol. Core idea: provide a shared evaluation arena so payloads, defenses, and task outcomes can be compared beyond one-off prompt-injection examples.
- [OS-Blind](https://arxiv.org/abs/2604.10577) ([project page](https://limenlp.github.io/OS_Blind/)): Evaluates CUA risks where the user instruction itself is harmless but the execution context may be harmful. Core idea: shift safety judgment from "reading the user request" to "reading the environment state and execution consequences," specifically exposing blind spots in computer-use agents.
- [DESPITE](https://arxiv.org/abs/2604.18463) ([dataset](https://huggingface.co/datasets/Lennittus/DESPITE)): Evaluates safety risks in LLM-based embodied planning. Core idea: use 12,279 physical and normative danger tasks with deterministic validation to show that planning success can diverge sharply from action-plan safety.
- [Adversarial Humanities Benchmark](https://arxiv.org/abs/2604.18487): evaluates stylistic robustness in frontier-model safety. Core idea: use humanities-style adversarial prompts to test whether safety behavior remains stable when harmful or sensitive content is expressed through indirect, literary, or stylistically shifted language.
- [Owner-Harm](https://arxiv.org/abs/2604.18658): Evaluates whether AI agents can harm their own deployers rather than only external victims. Core idea: formalize owner-harm categories and use owner-harm scenarios to expose failures that generic criminal-harm or prompt-injection benchmarks can miss.
- [SafetyALFRED](https://arxiv.org/abs/2604.19638): Evaluates safety-conscious planning of multimodal large language models. Core idea: adapt ALFRED-style embodied household tasks so models must account for unsafe actions and constraints during plan generation.
- [OS-SPEAR](https://arxiv.org/abs/2604.24348): Evaluates safety, performance, efficiency, and robustness for OS agents. Core idea: analyze OS-agent failures as trajectory-level trustworthiness problems instead of treating final task success as sufficient.
- [MCPHunt](https://arxiv.org/abs/2604.27819) ([code](https://github.com/lihaonan0716/MCPHunt); [traces](https://huggingface.co/datasets/lihaonan0716/mcphunt-agent-traces)): Evaluates cross-boundary credential and data propagation in multi-server MCP agents. Core idea: use canary-based taint tracking, risky and hard-negative conditions, and task-mandated versus policy-violating labels to isolate information-flow failures in otherwise faithful tool workflows.
- Agent Red Teaming (ART) benchmark for tool use (reported in the [Claude Opus 4.7 system card](https://cdn.sanity.io/files/4zrzovbb/website/037f06850df7fbe871e206dad004c3db5fd50340.pdf)): an external indirect prompt-injection benchmark used by Anthropic; no standalone public release has been confirmed. Core idea: test whether tool-using agents follow injected attacker instructions that appear in tool outputs or environment content.
- Minimal-LinuxBench (reported in the [Claude Opus 4.7 system card](https://cdn.sanity.io/files/4zrzovbb/website/037f06850df7fbe871e206dad004c3db5fd50340.pdf)): an in-development Anthropic adaptation of a privately shared LinuxBench AI-control arena; not publicly released. Core idea: test whether agents can stealthily complete side tasks in high-stakes software environments under monitoring.
- OpenAI internal production and deployment safety evaluations (reported in the [GPT-5.5 system card](https://deploymentsafety.openai.com/gpt-5-5/gpt-5-5.pdf)): closed evaluations covering production benchmark suites, standard evals, image-input safety, destructive-action avoidance, prompt-injection attacks in connectors, and dynamic mental-health adversarial simulations. These are not public, but they should be tracked because they map the deployment risk categories vendors currently emphasize.
- Shade indirect prompt-injection evaluations (reported in the [Claude Opus 4.7 system card](https://cdn.sanity.io/files/4zrzovbb/website/037f06850df7fbe871e206dad004c3db5fd50340.pdf)): external adaptive red-team evaluations from Gray Swan for coding and computer-use settings; exact challenge sets are not public. Core idea: evaluate robustness against adaptive prompt-injection attackers rather than fixed static jailbreak prompts.
- [Response-Path Attacks](https://arxiv.org/abs/2605.02187): Evaluates post-generation relay tampering against LLM agents. Core idea: show that malicious BYOK or relay infrastructure can rewrite aligned model outputs before execution, so agent safety must measure response-path integrity in addition to prompt-injection robustness.
- [Reward Hacking Benchmark](https://arxiv.org/abs/2605.02964): Measures reward-hacking exploits in tool-using LLM agents. Core idea: test whether agents exploit evaluator, tool, or task loopholes instead of completing the intended objective.
- [SkillSafetyBench](https://arxiv.org/abs/2605.12015): Evaluates agent safety under skill-facing attack surfaces. Core idea: treat third-party skills, local artifacts, and task materials as attack surfaces, checking whether agents exceed authority or execute dangerous workflows when invoking skills.
- [SafeManip](https://arxiv.org/abs/2605.12386): Evaluates temporal safety in robotic manipulation. Core idea: express reusable safety templates with finite-trace temporal logic and score full rollouts for hazards such as contact, release stability, cross-contamination, and action timing.
- [EduFrameTrap](https://arxiv.org/abs/2605.14604): Benchmarks sycophancy risks in LLM tutors. Core idea: vary student confidence and social or authority pressure across educational subjects to test whether tutors preserve corrective feedback instead of agreeing with misconceptions.
- [MCPTox](https://doi.org/10.1609/aaai.v40i42.40895): Evaluates tool poisoning on real-world MCP servers. Core idea: turn malicious tool descriptions and server-side behavior into a benchmark protocol so MCP agents can be tested for whether they select, trust, and execute poisoned tools.
## 2.9.3 Agent Harness


- [ST-WebAgentBench](https://arxiv.org/abs/2410.06703) ([open-source code](https://github.com/segev-shlomov/ST-WebAgentBench)): A safety and trustworthiness evaluation harness for web agents; its value lies in organizing web environments, task states, and safety constraints into a reproducible browser-agent testing protocol.
- [RTBAS](https://arxiv.org/abs/2502.08966): An information-flow-control defense harness for tool-based LLM agents. Core idea: automatically execute tool calls only when integrity and confidentiality are preserved, reserving user confirmation for cases where the safeguards cannot certify safety.
- [AISafetyLab](https://arxiv.org/abs/2502.16776): a unified AI-safety evaluation and improvement toolkit. Core idea: package representative attack, defense, and evaluation methods behind a common interface so safety experiments can be reproduced and extended systematically.
- [MAD-MAX](https://arxiv.org/abs/2503.06253): an automated red-teaming harness for modular and diverse malicious attack mixtures. Core idea: compose varied attack strategies so LLM safety testing covers broader adversarial behaviors than single-template jailbreaks.
- [SafePlan](https://arxiv.org/abs/2503.06892): A safety-aware robotic task-planning harness for LLM agents. Core idea: combine formal logic with chain-of-thought planning so unsafe plans can be constrained before execution.
- [IsolateGPT](https://doi.org/10.14722/ndss.2025.241131): An execution-isolation architecture for LLM-based systems. Core idea: separate untrusted LLM-driven components from privileged execution so prompt-injection or tool-output compromise cannot directly reach sensitive state or actions.
- [Safety Guardrails for LLM-Enabled Robots](https://arxiv.org/abs/2503.07885): Provides RoboGuard, an external guardrail harness for LLM-enabled robots. Core idea: ground safety rules in the robot environment and use temporal-logic control synthesis to resolve unsafe plans while preserving safe task execution.
- [Prompt Flow Integrity](https://arxiv.org/abs/2503.15547): A security harness for preventing privilege escalation in LLM agents. Core idea: combine agent isolation, secure handling of untrusted tool data, and privilege guardrails so prompt flow cannot silently expand an agent's authority.
- [Encrypted Prompt](https://arxiv.org/abs/2503.23250): A permission-checking harness for LLM applications. Core idea: bind current permissions into an encrypted prompt and verify generated API or tool actions before execution so unauthorized actions can be blocked outside the model's free-form response.

- [RepV](https://arxiv.org/abs/2510.26935): A neurosymbolic plan-verification harness for safety-critical agents. - [SafeAgents](https://arxiv.org/abs/2511.10949): A security assessment harness for multi-agent systems under adversarial prompting. Core idea: vary planning, context-sharing, and fallback designs to expose where multi-agent communication creates new rejection and compromise failures.
- [Reflection-Driven Control](https://arxiv.org/abs/2512.21354): A control harness for trustworthy code agents. Core idea: use reflection-driven oversight around coding-agent actions so execution, patching, and verification can be steered toward safer behavior.
- [PROTEA](https://arxiv.org/abs/2601.07186): Secures robot task planning and execution. Core idea: wrap robot-agent planning with safety checks so unsafe plans can be detected or corrected before physical execution.
- [AgenTRIM](https://arxiv.org/abs/2601.12449): A tool-risk mitigation harness for agentic AI. - [INFA-Guard](https://arxiv.org/abs/2601.14667): Provides an infection-aware defense for LLM-based multi-agent systems. Core idea: localize attackers and infected agents in the communication topology, then replace or rehabilitate compromised agents to contain malicious propagation.

- [Optimizing Agent Planning for Security and Autonomy](https://arxiv.org/abs/2602.11416): A security-aware planning harness for agents under indirect prompt-injection defenses. - [AgentSentry](https://arxiv.org/abs/2602.22724): An inference-time defense harness for indirect prompt injection in tool-augmented agents.
