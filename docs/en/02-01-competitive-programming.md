# 2.1 Competitive Programming

> Parent section: 2. Basic Agents


## 2.1.1 Leaderboard

- [LiveCodeBench Leaderboard](https://livecodebench.github.io/leaderboard.html): A continuously updated public code-generation leaderboard, suitable as an anti-contamination entry point for comparing coding models and agents.
- [CodeElo Leaderboard](https://codeelo-bench.github.io/): Converts competitive-programming correctness into Elo-style rankings, useful for observing relative model strength under the same contest-problem protocol.
- [ALE-Bench Leaderboard](https://sakanaai.github.io/ALE-Bench-Leaderboard/): A long-horizon scoring leaderboard for AtCoder heuristic and algorithm-engineering tasks, directly exposing whether agents can iteratively optimize rather than submit once.
- [LiveCodeBench Pro Leaderboard](https://livecodebenchpro.com/): A high-difficulty contest-problem extension of LiveCodeBench, suitable for tracking the upper bound of frontier coding agents under stronger judging pressure.
- [Humanity's Last Code Exam Leaderboard](https://humanity-s-last-code-exam.github.io/website/): An extremely hard competitive-programming leaderboard centered on ICPC World Finals and IOI problems, useful for observing remaining headroom.
- [Holistic Agent Leaderboard](https://hal.cs.princeton.edu/): A cross-task agent leaderboard that includes programming subtasks such as USACO and provides a unified agent/harness submission process, useful for comparing competitive-programming results alongside other agent tasks.

## 2.1.2 Bench

- [HumanEval](https://arxiv.org/abs/2107.03374): What it evaluates: executable unit-test correctness for Python function-level code generation. Core idea: use docstring prompts and hidden tests to measure functional correctness, forming a baseline reference for later code-generation evaluation and pass@k reporting. ([code](https://github.com/openai/human-eval))
- [CodeContests](https://github.com/google-deepmind/code_contests): What it evaluates: a competitive-programming dataset and execution-evaluation substrate, including statements, tests, and correct/incorrect solutions. Core idea: convert contest problems into a runnable judging format for training and evaluating harder algorithmic code generation.
- [LiveCodeBench v6](https://arxiv.org/abs/2403.07974): What it evaluates: continuously updated, contamination-aware code evaluation, including problems from contest platforms. Core idea: provide a more credible comparison baseline for "coding ability" through dynamic sampling and contamination control. ([code](https://github.com/LiveCodeBench/LiveCodeBench))
- [USACO](https://arxiv.org/abs/2404.10952): What it evaluates: competitive-programming reasoning and implementation on USA Computing Olympiad problems. Core idea: organize problems, samples, hidden tests, and tiered difficulty into executable evaluation to observe long-horizon bottlenecks in Olympiad-style programming. ([code](https://github.com/princeton-nlp/USACO))
- [CodeElo](https://arxiv.org/abs/2501.01257): What it evaluates: Elo-style comparable scoring for contest-level code generation. Core idea: use an evaluation protocol closer to "matches/ranking" so model performance yields more stable relative-ordering signals.
- [ProBench](https://arxiv.org/abs/2502.20868): What it evaluates: ICPC-inspired competitive-programming evaluation with problems from Codeforces, Luogu, and Nowcoder in the second half of 2024. Core idea: use real online-judge submissions, difficulty tiers, and algorithm tags to analyze chain-of-thought, error types, and reasoning depth.
- [ICPC-Eval](https://arxiv.org/abs/2506.04894) ([code](https://github.com/RUCAIBox/Slow_Thinking_with_LLMs)): What it evaluates: reasoning and local repair capability on ICPC-style contest problems. Core idea: use a problem set closer to real ICPC scenarios and Refine@K evaluation to include multi-round correction in the metrics.
- [ALE-Bench](https://arxiv.org/abs/2506.09050): What it evaluates: long-horizon, score-based algorithm-engineering tasks from AtCoder Heuristic Contest. Core idea: move from "AC/WA" to continuous scoring and iterative optimization, evaluating long-term trial-and-error ability on routing, scheduling, and other problems without exact optima. ([code](https://github.com/SakanaAI/ALE-Bench), [dataset](https://huggingface.co/datasets/SakanaAI/ALE-Bench))
- [LiveCodeBench Pro](https://arxiv.org/abs/2506.11928): What it evaluates: harder contamination-controlled code-generation evaluation centered on competitive algorithm problems. Core idea: increase problem difficulty and judging strength on top of LiveCodeBench's dynamic problem-source design to distinguish the upper bounds of frontier coding agents. ([code](https://github.com/GavinZhengOI/LiveCodeBench-Pro))
- [Humanity's Last Code Exam (HLCE)](https://arxiv.org/abs/2506.12713): What it evaluates: executable evaluation on an extremely hard set of ICPC World Finals and IOI problems. Core idea: widen upper-bound gaps through harder problem sources and strict execution evaluation. ([code](https://github.com/Humanity-s-Last-Code-Exam/HLCE))
- [OJBench](https://arxiv.org/abs/2506.16395) ([code](https://github.com/He-Ren/OJBench)): What it evaluates: code reasoning and execution correctness on NOI/ICPC-style contest problems. Core idea: turn contest-level hard problems into a stable benchmark with 232 bilingual Chinese-English problems.
- [COMPASS](https://arxiv.org/abs/2508.13757): What it evaluates: correctness, efficiency, and code quality for contest-problem code generation. Core idea: evaluate time efficiency and implementation quality alongside AC in one protocol.
- [AetherCode](https://arxiv.org/abs/2508.16402): What it evaluates: ability to win top programming competitions, closer to IOI/ICPC-level hard problems and judging. Core idea: treat whether the test set can distinguish correct from incorrect solutions as a core evaluation object, avoiding false positives from weak tests.
- [LiveOIBench](https://arxiv.org/abs/2510.09595): What it evaluates: long reasoning, algorithm design, and code execution on Olympiad-in-Informatics-style tasks. Core idea: complement ICPC/Codeforces-only distributions with OI hard-problem distributions, adding stronger pressure from construction, data structures, and algorithmic reasoning.
- [Holistic Agent Leaderboard (HAL)](https://arxiv.org/abs/2510.11977) ([code](https://github.com/princeton-pli/hal-harness)): What it evaluates: unified cross-benchmark agent evaluation, including competitive-programming subtasks such as USACO. Core idea: use a unified CLI, cost/time records, and leaderboard submission process so competitive-programming results can be compared with SWE, web, and real-world tasks.
- [Idea First, Code Later](https://arxiv.org/abs/2601.11332): What it evaluates: the separability of "algorithm idea" and "code implementation" in ICPC-style problems. Core idea: introduce 83 problems with gold editorials and complete tests, evaluating natural-language editorials first and code implementation later so AC does not hide the bottleneck.
- [VeriContest](https://arxiv.org/abs/2605.08553): What it evaluates: verifiable code generation on LeetCode and Codeforces problems. Core idea: combine natural-language statements, expert-verified formal specifications, AC Rust code, Verus proofs, and positive/negative tests to evaluate specification, code, proof, and end-to-end verified synthesis separately.

## 2.1.3 Agent Harness

- [USACO Episodic + Semantic](https://arxiv.org/abs/2404.10952) ([code](https://github.com/princeton-nlp/USACO)): A USACO competitive-programming agent configuration; core idea: use episodic memory and semantic retrieval to reuse similar-problem experience for multi-step Olympiad-style problem solving.
- [MapCoder](https://arxiv.org/abs/2405.11403) ([code](https://github.com/Md-Ashraful-Pramanik/MapCoder)): A multi-agent framework for contest code generation; core idea: explicitly decompose retrieval, planning, coding, and debugging into collaborative roles, approximating the human competitive-programming loop.
- [CodeContests+](https://arxiv.org/abs/2506.05817): A high-quality test-case generation and validation process for contest problems. Core idea: explicitly agentize test-set construction to improve evaluation discriminativeness and robustness.
- [ALE-Agent](https://arxiv.org/abs/2506.09050) ([code](https://github.com/SakanaAI/ALE-Bench)): A long-horizon algorithm-engineering agent for AtCoder heuristic contests; core idea: connect code edits, trial-run feedback, visual analysis, and score optimization into a continuous iterative loop.
- [Holistic Agent Leaderboard](https://arxiv.org/abs/2510.11977) ([code](https://github.com/princeton-pli/hal-harness)): A cross-benchmark agent evaluation harness; core idea: unify tasks such as USACO, SWE-bench, and SWE-Lancer under a submit-ready, reproducible experimental protocol.
- [AutoCode](https://arxiv.org/abs/2510.12803): An automated problem-setting, solving, and verification process for competitive programming; core idea: organize LLMs into problem setter, solver, and verifier roles to continuously generate executable new problems in the style of LiveCodeBench Pro.
- [SwiftSolve](https://arxiv.org/abs/2510.22626): A multi-agent contest-solving framework; core idea: divide planning, coding, profiling, and complexity analysis to target TLE/MLE failures.
- [Agentic Verifier](https://arxiv.org/abs/2602.04254): An execution-based verifier and reranker for contest code; core idea: actively search for counterexample inputs that distinguish candidate programs through multi-round execution interaction instead of only random test sampling.
- [CodeHacker](https://arxiv.org/abs/2602.20213): An adversarial test-generation agent for contest submissions; core idea: simulate the hacking mechanism of contest platforms and combine stress testing, anti-hash tactics, and logic-directed construction to expose wrong solutions that weak tests would pass.

## 2.1.4 Skill

- [mcp-code-execution](https://skills.sh/athola/claude-night-market/mcp-code-execution) is suitable for turning contest solving into an executable loop of "write code -> run samples/random tests -> fix".
- [e2b-sandbox](https://skills.sh/smithery.ai/e2b-sandbox) is suitable for quickly replaying samples and running regression checks in an isolated execution environment.
- [pytest](https://skills.sh/bobmatnyc/claude-mpm-skills/pytest) is better suited for turning "differential testing / constructed tests" into reusable automated checks.
- [pytest-advanced](https://skills.sh/laurigates/claude-plugins/pytest-advanced) is suitable for more complex test organization and regression-check orchestration.
- [leetcode-teacher](https://skills.sh/jamesrochabrun/skills/leetcode-teacher) can serve as a procedural skill for "algorithm-problem explanation / solution-pattern injection"; it is more about solution teaching and idea organization than judging runtime.
