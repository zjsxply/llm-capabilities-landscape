# 2.9.4 Agent Harness

- [AgentDojo](https://arxiv.org/abs/2406.13352) ([open-source code](https://github.com/ethz-spylab/agentdojo); [project page](https://agentdojo.spylab.ai/)): A tool-agent security evaluation harness for indirect prompt injection, with reproducible suites, task utilities, attacks, and defense comparisons.
- [ST-WebAgentBench](https://arxiv.org/abs/2410.06703) ([open-source code](https://github.com/segev-shlomov/ST-WebAgentBench)): A safety and trustworthiness evaluation harness for web agents; its value lies in organizing web environments, task states, and safety constraints into a reproducible browser-agent testing protocol.
- [Agentable / Agent Defect Detection](https://arxiv.org/abs/2412.18371): A static-analysis harness and dataset suite for defects in LLM-based autonomous agents. Core idea: define agent-specific defect types from real developer reports, then detect workflow and tool-invocation failures over real and synthetic agent codebases.
- [RTBAS](https://arxiv.org/abs/2502.08966): An information-flow-control defense harness for tool-based LLM agents. Core idea: automatically execute tool calls only when integrity and confidentiality are preserved, reserving user confirmation for cases where the safeguards cannot certify safety.
- [AISafetyLab](https://arxiv.org/abs/2502.16776): a unified AI-safety evaluation and improvement toolkit. Core idea: package representative attack, defense, and evaluation methods behind a common interface so safety experiments can be reproduced and extended systematically.
- [MAD-MAX](https://arxiv.org/abs/2503.06253): an automated red-teaming harness for modular and diverse malicious attack mixtures. Core idea: compose varied attack strategies so LLM safety testing covers broader adversarial behaviors than single-template jailbreaks.
- [SafePlan](https://arxiv.org/abs/2503.06892): A safety-aware robotic task-planning harness for LLM agents. Core idea: combine formal logic with chain-of-thought planning so unsafe plans can be constrained before execution.
- [Safety Guardrails for LLM-Enabled Robots](https://arxiv.org/abs/2503.07885): Provides RoboGuard, an external guardrail harness for LLM-enabled robots. Core idea: ground safety rules in the robot environment and use temporal-logic control synthesis to resolve unsafe plans while preserving safe task execution.
- [Prompt Flow Integrity](https://arxiv.org/abs/2503.15547): A security harness for preventing privilege escalation in LLM agents. Core idea: combine agent isolation, secure handling of untrusted tool data, and privilege guardrails so prompt flow cannot silently expand an agent's authority.
- [AgentSpec](https://arxiv.org/abs/2503.18666) ([open-source code](https://github.com/haoyuwang99/AgentSpec)): A policy-enforcement harness for agents that specifies allowed actions and checks runtime behavior against safety contracts.
- [CaMeL](https://arxiv.org/abs/2503.18813) ([open-source code](https://github.com/google-research/camel-prompt-injection)): A prompt-injection defense harness that separates control flow from data flow so untrusted tool outputs can inform work without acquiring execution authority.
- [Encrypted Prompt](https://arxiv.org/abs/2503.23250): A permission-checking harness for LLM applications. Core idea: bind current permissions into an encrypted prompt and verify generated API or tool actions before execution so unauthorized actions can be blocked outside the model's free-form response.
- [MCP Safety Audit / MCPSafetyScanner](https://arxiv.org/abs/2504.03767): An agentic security-audit harness for MCP servers. Core idea: use multiple agents to inspect an arbitrary MCP server, synthesize adversarial samples from its tools and resources, search for related vulnerabilities and remediations, and produce an actionable security report.
- [Progent](https://arxiv.org/abs/2504.11703): A privilege-control harness for AI agents. Core idea: represent allowed tool calls as symbolic policies over tool names and arguments, update them during execution, and use deterministic checks plus SMT reasoning to enforce least privilege.
- [Tool Squatting Zero Trust Registry](https://arxiv.org/abs/2504.19951): A registry-based security harness for multi-agent tool discovery. Core idea: use admin-controlled registration, access policies, trust scoring, vulnerability metadata, and just-in-time credentials to reduce deceptive or hijacked tool use.
- [ACE](https://arxiv.org/abs/2504.20984): A security architecture for LLM-integrated app systems. Core idea: split abstract planning from concrete execution so tool and app calls can be constrained, checked, and isolated before malicious apps corrupt plans, availability, or private data.
- [SAGA](https://arxiv.org/abs/2504.21034): A security architecture for governing agentic systems. Core idea: register agents with a provider, enforce user-defined access control and delegation policies, and keep user oversight over agent lifecycle and communications.
- [Maris](https://arxiv.org/abs/2505.04799): A formally verifiable privacy-policy enforcement harness for multi-agent collaboration systems. Core idea: make access and information-flow policies checkable during collaboration so multi-agent systems can coordinate without silently violating privacy constraints.
- [A2A protocol safety refinements](https://arxiv.org/abs/2505.12490): A protocol-level safety design for multi-agent communication. Core idea: add consent orchestration, scoped ephemeral tokens, and direct user-to-service data channels so A2A-style agent collaboration can reduce credential exposure and unintended data sharing.
- [PandaGuard](https://arxiv.org/abs/2505.13862): A modular jailbreak-safety evaluation harness that models attackers, defenders, and judges as configurable components. Its value is reproducible comparison of attack and defense strategies across LLM interfaces and interaction modes.
- [MCIP](https://arxiv.org/abs/2505.14590): A protocol-level MCP safety harness. Core idea: refine MCP with contextual-integrity mechanisms, define a taxonomy of unsafe MCP behaviors, and provide benchmark and training data for identifying safety risks in MCP interactions.
- [RedTeamCUA](https://arxiv.org/abs/2505.21936) (project page: [RedTeamCUA](https://osu-nlp-group.github.io/RedTeamCUA)): A hybrid Web-OS red-team harness; its value lies in combining web prompt injection, desktop actions, and real OS state to test CUA.
- [SentinelAgent](https://arxiv.org/abs/2505.24201): A graph-based anomaly-detection harness for multi-agent systems. Core idea: model agent interactions as graphs so suspicious coordination, role misuse, or abnormal communication patterns can be detected during multi-agent execution rather than only after final outputs.
- [CoP](https://arxiv.org/abs/2506.00781): An agentic red-teaming harness based on composition of principles. Core idea: organize adversarial prompt discovery around composable attack or safety principles so red-team search is more systematic than one-off jailbreak prompting.
- [IsolateGPT](https://doi.org/10.14722/ndss.2025.241131): An execution-isolation architecture for LLM-based systems. Core idea: separate untrusted LLM-driven components from privileged execution so prompt-injection or tool-output compromise cannot directly reach sensitive state or actions.
- [ETDI](https://arxiv.org/abs/2506.01333): A security-extension harness for MCP tool definitions. Core idea: bind tools to cryptographic identity, immutable versioned descriptors, OAuth-enhanced permissions, and policy-engine checks so tool squatting and rug-pull attacks cannot silently expand agent authority.
- [OpenAgentSafety](https://arxiv.org/abs/2507.06134): A comprehensive agent-safety evaluation framework; its value lies in using real tools and multi-user settings to reproduce deployment-like risks rather than only static prompt classification.
- [AgentArmor](https://arxiv.org/abs/2508.01249): A program-analysis defense harness for prompt injection in agents. Core idea: inspect agent runtime traces and enforce safety properties over actions and observations so injected instructions can be caught before they drive unsafe execution.
- [MI9](https://arxiv.org/abs/2508.03858): A runtime governance harness for agentic AI. Core idea: monitor and govern agent behavior during execution rather than only through pre-deployment checks, targeting emergent risks from planning, tool use, and autonomous action.
- [Cowpox](https://arxiv.org/abs/2508.09230): A robustness harness for VLM-based multi-agent systems. Core idea: distribute synthetic immunity signals across agents so compromise of one VLM agent is less likely to spread through collaboration and the system can recover integrity under adversarial infection.
- [AutoMalTool](https://arxiv.org/abs/2509.21011): An automated red-teaming harness for MCP-enabled LLM agents. Core idea: generate malicious MCP tools to systematically test tool-poisoning attacks instead of relying on manual proof-of-concept payloads.
- [Policy-as-Prompt](https://arxiv.org/abs/2509.23994): A governance-to-guardrail harness for AI agents. Core idea: compile design artifacts and policy controls into source-linked policy trees and runtime classifiers so least privilege, data minimization, provenance, and human review can be enforced during agent operation.
- [FuncPoison](https://arxiv.org/abs/2509.24408): An attack framework for poisoning shared function libraries in LLM-driven multi-agent autonomous-driving systems. Core idea: test whether text-based tool selection lets poisoned functions hijack perception, reasoning, or planning across cooperating driving agents.
- [A2AS](https://arxiv.org/abs/2510.13825): A runtime security layer for AI agents and LLM-powered applications. Core idea: enforce behavior certificates, authenticated prompts, security boundaries, context-integrity checks, and in-context defenses without retraining the base model.
- [Breaking and Fixing Defenses Against Control-Flow Hijacking in Multi-Agent Systems](https://arxiv.org/abs/2510.17276): A multi-agent safety harness for analyzing control-flow hijacking and defenses. Core idea: test whether coordination protocols can be redirected by adversarial messages and how external defenses can constrain compromised agent interactions.
- [AegisMCP](https://arxiv.org/abs/2510.19462): A protocol-level intrusion-detection harness for MCP toolchains on edge devices. Core idea: represent agents, MCP servers, tools, devices, remotes, and sessions as a streaming heterogeneous temporal graph, then detect escalation, tool-chain exfiltration, malicious server registration, and persistence patterns online.
- [CourtGuard](https://arxiv.org/abs/2510.19844) ([open-source code](https://github.com/isaacwu2000/CourtGuard)): A local multi-agent prompt-injection classifier. Core idea: use prosecutor, defense, and judge agents to classify prompts, exposing the precision and false-positive tradeoff of adversarial and benign prompt reasoning.
- [Jailbreak Mimicry](https://arxiv.org/abs/2510.22085): an automated red-teaming harness for narrative-based jailbreak discovery. Core idea: search for narrative attack patterns that elicit unsafe model behavior, expanding safety testing beyond fixed jailbreak templates.
- [QueryIPI](https://arxiv.org/abs/2510.23675): A red-teaming harness for query-agnostic indirect prompt injection against coding agents. Core idea: optimize payloads against invariant prompt context such as system prompts and tool descriptions so attacks can trigger across arbitrary user queries, exposing IDE/coding-agent risks missed by query-specific tests.
- [The Oversight Game](https://arxiv.org/abs/2510.26752): A control-layer harness for balancing agent autonomy and human oversight. Core idea: model ask-versus-act and trust-versus-oversee choices as a two-player Markov game, encouraging agents to defer under risk while preserving autonomy when actions are safe.
- [RepV](https://arxiv.org/abs/2510.26935): A neurosymbolic plan-verification harness for safety-critical agents. Core idea: learn safety-separable latent plan representations and connect them to symbolic constraints so natural-language rules can be checked more scalably than hand-written temporal logic alone.
- [AGENTVIGIL](https://aclanthology.org/2025.findings-emnlp.1258/): An automatic black-box red-teaming harness for indirect prompt injection against LLM agents. Core idea: iteratively generate and test attacks through agent interactions so prompt-injection robustness is measured at the agent behavior level rather than by static prompt filters.
- [SafeAgents](https://arxiv.org/abs/2511.10949): A security assessment harness for multi-agent systems under adversarial prompting. Core idea: vary planning, context-sharing, and fallback designs to expose where multi-agent communication creates new rejection and compromise failures.
- [IntentGuard](https://arxiv.org/abs/2512.00966): A defense harness for indirect prompt injection in agent inputs. Core idea: infer which prompt segments the model intends to treat as actionable instructions, then flag or neutralize overlaps with untrusted data rather than relying only on malicious-text detection.
- [AGENTSAFE Governance Framework](https://arxiv.org/abs/2512.03180): A governance and assurance framework for LLM-based agentic systems. Core idea: connect risk identification, design controls, runtime controls, and audit controls so agent safety management is operationalized beyond static taxonomies.
- [Cognitive Control Architecture (CCA)](https://arxiv.org/abs/2512.06716): A lifecycle supervision harness for aligned AI agents. Core idea: supervise the full task-execution pipeline against indirect prompt injection so malicious objectives can be detected across perception, reasoning, tool invocation, and feedback stages rather than by isolated filters.
- [MemoryGraft](https://arxiv.org/abs/2512.16962): An attack harness for poisoned experience retrieval in long-term-memory agents. Core idea: implant malicious successful experiences so later tasks retrieve and imitate compromised patterns, exposing a persistent memory-layer prompt-injection risk.
- [XAgen](https://arxiv.org/abs/2512.17896): An explainability and repair harness for multi-agent workflows. Core idea: combine log visualization, human feedback capture, and LLM-as-judge error detection so users can locate, attribute, and correct workflow failures.
- [Reflection-Driven Control](https://arxiv.org/abs/2512.21354): A control harness for trustworthy code agents. Core idea: use reflection-driven oversight around coding-agent actions so execution, patching, and verification can be steered toward safer behavior.
- [MCP-SandboxScan](https://arxiv.org/abs/2601.01241): A sandboxed runtime-analysis harness for MCP tools. Core idea: execute untrusted tools inside WebAssembly/WASI, trace external-input-to-output exposures, and generate auditable reports for prompt-injection and secret-leakage risks that static scans can miss.
- [BackdoorAgent](https://arxiv.org/abs/2601.04566): A modular framework for backdoor attacks on LLM-based agents. Core idea: model trigger injection and propagation across planning, memory, tool-use, and workflow stages so agent-centric backdoor risks can be compared systematically.
- [PROTEA](https://arxiv.org/abs/2601.07186): Secures robot task planning and execution. Core idea: wrap robot-agent planning with safety checks so unsafe plans can be detected or corrected before physical execution.
- [Agent Contracts](https://arxiv.org/abs/2601.08815): A formal framework for resource-bounded autonomous AI systems. Core idea: specify inputs, outputs, temporal limits, resource budgets, success criteria, and delegation rules so multi-agent execution can be governed by explicit contracts.
- [AgenTRIM](https://arxiv.org/abs/2601.12449): A tool-risk mitigation harness for agentic AI. Core idea: reconstruct and verify an agent's tool interface, then enforce least-privilege, status-aware tool access at runtime so unnecessary permissions and missing required tools are both visible safety failures.
- [MirrorGuard](https://arxiv.org/abs/2601.12822): A plug-and-play computer-use agent defense; its value lies in simulation-to-real reasoning correction so suspicious GUI actions can be repaired rather than simply blocked.
- LlamaFirewall ([open-source code](https://github.com/meta-llama/PurpleLlama/tree/main/LlamaFirewall)): A production-oriented agent firewall from Meta's PurpleLlama suite, relevant as an engineering baseline for prompt-injection, insecure tool-use, and policy-enforcement layers around agents.
- [NeuroFilter](https://arxiv.org/abs/2601.14660): A privacy guardrail harness for conversational LLM agents. Core idea: map contextual-integrity violations to linear directions in model activations, enabling low-latency detection of privacy-violating intent across multi-turn conversations.
- [INFA-Guard](https://arxiv.org/abs/2601.14667): Provides an infection-aware defense for LLM-based multi-agent systems. Core idea: localize attackers and infected agents in the communication topology, then replace or rehabilitate compromised agents to contain malicious propagation.
- [MaMa](https://arxiv.org/abs/2602.04431): A game-theoretic safe-agent-system design harness; its value lies in modeling compromised subagents through a Stackelberg security game between a meta-agent and meta-adversary.
- [MemPot](https://arxiv.org/abs/2602.07517): A memory-safety defense harness for LLM agents. Core idea: inject optimized honeypot memories that are attractive to extraction attackers but inconspicuous to benign users, then use sequential testing to detect memory-stealing behavior with fewer samples.
- [MUZZLE](https://arxiv.org/abs/2602.09222): An adaptive red-teaming harness for web agents under indirect prompt injection; its value lies in searching for attack surfaces and payloads beyond fixed templates.
- [Optimizing Agent Planning for Security and Autonomy](https://arxiv.org/abs/2602.11416): A security-aware planning harness for agents under indirect prompt-injection defenses. Core idea: measure how much consequential action can remain autonomous under confidentiality and integrity policies, then plan with both task progress and policy compliance in view.
- [ToolShield](https://arxiv.org/abs/2602.13379): A training-free defense framework paired with MT-AgentRisk; its value lies in mediating risky tool trajectories in multi-turn agent settings.
- [Formal Policy Enforcement for Real-World Agentic Systems](https://arxiv.org/abs/2602.16708): A formal policy-enforcement harness for deployed agentic systems. Core idea: move policy compliance out of prompt-only instructions and into runtime checks over agent state, tool calls, and environmental observations so safety constraints can be enforced with clearer guarantees.
- [Right to History / PunkGo](https://arxiv.org/abs/2602.20214): A verifiable execution kernel for personal AI agents. Core idea: combine tamper-evident Merkle audit logs, capability isolation, and independent verification so users can retain a complete record of actions performed by agents on their hardware.
- [AgentSentry](https://arxiv.org/abs/2602.22724): An inference-time defense harness for indirect prompt injection in tool-augmented agents. Core idea: localize temporal causal takeover points at tool-return boundaries and purify context so agents can continue useful work without carrying attacker-induced deviations.
- [Learning When to Act or Refuse](https://arxiv.org/abs/2603.03205): a safety guard for agentic reasoning models using multi-step tools. Core idea: decide when an agent should proceed or refuse during tool-mediated workflows so unsafe actions can be blocked before execution.
- [MCP-in-SoS](https://arxiv.org/abs/2603.10194): A risk-assessment framework for open-source MCP servers. Core idea: combine static code analysis, CWE and CAPEC mappings, and multi-metric likelihood-impact scoring so MCP tool infrastructure can be audited before agents rely on it.
- [AttriGuard](https://arxiv.org/abs/2603.10749): A runtime defense harness for indirect prompt injection in tool-using agents. Core idea: use action-level causal attribution and counterfactual shadow replay to check whether proposed tool calls are supported by user intent or causally driven by untrusted observations.
- [ChainFuzzer](https://arxiv.org/abs/2603.12614): A greybox fuzzing harness for workflow-level multi-tool vulnerabilities in LLM agents. Core idea: search source-to-sink tool chains, use trace-guided prompt solving, and produce auditable evidence for cross-tool exploits that single-tool tests miss.
- [Cryptographic Binding for AI Agent Tool Use](https://arxiv.org/abs/2603.14332): A governance harness for dynamic agent capabilities. Core idea: bind tool capabilities, execution claims, and interaction provenance with cryptographic and reproducibility checks so agent tool use can be audited beyond prompt-level declarations.
- [SafeAudit](https://arxiv.org/abs/2603.18245): A meta-audit framework for tool-call safety benchmarks; its value lies in systematically enumerating workflow patterns and finding residual unsafe interactions after benchmark passing.
- [PlanTwin](https://arxiv.org/abs/2603.18377): A privacy-preserving planning harness for cloud-assisted LLM agents. Core idea: expose a schema-constrained planning twin of the local environment instead of raw files, credentials, or metadata, so cloud planners can coordinate tools without directly observing private state.
- [Open Agent Passport](https://arxiv.org/abs/2603.20953): A deterministic pre-action authorization layer for autonomous agents. Core idea: intercept tool calls before execution, check them against declarative policy, and emit signed audit records so authorization is enforced at the action boundary rather than after the fact.
- [Agent Audit](https://arxiv.org/abs/2603.22853): A static security-analysis system for LLM agent applications. Core idea: inspect Python agent code, deployment artifacts, credentials, and MCP privilege settings together so developers can catch tool-code and configuration risks before deployment.
- [AgentRFC](https://arxiv.org/abs/2603.23801): A protocol-security conformance harness for agent protocols such as MCP, A2A, ANP, and ACP. Core idea: formalize agent-protocol layers and security principles, then check normative clauses and implementation conformance rather than relying on ad hoc protocol reviews.
- [ClawKeeper](https://arxiv.org/abs/2603.24414): A layered safety framework for OpenClaw agents. Core idea: combine skill-level protection, plugin-level controls, and watcher-based runtime monitoring so broad agent privileges can be constrained across the execution lifecycle.
- [ATBench](https://arxiv.org/abs/2604.02022): A trajectory-level safety diagnostic harness; its value lies in locating risk in specific stages of an execution trajectory, making it easier to analyze systematic defects in agent scaffolds.
- [ARM / Causality Laundering](https://arxiv.org/abs/2604.04035): A runtime enforcement layer for denial-feedback leakage in tool-calling agents. Core idea: track causal influence from denied protected actions so agents cannot infer private state from refusals and exfiltrate it through later benign-looking tool calls.
- [Layered Translation for Runtime Guardrails](https://arxiv.org/abs/2604.05229): A governance-to-runtime guardrail harness for agentic AI. Core idea: translate standards-derived objectives into design constraints, runtime mediation, and assurance feedback so multi-step tool-using agents can be controlled during execution rather than only documented before deployment.
- [Pre-Execution Safety Gate and Task Safety Contracts](https://arxiv.org/abs/2604.05427): A safety harness for LLM-controlled robot systems. Core idea: check task-level safety contracts before execution so unsafe plans can be blocked or revised before physical actions occur.
- [JailAgent](https://arxiv.org/abs/2604.05549): A red-teaming harness for reasoning hijacking in LLM agents. Core idea: avoid editing the user prompt and instead manipulate triggers, reasoning trajectories, memory retrieval, and constraints to discover cross-model and cross-scenario agent jailbreaks.
- [MCPSHIELD](https://arxiv.org/abs/2604.05969): A formal security framework for MCP-based AI agents. Core idea: unify MCP threat taxonomy, verification models, and defense mechanisms so protocol, host, server, and tool risks can be analyzed under one security model.
- [ClawLess](https://arxiv.org/abs/2604.06284): A security model for AI agents. Core idea: formalize how agent authority and execution should be constrained so agent systems can be reasoned about before unsafe tool or app actions occur.
- [Anumati](https://arxiv.org/abs/2604.16524): A formal consent model for autonomous agent protocols. Core idea: add versioned policy documents, consent records, and per-action adherence events so agent-to-agent calls can prove not only acceptance of terms but also compliance with them during execution.
- [CapSeal](https://arxiv.org/abs/2604.16762): A capability-sealed secret-mediation harness for secure agent execution. Core idea: replace direct environment-variable or file-based secret access with constrained brokered invocations, schema-checked tool calls, anti-replay binding, and audit trails.
- [CASCADE](https://arxiv.org/abs/2604.17125): A cascaded prompt-injection defense architecture for MCP-based systems. Core idea: combine fast lexical pre-filtering, embedding-based semantic analysis, fallback LLM checks, and output filtering to screen MCP tool-poisoning and prompt-injection attempts.
- [LLM-Guided Safety Agent for Edge Robotics](https://arxiv.org/abs/2604.20193): A safety harness for edge robotics. Core idea: translate natural-language safety regulations into executable predicates and run them inside an ISO-oriented perception-compute-control architecture for low-latency human-robot interaction.
- [Sovereign Agentic Loops](https://arxiv.org/abs/2604.22136): A control-plane architecture for separating agent reasoning from real-system execution. Core idea: require structured intents, policy validation against true system state, identity obfuscation, and evidence-chain auditability before APIs mutate external systems.
- [Ghost in the Agent / NeuroTaint](https://arxiv.org/abs/2604.23374): An information-flow tracking harness for LLM agents. Core idea: redefine taint propagation for probabilistic natural-language reasoning so untrusted tool, API, and memory content can be tracked before it drives unauthorized tool execution.
- [RiskGate](https://arxiv.org/abs/2604.24686): A runtime governance harness for autonomous agents. Core idea: estimate unobserved risk from monitoring, drift, and sequential-pattern signals, then monotonically restrict or gate actions through a fail-secure pipeline before a kill switch becomes necessary.
- [SnapGuard](https://arxiv.org/abs/2604.25562): A lightweight prompt-injection detector for screenshot-based web agents; its value lies in defending visual web-agent pipelines where malicious instructions appear only in rendered page content.
- [FlashRT](https://arxiv.org/abs/2604.28157): A computationally efficient red-teaming harness for prompt injection and knowledge corruption. Core idea: reduce the compute and memory cost of optimization-based attacks so long-context LLM and agent applications can be stress-tested more systematically.
- [Alignment Contracts](https://arxiv.org/abs/2605.00081): A formal policy-enforcement harness for agentic security systems. Core idea: specify scope, allowed and forbidden effects, resource budgets, and disclosure rules over observable traces so offensive capabilities remain constrained to authorized engagements.
- [Autonomous LLM Agent Worms](https://arxiv.org/abs/2605.02812): A security-analysis harness for persistent cross-agent propagation. Core idea: trace file and memory carriers that can re-enter agent context, optimize payloads robust to summaries, and test temporal re-entry defenses for long-running agent ecosystems.
- [MAGE](https://arxiv.org/abs/2605.03228): A shadow-memory defense framework for long-horizon LLM-agent threats. Core idea: maintain a separate safety memory that records risk-relevant context across user, agent, and environment interactions, then uses it to guard later decisions.
- [ClawGuard](https://arxiv.org/abs/2605.06205): An out-of-band detector for LLM-agent workflow hijacking. Core idea: monitor side-channel signals around agent execution so malicious workflow diversion can be detected without relying only on in-band prompt or tool-call inspection.
- [MCP-BiFlow](https://arxiv.org/abs/2605.07836): A bidirectional static-analysis harness for MCP data-flow risks. Core idea: recover MCP entry points, model requester-to-sensitive-operation and source-to-output flows, and analyze complete tool-scoped paths that generic analyzers miss.
- [MATRA](https://arxiv.org/abs/2605.10763): A threat-modeling framework for agentic AI systems. Core idea: map assets, impacts, known LLM-agent threats, and architectural controls into attack trees, using OpenClaw as a worked case for deployment-specific risk analysis.
- [PACT](https://arxiv.org/abs/2605.11039): A provenance-aware runtime monitor for tool-using agents. Core idea: enforce trust at the level of authority-bearing tool arguments so untrusted webpages, emails, or files can inform benign work without silently controlling privileged actions.
- [JAW / Comment and Control](https://arxiv.org/abs/2605.11229): A hijacking framework for LLM-enabled agentic workflows on automation platforms. Core idea: use hybrid program-analysis context to evolve inputs such as issue comments until agents execute unintended actions such as credential exfiltration or command execution.
- [Persona-Conditioned Adversarial Prompting](https://arxiv.org/abs/2605.11730): an automated red-teaming harness for adversarial prompt discovery and mitigation. Core idea: run persona-conditioned parallel searches with strategy metadata so safety testing covers more attacker identities, tactics, and transferable jailbreak patterns.
- [IPI-proxy](https://arxiv.org/abs/2605.11868): An intercepting-proxy red-team harness for web-browsing agents under indirect prompt injection. Core idea: rewrite real HTTP responses from whitelisted domains in flight with a large payload library, so enterprise-style browser agents can be tested without relying on prebuilt adversarial pages.
- [Distributed Governance under Byzantine Adversaries](https://arxiv.org/abs/2605.12364): A protocol-security harness for agentic AI governance. Core idea: analyze how a compromised provider can undermine identity and access-control enforcement, then introduce distributed mitigations for owner policies and malicious-agent resistance.
- [Sleeper Channels / Provenance Gates](https://arxiv.org/abs/2605.13471): A defense harness for persistent prompt injection in always-on autonomous agents. Core idea: track action-instance provenance and require owner attestations so untrusted inputs cannot persist through memory, skills, scheduled jobs, or filesystem patches and fire later under a different surface.
- [MemLineage](https://arxiv.org/abs/2605.14421): A lineage-guided enforcement harness for LLM-agent memory. Core idea: attach cryptographic provenance and derivation lineage to memory entries, then gate sensitive actions when active justifications descend from untrusted external content.
