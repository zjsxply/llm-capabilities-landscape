# 1.2 Scientific Knowledge

> Parent chapter: 1. Basic Capabilities


## 1.2.1 Leaderboard

- [Humanity's Last Exam](https://lastexam.ai/): a public leaderboard for expert-level cross-disciplinary knowledge and reasoning. Its value is using difficult science, math, humanities, and professional questions as a stress test for the upper bound of model knowledge.
- [HLE-Rolling](https://agi.safe.ai/): the dynamic update/submission entry point for Humanity's Last Exam. Its value is reducing contamination, errors, and saturation in the public HLE through continuous revision, new questions, and live submission.
- [PaperBench Results](https://github.com/openai/preparedness/blob/main/project/paperbench/README.md): public results for AI research agents that reproduce papers. Its value is separating rollout, reproduction, and grading, making end-to-end scientific-reproduction capability easier to compare.
- [AstaBench Leaderboard](https://huggingface.co/spaces/allenai/asta-bench-leaderboard): a public leaderboard for a comprehensive scientific-agent suite. Its value is covering research skills such as literature retrieval, code execution, data analysis, and end-to-end scientific discovery.
- [ResearchCodeBench Leaderboard](https://researchcodebench.github.io/leaderboard/index.html): a public leaderboard for implementing research code from recent ML papers. It is suitable as a more code-implementation-oriented reference beyond PaperBench and EXP-Bench.
- [SciVisAgentBench Leaderboard](https://scivisagentbench.github.io/leaderboard.html): a leaderboard for scientific data analysis and visualization agents. Its value is bringing scientific data understanding, analysis decisions, and graphical expression into comparable evaluation.

## 1.2.2 Bench

- [GPQA Diamond](https://arxiv.org/abs/2311.12022) (dataset: [Idavidrein/gpqa](https://huggingface.co/datasets/Idavidrein/gpqa)): evaluates graduate-level scientific QA, in multiple-choice form and with a "Google-proof" emphasis. The core idea is to have experts construct difficult questions and weaken direct retrieval hits, making success depend more on knowledge understanding and reasoning than snippet matching.
- [OlympiadBench](https://arxiv.org/abs/2402.14008): evaluates bilingual multimodal science problems at Olympiad competition level. The core idea is to use difficult math, physics, and related competition problems to stress-test professional reasoning across languages and modalities.
- [MMLU-Pro](https://arxiv.org/abs/2406.01574) (dataset: [TIGER-Lab/MMLU-Pro](https://huggingface.co/datasets/TIGER-Lab/MMLU-Pro)): evaluates harder and more robust multidisciplinary professional knowledge. The core idea is to raise question difficulty and reduce inflated scores from shortcuts or contamination, making "memorizing answers" less effective.
- [DiscoveryBench](https://arxiv.org/abs/2407.01725) ([open-source code](https://github.com/allenai/discoverybench)): evaluates data-driven scientific discovery. The core idea is to give an agent a research goal and dataset, ask it to perform statistical analysis, semantic reasoning, and discovery generation, and use faceted evaluation to measure conclusion quality.
- [LAB-Bench](https://arxiv.org/abs/2407.10362): evaluates language-model capabilities for biology research. The core idea is to cover practical research tasks such as literature understanding, experimental design, database navigation, and DNA/protein sequence processing, rather than only textbook-style science QA.
- [BLADE](https://arxiv.org/abs/2408.09667) ([open-source code](https://github.com/behavioral-data/BLADE)): evaluates data-analysis scientific agents. The core idea is to require agents to generate defensible data analyses from real research questions and datasets, covering scientific decisions such as variable selection, data transformation, and statistical modeling.
- [ScienceAgentBench](https://arxiv.org/abs/2410.05080) ([open-source code](https://github.com/OSU-NLP-Group/ScienceAgentBench)): evaluates practical agent capabilities in data-driven scientific discovery. The core idea is to extract tasks from peer-reviewed papers and standardize outputs as self-contained Python programs that can be automatically evaluated.
- [KORBench](https://arxiv.org/abs/2410.06526): evaluates reasoning capability as orthogonal as possible to "memorizing knowledge." The core idea is to construct tasks where success depends more on reasoning structure than factual memory, better separating knowledge stock from reasoning mechanisms.
- [RE-Bench](https://arxiv.org/abs/2411.15114): evaluates the research-engineering capability of frontier AI R&D agents. The core idea is to use open-ended machine-learning research environments and compare against records from 8-hour attempts by human experts, measuring agent progress speed and upper bounds in real R&D tasks.
- [Humanity's Last Exam (HLE)](https://arxiv.org/abs/2501.14249) (dataset: [cais/hle](https://huggingface.co/datasets/cais/hle)): evaluates extremely difficult expert-level cross-disciplinary questions. The core idea is to stress-test the upper bound of model knowledge and reasoning with a high-difficulty question set.
- [HLE-Verified](https://arxiv.org/abs/2501.14249) (dataset: [lmms-lab/HLE-Verified](https://huggingface.co/datasets/lmms-lab/HLE-Verified)): evaluates a human-audited verifiable subset. The core idea is to reduce ambiguity and undecidable samples, improving evaluation credibility.
- [UGPhysics](https://arxiv.org/abs/2502.00334) ([open-source code](https://github.com/YangLabHKUST/UGPhysics), [dataset](https://huggingface.co/datasets/UGPhysics/ugphysics)): evaluates undergraduate physics knowledge and reasoning, covering bilingual Chinese-English questions, 13 topics, and multiple answer formats. The core idea is to put formula derivation, concept judgment, and numerical calculation into one physics evaluation protocol.
- [MLGym](https://arxiv.org/abs/2502.14499) ([open-source code](https://github.com/facebookresearch/MLGym)): evaluates open-ended AI research agents. The core idea is to let agents generate ideas, process data, implement methods, train models, and iterate experiments in a Gym-like environment.
- [SuperGPQA](https://arxiv.org/abs/2502.14739) (dataset: [m-a-p/SuperGPQA](https://huggingface.co/datasets/m-a-p/SuperGPQA)): evaluates longer-tail professional QA closer to workplace scenarios. The core idea is to scale "common but long-tail professional questions from real work" into an evaluable question set.
- [Auto-Bench](https://arxiv.org/abs/2502.15224): evaluates the scientific-discovery capability of LLMs/agents. The core idea is to abstract scientific discovery as causal graph discovery and intervention decisions with oracle interaction, letting models iteratively propose hypotheses, take actions, and explain conclusions in natural and social science scenarios.
- [BixBench](https://arxiv.org/abs/2503.00096): evaluates practical LLM-agent capability in computational biology. The core idea is to use more than 50 real biological data-analysis scenarios and nearly 300 open-ended QA items, requiring agents to explore data, perform multi-step analyses, and explain results.
- [PaperBench](https://arxiv.org/abs/2504.01848) ([open-source code](https://github.com/openai/preparedness)): evaluates an AI agent's ability to reproduce AI research papers from scratch. The core idea is to break 20 ICML 2024 Spotlight/Oral papers into 8,316 gradable subtasks covering paper understanding, code implementation, and experiment execution.
- [AI Idea Bench 2025](https://arxiv.org/abs/2504.14191): evaluates AI research idea generation. The core idea is to use papers and their inspired works as comparable material, evaluating idea quality from two dimensions: fit to real follow-up work and judgment using general reference material.
- [PhyBench](https://arxiv.org/abs/2504.16074) (dataset: [Eureka-Lab/PHYBench](https://huggingface.co/datasets/Eureka-Lab/PHYBench)): evaluates physics knowledge and physics reasoning. The core idea is to make the physics domain's demands for concepts, laws, and derivations explicit, avoiding shortcuts based only on surface language patterns.
- [SuperChem (text-only)](https://arxiv.org/abs/2505.05331): evaluates text-based scientific QA/reasoning in chemistry. The core idea is to use domain-specific questions to explicitly measure a model's chemistry knowledge and reasoning chains instead of hiding them within general QA.
- [HealthBench](https://arxiv.org/abs/2505.08775): evaluates medical-related QA and clinical/health knowledge application. The core idea is to stress-test reliability in a high-risk knowledge domain with questions and scoring closer to medical contexts.
- [LLM-SRBench](https://proceedings.mlr.press/v267/shojaee25a.html) ([open-source code](https://github.com/deep-symbolic-mathematics/llm-srbench)): evaluates true generalization by LLMs in scientific symbolic regression and equation discovery. The core idea is to use transformations and synthetic tasks across scientific domains to distinguish "memorizing known formulas" from "discovering interpretable laws from data."
- [SciSafetyBench](https://arxiv.org/abs/2505.23559) ([open-source code](https://github.com/ulab-uiuc/SafeScientist)): evaluates scientific-research agents' safety awareness and tool-use risk. The core idea is to use 240 high-risk research tasks, 30 simulated scientific tools, and 120 tool-risk tasks to check whether agents refuse or avoid dangerous research workflows.
- [EXP-Bench](https://arxiv.org/abs/2505.24785) ([open-source code](https://github.com/Just-Curieous/Curie/tree/main/benchmark/exp_bench)): evaluates AI agents' ability to conduct complete AI research experiments. The core idea is to extract 461 tasks from 51 top AI papers, requiring agents to propose hypotheses, design experiments, implement and execute them, and analyze results from research questions and incomplete code.
- [ResearchCodeBench](https://arxiv.org/abs/2506.02314) ([open-source code](https://github.com/PatrickHua/ResearchCodeBench)): evaluates the ability to implement research code from recent ML papers. The core idea is to use real research-code challenges to check whether models can understand paper methods and complete runnable implementations.
- [SimpleQA Verified](https://arxiv.org/abs/2509.07968): evaluates a model's "parametric factuality" through short-answer, decidable factoid QA. The core idea is to use higher-quality verifiable factoid questions to measure factual memory and hallucination risk without tools.
- [HLE-Rolling](https://agi.safe.ai/) (change log: [centerforaisafety/hle](https://github.com/centerforaisafety/hle/blob/main/hle-rolling-changes.txt)): evaluates a dynamically maintained HLE fork. The core idea is to continuously correct questions, add new samples, and maintain live submission, reducing the risk that a static high-difficulty question set becomes contaminated or saturated.
- [CMT-Benchmark](https://arxiv.org/abs/2510.05228): evaluates research-level reasoning and programmatically gradable physics tasks in condensed matter theory. The core idea is to test whether models can handle frontier physics derivations and computational constraints with expert question types such as non-commutative operators, QMC, and DMRG.
- [AstaBench](https://arxiv.org/abs/2510.21652) ([open-source code](https://github.com/allenai/asta-bench)): evaluates comprehensive scientific-agent capabilities. The core idea is to use 11 scientific benchmarks and standardized tool environments to cover literature retrieval, code execution, data analysis, and scientific-discovery workflows.
- [CGBench](https://openreview.net/forum?id=UEGEHy1IQE) ([open-source code](https://github.com/owencqueen/cgbench), [dataset](https://huggingface.co/datasets/owencqueen/cgbench_data)): evaluates clinical-genetics literature interpretation. The core idea is to approximate the ClinGen expert workflow, asking models to extract experimental results from papers, judge evidence strength, and explain genetic-variant evidence.
- [LPFQA](https://arxiv.org/abs/2511.06346) (dataset: [m-a-p/LPFQA](https://huggingface.co/datasets/m-a-p/LPFQA)): evaluates long-tail QA from professional forum/community contexts. The core idea is to make questions closer to everyday professional communication and emphasize retrieval plus synthesis.
- [Encyclo-K](https://arxiv.org/abs/2512.24867) (dataset: [m-a-p/Encyclo-K](https://huggingface.co/datasets/m-a-p/Encyclo-K)): evaluates "book-level/long-form" professional knowledge mastery. The core idea is to extract composable atomic knowledge points from book material and measure long-term knowledge internalization rather than short-snippet memorization.
- [FrontierScience](https://arxiv.org/abs/2601.21165): evaluates expert-level frontier scientific reasoning, covering Olympiad and Research subsets in physics, chemistry, and biology. The core idea is to have domain experts construct extremely difficult, verifiable questions, stress-testing scientific capability through both research-style knowledge synthesis and difficult competition reasoning.
- [FIRE-Bench](https://arxiv.org/abs/2602.02905) ([open-source code](https://github.com/maitrix-org/FIRE-Bench)): evaluates scientific agents' full-process rediscovery of existing scientific insights. The core idea is to provide only high-level research questions, let agents autonomously ideate, experiment, execute, and summarize, and then measure whether they reconstruct verifiable claims from the paper with claim-level precision/recall/F1.
- [BABE](https://arxiv.org/abs/2602.05857): a science/biology-related evaluation listed in the Seed2.0 report. The core idea is to examine "research-style understanding and reasoning" with more scientific-context materials and questions; the exact construction and task form should follow the paper/report.
- [AIRS-Bench](https://arxiv.org/abs/2602.06855) ([open-source code](https://github.com/facebookresearch/airs-bench)): evaluates end-to-end scientific workflows for frontier AI research agents. The core idea is to put idea generation, experiment analysis, and iterative revision into one task suite.
- [ResearchGym](https://arxiv.org/abs/2602.15112) ([open-source code](https://github.com/Anikethh/ResearchGym)): evaluates long-horizon agents in real AI research tasks. The core idea is to provide problem statements, trimmed codebases, evaluation scripts, and baseline scores, letting agents advance open-ended research goals under a limited budget.
- [SciVisAgentBench](https://arxiv.org/abs/2603.29139) ([open-source code](https://github.com/KuangshiAi/SciVisAgentBench)): evaluates scientific data analysis and visualization agents. The core idea is to cover multiple application domains, data types, and visualization operations, checking whether agents can turn scientific data into reliable graphical expression.
- [LABBench2](https://arxiv.org/abs/2604.09554) ([open-source code](https://github.com/EdisonScientific/labbench2)): evaluates more realistic biology research tasks. The core idea is to expand task scale beyond LAB-Bench and strengthen agent-evaluation interfaces such as file handling, external runners, and tool switches.
- [HealthBench Professional](https://arxiv.org/abs/2604.27470): evaluates large language models on real clinician chats. The core idea is to move medical evaluation from general consumer health questions toward clinician-facing scenarios where safety, nuance, and practical usefulness are harder to capture with ordinary QA.
- HealthBench Consensus (reported in the [GPT-5.5 system card](https://deploymentsafety.openai.com/gpt-5-5/gpt-5-5.pdf)): a HealthBench-family scoring variant used by OpenAI; no standalone public benchmark package has been confirmed. The core idea is to track consensus-style medical safety and usefulness judgments alongside HealthBench and HealthBench Professional.
- [ProtocolQA Open-Ended](https://deploymentsafety.openai.com/gpt-5-5/gpt-5-5.pdf): a GPT-5.5 model-card evaluation that converts FutureHouse ProtocolQA-style wet-lab troubleshooting questions into open-ended short answers; OpenAI's modified set is not publicly released. The core idea is to test whether models can diagnose protocol errors without multiple-choice scaffolding.
- [TroubleshootingBench](https://deploymentsafety.openai.com/gpt-5-5/gpt-5-5.pdf): an OpenAI internal biology troubleshooting benchmark reported in the GPT-5.5 system card and not publicly released. The core idea is to use expert-written wet-lab procedures and tacit, non-public procedural errors to test hands-on troubleshooting knowledge.
- [BioPipelineBench Verified](https://cdn.sanity.io/files/4zrzovbb/website/037f06850df7fbe871e206dad004c3db5fd50340.pdf): an Anthropic model-card evaluation for bioinformatics workflows such as targeted sequence analysis, long-read analysis, metagenome assembly, and chromatin profiling; the verified subset is not publicly released. The core idea is to test whether models can execute realistic computational biology pipelines.
- [BioMysteryBench Verified](https://www.anthropic.com/research/Evaluating-Claude-For-Bioinformatics-With-BioMysteryBench): evaluates difficult bioinformatics puzzles on real data, with Anthropic reporting a verified subset in the Claude Opus 4.7 system card. The core idea is to ask models to interleave computational analysis with biological reasoning and score objective answers rather than a fixed analysis path.
- Structural biology benchmark (reported in the [Claude Opus 4.7 system card](https://cdn.sanity.io/files/4zrzovbb/website/037f06850df7fbe871e206dad004c3db5fd50340.pdf)): an Anthropic internal evaluation that asks models to infer biomolecular function from structural data; not publicly released. The core idea is to test structure-function reasoning beyond text-only biology QA.
- OpenAI internal biology and chemistry risk evaluations (reported in the [GPT-5.5 system card](https://deploymentsafety.openai.com/gpt-5-5/gpt-5-5.pdf)): a closed set including multimodal troubleshooting virology, tacit knowledge and troubleshooting, hard-negative protein binding prediction, DNA sequence design for transcription-factor binding, and protocol troubleshooting. These are not publicly released, but they are important to track because frontier model cards use them to monitor high-risk wet-lab, protein, and sequence-design capability.

## 1.2.3 Agent Harness

- [ReAct](https://arxiv.org/abs/2210.03629) ([open-source code](https://github.com/ysymyth/ReAct)): a general "think-retrieve/act-observe" framework. For long-tail scientific knowledge tasks, it is more like a reusable `retrieve -> integrate evidence -> answer again` workflow skeleton.
- [RARR](https://arxiv.org/abs/2210.08726) ([open-source code](https://github.com/anthonywchen/RARR)): a `retrieve -> revise -> cite` framework, suitable for rewriting knowledge answers into "verifiable conclusions with citations."
- [Chain-of-Verification](https://arxiv.org/abs/2309.11495): proposes a general factuality workflow of "answer first, then decompose verification questions, then revise." No stable public official code repository is currently known.
- [DSPy](https://arxiv.org/abs/2310.03714) ([open-source code](https://github.com/stanfordnlp/dspy)): organizes retrieval, prompts, and scorers into compilable/evaluable programs. It is often used to turn "RAG/evidence organization/answer format" into a tunable harness rather than a one-off prompt.
- [Agent Laboratory](https://arxiv.org/abs/2501.04227) ([open-source code](https://github.com/SamuelSchmidgall/AgentLaboratory)): a multi-stage workflow for research assistants, covering literature retrieval, experiment execution, and report writing.
- [AgentRxiv](https://arxiv.org/abs/2503.18102) ([open-source code](https://github.com/SamuelSchmidgall/AgentLaboratory)): a shared research-memory and collaborative preprint server, allowing research agents to upload, retrieve, and reuse prior results.
- [The AI Scientist-v2](https://arxiv.org/abs/2504.08066) ([open-source code](https://github.com/SakanaAI/AI-Scientist-v2)): an end-to-end automated scientific-research system. The core idea is to use agentic tree search and experiment-management agents to iteratively generate hypotheses, run experiments, analyze results, plot figures, and write papers.
- [SafeScientist](https://arxiv.org/abs/2505.23559) ([open-source code](https://github.com/ulab-uiuc/SafeScientist)): a risk-aware harness for scientific agents. The core idea is to add safety monitoring to task input, collaborative discussion, tool calls, and ethics review, using SciSafetyBench to test refusal and risk-avoidance capability.
- [AlphaEvolve](https://arxiv.org/abs/2506.13131) (open-source code: no stable public official repository currently known): an evolutionary coding agent for scientific and algorithmic discovery. The core idea is to let LLMs directly modify programs and use feedback from one or more automatic evaluators for population-style search and iterative optimization.

## 1.2.4 Skill

- [openalex-database](https://github.com/davila7/claude-code-templates/tree/main/cli-tool/components/skills/scientific/openalex-database) is suitable for academic knowledge, paper-author graphs, and topic tracking.
- [citation-management](https://github.com/davila7/claude-code-templates/tree/main/cli-tool/components/skills/scientific/citation-management) is suitable for citation extraction, BibTeX management, and literature verification.
- [fact-check](https://github.com/openclaw/skills/tree/main/skills/webguhui/fact-check) is suitable for turning professional knowledge QA into a workflow that compares multiple sources and then gives evidence-backed conclusions.
- [clarity-gate](https://github.com/openclaw/skills/tree/main/skills/frmoretto/clarity-gate) is more like a "verifiable-claim checker" before knowledge output, reducing the risk of writing speculation as fact.
- [nemo-evaluator-sdk](https://skills.sh/zechenzhangagi/ai-research-skills/nemo-evaluator-sdk) leans toward evaluator integration and experiment reproduction, and is suitable for running evaluations such as GPQA, HealthBench, and SimpleQA with reproducible results.
