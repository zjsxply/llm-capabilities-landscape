# 1.1 Multilingual

> Parent chapter: 1. Basic Capabilities


## 1.1.1 Leaderboard

- [MTEB Leaderboard](https://huggingface.co/spaces/mteb/leaderboard): a public leaderboard for multilingual text embedding and retrieval capability. Its value is providing a reusable evaluation entry point for embedding/RAG prerequisites, which can connect to multilingual RAG and retrieval tasks such as MIRAGE-Bench and AfriMTEB.

## 1.1.2 Bench

- [XNLI](https://arxiv.org/abs/1809.05053): evaluates cross-lingual natural language inference (NLI). The core idea is to extend inference questions (entailment/contradiction/neutral) to multilingual settings and measure cross-lingual semantic alignment and reasoning consistency.
- [TyDi QA](https://arxiv.org/abs/2003.05002): evaluates multilingual question answering, with more emphasis on the authenticity and linguistic diversity of "native-language questions." The core idea is to cover typologically more diverse languages and measure retrieval/understanding robustness under a QA protocol.
- [FLORES-200](https://arxiv.org/abs/2207.04672) ([open-source code](https://github.com/facebookresearch/flores)): evaluates large-scale multilingual machine translation and cross-lingual generation. The core idea is to use broad language coverage and standardized references to measure multilingual generation quality and cross-lingual transfer.
- [MMMLU](https://huggingface.co/datasets/openai/MMMLU): evaluates multiple-choice general and subject knowledge in multilingual settings. The core idea is to transfer comparable knowledge questions into multilingual inputs and use a unified multiple-choice protocol to compare knowledge retention and understanding robustness across languages.
- [Linguini](https://arxiv.org/abs/2409.12126) ([open-source code](https://github.com/facebookresearch/linguini), [dataset](https://huggingface.co/datasets/facebook/linguini)): evaluates language-agnostic linguistic reasoning. The core idea is to start from International Linguistics Olympiad-style problems and ask models to infer morphology, syntax, and semantic rules from context without knowing the target language, filling a gap where multilingual evaluations rely too heavily on knowledge of already-seen languages.
- [MIRAGE-Bench](https://arxiv.org/abs/2410.13716) ([open-source code](https://github.com/vectara/mirage-bench)): evaluates multilingual RAG answer generation and judge efficiency. The core idea is to combine heuristic features, LLM pairwise judges, and surrogate judges on human questions in 18 languages to reduce the cost of multilingual RAG arena evaluation.
- [MILU](https://arxiv.org/abs/2411.02538): evaluates multitask language understanding for Indic languages. The core idea is to cover 10 Indic languages plus English with culturally grounded subject questions, making it a targeted complement to broad translated MMLU variants.
- [INCLUDE](https://arxiv.org/abs/2411.19799): evaluates multilingual language understanding with regional knowledge. The core idea is to draw questions from regional academic and professional examinations across 44 languages, reducing the bias toward translated English knowledge.
- [GMMLU / Global MMLU](https://arxiv.org/abs/2412.03304): evaluates MMLU-style knowledge across 42 languages. The core idea is to expose both linguistic and cultural-resource gaps by comparing high-, mid-, and low-resource language performance under a comparable subject-knowledge protocol.
- [MMTEB](https://arxiv.org/abs/2502.13595) ([open-source code](https://github.com/embeddings-benchmark/mteb)): evaluates large-scale multilingual text embeddings. The core idea is to compare embedding retrieval, classification, clustering, and semantic matching under one framework across more than 250 languages and more than 500 quality-controlled tasks.
- [MMLU-ProX](https://arxiv.org/abs/2503.10497) (dataset: [li-lab/MMLU-ProX](https://huggingface.co/datasets/li-lab/MMLU-ProX)): evaluates harder cross-lingual subject and professional knowledge, as a cross-lingual extension in the style of MMLU-Pro. The core idea is to fill the "multilingual plus professional knowledge" dimension with harder professional questions that emphasize robustness.
- [MultiLoKo](https://arxiv.org/abs/2504.10356) ([open-source code](https://github.com/facebookresearch/MultiLoKo)): evaluates local knowledge and cross-lingual knowledge transfer in 31 languages. The core idea is to provide language-local questions, human-translated questions, and machine-translated questions together, distinguishing "knowing the fact" from "being able to express/retrieve the fact reliably in the target language."
- [X-WebAgentBench](https://arxiv.org/abs/2505.15372) ([open-source code](https://github.com/WPENGxs/X-WebAgentBench)): evaluates planning and interaction capability for multilingual interactive web agents. The core idea is to extend agentic web tasks to multilingual environments and check whether cross-lingual alignment methods can really support global agent services.
- [Trojsten Benchmark](https://doi.org/10.18653/v1/2025.emnlp-main.1779): What it evaluates: Slovak-language open-response STEM competition problem solving across mathematics, physics, and programming. Core idea: use native low-resource-language problems and rubric-based grading to expose reasoning failures that translated or English-centric STEM benchmarks can miss.
- [MAPS](https://aclanthology.org/2026.findings-eacl.42/) (dataset: [Fujitsu-FRE/MAPS](https://huggingface.co/datasets/Fujitsu-FRE/MAPS)): evaluates multilingual agents for performance and safety. The core idea is to translate tasks such as GAIA, MATH, SWE-bench, and Agent Security Benchmark into multiple languages and observe capability degradation and safety regressions.
- [MultiNRC](https://arxiv.org/abs/2507.17476): evaluates native multilingual reasoning and culture-related commonsense. The core idea is to use native-language questions rather than English-translated questions, directly exposing lexical, cultural, and language-game differences.
- [AfriMTEB](https://arxiv.org/abs/2510.23896): evaluates text embedding and retrieval/classification representation capability for African languages. The core idea is to extend MMTEB to 59 languages, 14 task types, and 38 datasets, addressing the long-standing underestimation of African languages in multilingual evaluation.
- [Global PIQA](https://arxiv.org/abs/2510.24081) (dataset: [mrlbenchmarks/global-piqa-nonparallel](https://huggingface.co/datasets/mrlbenchmarks/global-piqa-nonparallel)): evaluates cross-lingual physical commonsense and everyday plausibility judgments in the style of PIQA. The core idea is to use contrastive option questions with commonsense-decidable answers to measure how language changes affect commonsense reasoning stability.
- [DiscoX (Disco-X)](https://arxiv.org/abs/2511.10984): evaluates discourse-level translation and cross-sentence consistency for expert domains. The core idea is to use longer discourse and terminology constraints to expose multilingual difficulties such as correct within-sentence translation but cross-sentence inconsistency or coreference mismatch.
- [AncientBench](https://arxiv.org/abs/2512.17756): What it evaluates: understanding of excavated and transmitted ancient Chinese corpora. Core idea: organize ancient-character comprehension into glyph, pronunciation, meaning, and contextual tasks, covering historical Chinese materials beyond modern-language benchmarks.
- [GreekMMLU](https://arxiv.org/abs/2602.05150): evaluates native Greek multitask language understanding. The core idea is to use Greek questions from academic, professional, and government exams instead of translated English questions, testing whether models truly cover the target language's educational and cultural context.
- [Macaron](https://arxiv.org/abs/2602.10732): evaluates multilingual and multicultural reasoning. The core idea is to use human-written templates to disentangle reasoning types from cultural factors, comparing differences between English questions and local-language questions across 20 country/cultural contexts and 20 languages/dialects.


## 1.1.3 Agent Harness

- [ReAct](https://arxiv.org/abs/2210.03629) ([open-source code](https://github.com/ysymyth/ReAct)): a general `think -> act -> observe` framework. In multilingual settings, it is more like a controllable cross-lingual workflow skeleton that can make `language detection -> translation/back-translation -> retrieval/verification -> output` explicit instead of hiding cross-lingual processing in one answer.
- [Reflexion](https://arxiv.org/abs/2303.11366) ([open-source code](https://github.com/noahshinn024/reflexion)): iteratively improves answers through failure reflection and memory writing. In multilingual tasks, it can be used to repair errors across turns, such as mistranslated terms, missed constraints, and entity mismatches.
- [DSPy](https://arxiv.org/abs/2310.03714) ([open-source code](https://github.com/stanfordnlp/dspy)): organizes `translation -> retrieval -> answer -> verification` as a programmable program. In multilingual tasks, it is suitable for solidifying cross-lingual retrieval and evidence-consistency constraints.
- [EfficientXLang](https://arxiv.org/abs/2507.00246) ([open-source code](https://github.com/microsoft/EfficientXLang)): a cross-lingual test-time reasoning harness. The core idea is to route the same reasoning task to a more token-efficient language, then check whether accuracy and language consistency are preserved; it is suitable for multilingual reasoning cost/quality tradeoff experiments.

## 1.1.4 Skill

- [translation-expertise](https://skills.sh/shino369/claude-code-personal-workspace/translation-expertise) is suitable for cross-lingual prompt rewriting, terminology alignment, and high-fidelity translation.
- [sentence-transformers](https://github.com/davila7/claude-code-templates/tree/main/cli-tool/components/skills/ai-research/rag-sentence-transformers) explicitly supports multilingual embeddings and is suitable for cross-lingual retrieval and cross-lingual RAG.
