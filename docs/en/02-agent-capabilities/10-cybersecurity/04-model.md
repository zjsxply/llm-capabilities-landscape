# 2.10.4 Model

- [Automatically Identifying CVE Affected Versions With Patches and Developer Logs](https://doi.org/10.1109/tdsc.2023.3264567): Matches vulnerability patches and developer-log evidence to CVE version ranges so affected-version identification can be learned from maintenance traces rather than only advisory text.
- [Universal Vulnerabilities in Large Language Models: Backdoor Attacks for In-context Learning](https://arxiv.org/abs/2401.05949): Shows that poisoned in-context demonstrations can implant backdoor behavior across LLMs without parameter updates, exposing a training-free model vulnerability relevant to secure deployment.
- [Large Language Model as Synthesizer: Fusing Diverse Inputs for Better Automatic Vulnerability Repair](https://arxiv.org/abs/2401.15459): Uses an LLM to synthesize patch candidates from heterogeneous vulnerability evidence such as reports, code context, and repair hints for automatic vulnerability repair.
- [Large Language Model for Vulnerability Detection: Emerging Results and Future Directions](https://arxiv.org/abs/2401.15468): Studies how LLM-based vulnerability detectors perform across code-analysis settings and identifies model adaptation and evaluation gaps for secure-code reasoning.
- [Finetuning Large Language Models for Vulnerability Detection](https://arxiv.org/abs/2401.17010): Fine-tunes general LLMs on vulnerability-detection data to measure whether supervised adaptation improves code-security classification over prompting alone.
- [Instruction Tuning for Secure Code Generation](https://arxiv.org/abs/2402.09497): Builds secure-code instruction data and tunes code LLMs to prefer functionally correct outputs that avoid common security weaknesses.
- [On the Vulnerability of LLM/VLM-Controlled Robotics](https://arxiv.org/abs/2402.10340): Analyzes how LLM and VLM policy models can be induced into unsafe robotic actions, connecting model-level multimodal reasoning failures to cyber-physical attack surfaces.
- [DeepCode AI Fix: Fixing Security Vulnerabilities with Large Language Models](https://arxiv.org/abs/2402.13291): Describes an LLM-based repair model that generates source-code fixes for detected security vulnerabilities and evaluates patch quality on real bug patterns.
- [Chain-of-Thought Prompting of Large Language Models for Discovering and Fixing Software Vulnerabilities](https://arxiv.org/abs/2402.17230): Tests whether chain-of-thought prompting improves LLM vulnerability discovery and patch generation by forcing explicit security reasoning steps.
- [Unveiling Typographic Deceptions: Insights of the Typographic Vulnerability in Large Vision-Language Model](https://arxiv.org/abs/2402.19150): Examines typographic adversarial inputs for large vision-language models, showing how text rendered inside images can steer model outputs in security-relevant ways.
- [LLM4Decompile: Decompiling Binary Code with Large Language Models](https://arxiv.org/abs/2403.05286): Trains and evaluates LLMs for binary-to-source decompilation, providing model-side reverse-engineering capability for malware and vulnerability analysis.
- [ACFix: Guiding LLMs With Mined Common RBAC Practices for Context-Aware Repair of Access Control Vulnerabilities in Smart Contracts](https://arxiv.org/abs/2403.06838): Guides LLM smart-contract repair with mined role-based-access-control practices so patches preserve context-specific authorization logic.
- [Robustness, Security, Privacy, Explainability, Efficiency, and Usability of Large Language Models for Code](https://arxiv.org/abs/2403.07506): Organizes code-LLM risks and model-improvement directions across security, privacy, robustness, explainability, efficiency, and developer usability.
- [Efficiently Detecting Reentrancy Vulnerabilities in Complex Smart Contracts](https://arxiv.org/abs/2403.11254): Improves smart-contract reentrancy detection by modeling complex contract interactions rather than relying only on shallow syntactic indicators.
- [Leveraging Large Language Models to Detect NPM Malicious Packages](https://arxiv.org/abs/2403.12196): Applies LLM-based package analysis to NPM metadata and code so malicious packages can be flagged from semantic and behavioral cues.
- [A Study of Vulnerability Repair in JavaScript Programs with Large Language Models](https://arxiv.org/abs/2403.13193): Evaluates LLM-generated repairs for JavaScript vulnerabilities, separating patch correctness, security improvement, and language-specific failure modes.
- [Combining Fine-Tuning and LLM-Based Agents for Intuitive Smart Contract Auditing with Justifications](https://arxiv.org/abs/2403.16073): Couples a fine-tuned smart-contract auditor with LLM agents that explain suspected vulnerabilities, so the workflow produces both findings and human-readable audit justifications.
- [FoC: Figure Out the Cryptographic Functions in Stripped Binaries with LLMs](https://arxiv.org/abs/2403.18403): Uses LLMs to identify cryptographic functions in stripped binaries, supporting reverse engineering when symbols and source code are unavailable.
- [Vulnerability Detection with Code Language Models: How Far are We?](https://arxiv.org/abs/2403.18624): Benchmarks code language models for vulnerability detection and highlights where pretrained code representations still fail on realistic security bugs.
- [Dialectical Alignment: Resolving the Tension of 3H and Security Threats of LLMs](https://arxiv.org/abs/2404.00486): Proposes an alignment strategy that balances helpfulness, honesty, and harmlessness against security-threat behaviors rather than optimizing safety refusal alone.
- [Enchanting Program Specification Synthesis by Large Language Models using Static Analysis and Program Verification](https://arxiv.org/abs/2404.00762): Combines LLM specification synthesis with static analysis and verification feedback to generate checkable program properties for security-critical code.
- [An Investigation into Misuse of Java Security APIs by Large Language Models](https://arxiv.org/abs/2404.03823): Measures how often LLMs misuse Java security APIs, exposing model failure modes around cryptography and secure-library usage.
- [LLMs for Cyber Security: New Opportunities](https://arxiv.org/abs/2404.11338): Surveys model-side opportunities for applying LLMs to cyber tasks such as vulnerability analysis, threat intelligence, and defensive automation.
- [Vul-LMGNNs: Fusing language models and online-distilled graph neural networks for code vulnerability detection](https://arxiv.org/abs/2404.14719): Fuses language-model code representations with online-distilled graph neural networks to capture both token semantics and program-structure signals for vulnerability detection.
- [When Fuzzing Meets LLMs: Challenges and Opportunities](https://arxiv.org/abs/2404.16297): Reviews how LLM-generated inputs, harnesses, and guidance can augment fuzzing while noting model limitations for coverage and bug validation.
- [Double Backdoored: Converting Code Large Language Model Backdoors to Traditional Malware via Adversarial Instruction Tuning Attacks](https://arxiv.org/abs/2404.18567): Demonstrates that adversarial instruction tuning can turn code-LLM backdoors into generated malware behaviors, linking model poisoning to executable attack payloads.
- [LLM Security Guard for Code](https://arxiv.org/abs/2405.01103): Uses an LLM guard model to inspect generated code for security flaws before the code is accepted by downstream developer workflows.
- [Codexity: Secure AI-assisted Code Generation](https://arxiv.org/abs/2405.03927): Studies secure AI-assisted code generation and mitigation strategies for reducing vulnerability introduction during code-model use.
- [SPVR: syntax-to-prompt vulnerability repair based on large language models](https://arxiv.org/abs/2405.04994): Converts syntactic vulnerability cues into targeted prompts that steer LLMs toward repairing vulnerable code.
- [DoLLM: How Large Language Models Understanding Network Flow Data to Detect Carpet Bombing DDoS](https://arxiv.org/abs/2405.07638): Adapts LLMs to network-flow descriptions so carpet-bombing DDoS behavior can be recognized from traffic patterns.
- [Uncovering Logit Suppression Vulnerabilities in LLM Safety Alignment](https://arxiv.org/abs/2405.13068): Identifies logit-suppression failures in safety-aligned LLMs, showing how output-probability controls can create exploitable refusal bypasses.
- [LLM-Assisted Static Analysis for Detecting Security Vulnerabilities](https://arxiv.org/abs/2405.17238): Integrates LLM reasoning with static-analysis warnings to prioritize and explain likely security vulnerabilities in source code.
- [Code Repair with LLMs gives an Exploration-Exploitation Tradeoff](https://arxiv.org/abs/2405.17503): Frames LLM code repair as a search problem where diverse candidate exploration must be balanced against exploiting high-confidence patch patterns.
- [BadRAG: Identifying Vulnerabilities in Retrieval Augmented Generation of Large Language Models](https://arxiv.org/abs/2406.00083): Characterizes vulnerabilities in retrieval-augmented generation, including how malicious or poorly ranked context can distort LLM responses.
- [Generalization-Enhanced Code Vulnerability Detection via Multi-Task Instruction Fine-Tuning](https://arxiv.org/abs/2406.03718): Uses multi-task instruction fine-tuning to improve code-LLM generalization across vulnerability types and detection datasets.
- [Security Vulnerability Detection with Multitask Self-Instructed Fine-Tuning of Large Language Models](https://arxiv.org/abs/2406.05892): Generates self-instructed security tasks and fine-tunes LLMs jointly across them for vulnerability detection.
- [M2CVD: Multi-Model Collaboration for Code Vulnerability Detection](https://arxiv.org/abs/2406.05940): Combines multiple model predictions for code vulnerability detection so complementary model strengths can reduce false positives and missed bugs.
- [LLAMAFUZZ: Large Language Model Enhanced Greybox Fuzzing](https://arxiv.org/abs/2406.07714): Uses LLM-generated guidance to improve greybox fuzzing input mutation and path exploration for vulnerability discovery.
- [Vul-RAG: Enhancing LLM-based Vulnerability Detection via Knowledge-level RAG](https://arxiv.org/abs/2406.11147): Adds vulnerability knowledge retrieval to LLM detection so model judgments can reference CWE-style concepts and known flaw patterns.
- [Assessing the Effectiveness of LLMs in Android Application Vulnerability Analysis](https://arxiv.org/abs/2406.18894): Evaluates LLMs on Android vulnerability analysis tasks, identifying where mobile-specific APIs and lifecycle behavior challenge code models.
- [Revisiting the Performance of Deep Learning-Based Vulnerability Detection on Realistic Datasets](https://arxiv.org/abs/2407.03093): Reassesses deep vulnerability detectors on more realistic datasets to expose overestimation from sanitized or duplicate-heavy benchmarks.
- [Identifying Smart Contract Security Issues in Code Snippets from Stack Overflow](https://arxiv.org/abs/2407.13271): Applies security models to Stack Overflow smart-contract snippets to detect vulnerable patterns in reused community code.
- [Beyond Static Pattern Matching? Rethinking Automatic Cryptographic API Misuse Detection in the Era of LLMs](https://arxiv.org/abs/2407.16576): Compares LLM-based cryptographic API misuse detection with traditional pattern matching to test whether semantic reasoning reduces brittle rules.
- [Automated Software Vulnerability Static Code Analysis Using Generative Pre-Trained Transformer Models](https://arxiv.org/abs/2408.00197): Uses generative pretrained transformers for static vulnerability analysis, targeting source-code weaknesses that require semantic context.
- [MCGMark: An Encodable and Robust Online Watermark for LLM-Generated Malicious Code](https://arxiv.org/abs/2408.01354): Designs an online watermark for LLM-generated malicious code so harmful generated programs can be traced despite code transformations.
- [From Generalist to Specialist: Exploring CWE-Specific Vulnerability Detection](https://arxiv.org/abs/2408.02329): Specializes vulnerability detectors by CWE category to test whether narrower security labels improve detection over general-purpose models.
- [Black-Box Adversarial Attacks on LLM-Based Code Completion](https://arxiv.org/abs/2408.02509): Develops black-box attacks that manipulate LLM code completion toward vulnerable outputs without access to model internals.
- [VulScribeR: Exploring RAG-based Vulnerability Augmentation with LLMs](https://arxiv.org/abs/2408.04125): Uses retrieval-augmented generation to expand vulnerability descriptions and supporting context for improving downstream vulnerability analysis.
- [Towards Explainable Network Intrusion Detection using Large Language Models](https://arxiv.org/abs/2408.04342): Applies LLMs to network intrusion detection with natural-language explanations for why traffic is classified as malicious.
- [A Jailbroken GenAI Model Can Cause Substantial Harm: GenAI-powered Applications are Vulnerable to PromptWares](https://arxiv.org/abs/2408.05061): Shows how jailbroken generative models can be used to create promptware attacks against GenAI-powered applications.
- [A RAG-Based Question-Answering Solution for Cyber-Attack Investigation and Attribution](https://arxiv.org/abs/2408.06272): Builds a retrieval-augmented question-answering model for cyberattack investigation and attribution over incident evidence.
- [DeepREST: Automated Test Case Generation for REST APIs Exploiting Deep Reinforcement Learning](https://arxiv.org/abs/2408.08594): Uses deep reinforcement learning to generate REST API test cases that exercise security-relevant behaviors beyond hand-written tests.
- [A Disguised Wolf Is More Harmful Than a Toothless Tiger: Adaptive Malicious Code Injection Backdoor Attack Leveraging User Behavior as Triggers](https://arxiv.org/abs/2408.10334): Models adaptive code-generation backdoors as a game between attacker, model distributor, and user, showing that malicious code can be injected selectively based on inferred user skill.
- [ANVIL: Anomaly-based Vulnerability Identification without Labelled Training Data](https://arxiv.org/abs/2408.16028): Recasts line-level vulnerability detection as masked-code anomaly scoring, combining reconstruction mismatch, cross-entropy, confidence, and structure signals without labeled vulnerable-code training data.
- [Outside the Comfort Zone: Analysing LLM Capabilities in Software Vulnerability Detection](https://arxiv.org/abs/2408.16400): Compares six vulnerability-specialized open models with six general LLMs, then fine-tunes three general models to expose benchmark-label noise and narrow-domain overfitting in source-code vulnerability detection.
- [Advancing Cyber Incident Timeline Analysis Through Rule Based AI and Large Language Models](https://arxiv.org/abs/2409.02572): Introduces GenDFIR, which preprocesses incident artifacts into a structured knowledge base and uses a Llama 3.1 8B RAG agent to reconstruct forensic timelines from synthetic DFIR data.
- [PromSec: Prompt Optimization for Secure Generation of Functional Source Code with Large Language Models (LLMs)](https://arxiv.org/abs/2409.12699): Couples a generative-adversarial graph neural network that clears vulnerabilities with an LLM prompt-optimization loop, producing secure functional Python and Java code with fewer LLM queries.
- [Boosting Cybersecurity Vulnerability Scanning based on LLM-supported Static Application Security Testing](https://arxiv.org/abs/2409.15735): Proposes LSAST, combining locally hosted LLM analysis, retrieval, and SAST scanner outputs so static vulnerability scanning can use current vulnerability knowledge without exposing private code.
- [APILOT: Navigating Large Language Models to Generate Secure Code by Sidestepping Outdated API Pitfalls](https://arxiv.org/abs/2409.16526): Maintains a quickly updatable dataset of outdated APIs and augments code generation with version-aware guidance, reducing obsolete API recommendations across seven LLMs.
- [On the Vulnerability of Applying Retrieval-Augmented Generation within Knowledge-Intensive Application Domains](https://arxiv.org/abs/2409.17275): Studies universal poisoning of RAG retrievers across corpus, query, and target-information settings, then proposes a detector for poisoned documents that preserve high query similarity.
- [Comparing Unidirectional, Bidirectional, and Word2vec Models for Discovering Vulnerabilities in Compiled Lifted Code](https://arxiv.org/abs/2409.17513): Trains GPT-2 embeddings over LLVM lifted functions and feeds them to LSTMs, finding unidirectional embeddings outperform BERT, RoBERTa, and Word2vec for compiled-code vulnerability classification.
- [StagedVulBERT: Multigranular Vulnerability Detection With a Novel Pretrained Code Model](https://arxiv.org/abs/2410.05766): Adds CodeBERT-HLS, a hierarchical token-and-statement encoder used in a coarse-to-fine detector for both function-level and statement-level vulnerability localization.
- [CodeCipher: Learning to Obfuscate Source Code Against LLMs](https://arxiv.org/abs/2410.05797): Learns a token-confusion mapping by transforming an LLM embedding matrix, obfuscating source-code privacy while preserving code completion, summarization, and translation behavior.
- [Hallucinating AI Hijacking Attack: Large Language Models and Malicious Code Recommenders](https://arxiv.org/abs/2410.06462): Shows that coding contexts can make LLMs recommend hallucinated or attacker-controlled APIs and package endpoints, creating a domain-squatting route from copied code to malicious infrastructure.
- [LLM-SmartAudit: Advanced Smart Contract Vulnerability Detection](https://arxiv.org/abs/2410.09381): Uses specialized conversational LLM agents to audit smart contracts, with labeled and real-world datasets for detecting logic vulnerabilities missed by traditional tools.
- [FTSmartAudit: A Knowledge Distillation-Enhanced Framework for Automated Smart Contract Auditing Using Fine-Tuned LLMs](https://arxiv.org/abs/2410.13918): Uses distilled and fine-tuned LLMs for automated smart-contract auditing, organizing contract evidence into vulnerability findings rather than a generic chat response.
- [From Solitary Directives to Interactive Encouragement! LLM Secure Code Generation by Natural Language Prompting](https://arxiv.org/abs/2410.14321): Introduces SecCode, an interactive encouragement-prompting loop that generates code, detects and fixes vulnerabilities, and cross-checks repairs using only natural-language prompts.
- [The Best Defense is a Good Offense: Countering LLM-Powered Cyberattacks](https://arxiv.org/abs/2410.15396): Defends against LLM-powered cyber agents by exploiting their trust in inputs, biases, memory limits, and tunnel vision, then tests black-box defenses on prompt scenarios and custom CTF machines.
- [Insights and Current Gaps in Open-Source LLM Vulnerability Scanners: A Comparative Analysis](https://arxiv.org/abs/2410.16527): Compares Garak, Giskard, PyRIT, and CyberSecEval as open-source LLM red-teaming scanners and identifies reliability gaps in attack-success detection.
- [ProveRAG: Provenance-Driven Vulnerability Analysis With Automated Retrieval-Augmented LLMs](https://arxiv.org/abs/2410.17406): Retrieves NVD and CWE evidence for vulnerability analysis and adds self-critique so LLM outputs include verifiable exploitation and mitigation rationales.
- [CTINexus: Automatic Cyber Threat Intelligence Knowledge Graph Construction Using Large Language Models](https://arxiv.org/abs/2410.21060): Uses optimized in-context learning, demonstration retrieval, hierarchical entity alignment, and long-distance relation prediction to build cyber-threat knowledge graphs from 150 real CTI reports.
- [SQL Injection Jailbreak: a structural disaster of large language models](https://arxiv.org/abs/2411.01565): Attacks the external prompt-construction structure of LLMs with SQL-injection-style payloads, then evaluates Self-Reminder-Key as a simple adaptive defense.
- [Fixing Security Vulnerabilities with AI in OSS-Fuzz](https://arxiv.org/abs/2411.03346): Customizes an AutoCodeRover-style LLM agent for OSS-Fuzz patching by using exploit-input test execution to locate fix-relevant code and judge patch correctness dynamically.
- [Enhancing Security Control Production With Generative AI](https://arxiv.org/abs/2411.04284): Uses in-context learning and retrieval-augmented prompting to generate Gherkin security-control code for AWS cloud services, reducing control authoring from days to minutes.
- [ChatHTTPFuzz: large language model-assisted IoT HTTP fuzzing](https://arxiv.org/abs/2411.11929): Applies LLM assistance to IoT HTTP fuzzing, using generated protocol-aware requests to exercise web-facing device handlers for vulnerability discovery.
- [ProSec: Fortifying Code LLMs with Proactive Security Alignment](https://arxiv.org/abs/2411.12882): Synthesizes CWE-derived vulnerability-inducing coding scenarios and fixes, then uses preference learning to align code LLMs toward secure coding without losing utility.
- [Evaluating Large Language Models' Capability to Launch Fully Automated Spear Phishing Campaigns: Validated on Human Subjects](https://arxiv.org/abs/2412.00586): Measures whether LLMs can automate end-to-end spear-phishing campaigns and validates the resulting campaign effectiveness with human subjects.
- [Beyond Text-Visual Attention: Exploiting Visual Cues for Effective Token Pruning in VLMs](https://arxiv.org/abs/2412.01818): Primarily an off-axis VLM efficiency paper; its relevance here is limited to analyzing visual-token pruning under adversarial or security-sensitive multimodal inputs.
- [AI-Based Attacker Models for Enhancing Multi-Stage Cyberattack Simulations in Smart Grids Using Co-Simulation Environments](https://arxiv.org/abs/2412.03979): Builds AI attacker models inside smart-grid co-simulation environments so multi-stage cyberattacks can be generated and tested against power-system behavior.
- [Buster: Incorporating Backdoor Attacks into Text Encoder to Mitigate NSFW Content Generation](https://arxiv.org/abs/2412.07249): Off-axis for cyber operations; injects semantic backdoors into text-to-image text encoders so NSFW prompts are redirected toward benign targets with low inference overhead.
- [Ontology-Aware RAG for Improved Question-Answering in Cybersecurity Education](https://arxiv.org/abs/2412.14191): Adds cybersecurity-domain ontologies to RAG question answering so educational answers can retrieve and structure security concepts more consistently.
- [Combining GPT and Code-Based Similarity Checking for Effective Smart Contract Vulnerability Detection](https://arxiv.org/abs/2412.18225): Combines GPT analysis with code-similarity checks to flag smart-contract vulnerabilities, using similarity evidence to constrain LLM security judgments.
- [On the Validity of Traditional Vulnerability Scoring Systems for Adversarial Attacks Against LLMs](https://arxiv.org/abs/2412.20087): Tests whether CVSS-style vulnerability metrics meaningfully score adversarial attacks on LLMs, identifying metric factors that may need adjustment for model-specific attack surfaces.
- [Enhancing vulnerability detection efficiency: An exploration of light-weight LLMs with hybrid code features](https://doi.org/10.1016/j.jisa.2024.103925): Studies lightweight LLM vulnerability detection with hybrid code features, targeting cheaper secure-code screening rather than full-size model inference.

- [Behavior Speaks Louder: Rethinking Malware Analysis Beyond Family Classification](https://doi.org/10.1109/trustcom63139.2024.00048): Uses LLM-assisted Android behavior labels and API-to-behavior feedback to move malware analysis from inconsistent family names toward attack-chain behavior reports.
