# 1.3.3 Bench

- [COLLIE](https://arxiv.org/abs/2307.08689): evaluates constrained text generation and complex instruction following. The core idea is to make constraints such as format, inclusion/exclusion, length, and set constraints into composable, decidable diagnostic task families.
- [FollowBench](https://arxiv.org/abs/2310.20410): evaluates multi-level, fine-grained constraint following. The core idea is to split complex user instructions into constraints of different difficulties and types, locating whether models fail at the overall task, local constraints, or detailed execution.
- [IFEval](https://arxiv.org/abs/2311.07911) (dataset: [google/IFEval](https://huggingface.co/datasets/google/IFEval); core instruction-following task in [Open LLM Leaderboard](https://huggingface.co/spaces/open-llm-leaderboard/open_llm_leaderboard)): evaluates instruction following for format, constraints, prohibited items, and related rules. The core idea is to use a decidable rule set to automatically evaluate "whether the output follows instructions", making it a direct reference for Inverse IFEval.
- [InFoBench](https://arxiv.org/abs/2401.03601): evaluates decomposed requirement following for complex instructions. The core idea is to split 500 multi-constraint instructions into 2,250 decidable sub-requirements and measure how well models satisfy each requirement with the DRFR metric.
- [LiveBench Instruction Following](https://arxiv.org/abs/2406.19314) ([open-source code](https://github.com/livebench/livebench)): evaluates the instruction-following category in a dynamically updated leaderboard. The core idea is to reduce contamination with continuously updated, automatically scored data and place instruction following within broader comprehensive capability comparison.
- [MultiChallenge](https://arxiv.org/abs/2501.17399): evaluates instruction following and consistency in more realistic multi-turn dialogue. The core idea is to treat "accumulated multi-turn constraints and persistent roles/rules" as the main difficulty rather than single-turn instruction execution.
- [M-IFEval](https://arxiv.org/abs/2502.04688) ([open-source code](https://github.com/lightblue-tech/M-IFEval)): evaluates multilingual verifiable instruction following. The core idea is to extend IFEval-style rules to French, Japanese, and Spanish and check whether constraint checkers and model behavior remain stable across languages.
- [CodeIF](https://arxiv.org/abs/2502.19166) ([open-source code](https://github.com/lin-rany/codeIF)): evaluates instruction following in code-generation tasks. The core idea is to cover function synthesis, bug debugging, algorithm refactoring, code explanation, and related scenarios, checking whether models can satisfy both the task goal and constraint details while generating code.
- [XIFBench](https://arxiv.org/abs/2503.07539) ([open-source code](https://github.com/zhenyuli801/XIFBench)): evaluates multilingual instruction following. The core idea is to set content, style, situational, format, and numeric constraints in six languages, and compare constraint satisfaction across high- and low-resource languages using requirement-level semantic anchors.
- [DeR2](https://arxiv.org/abs/2503.14443): mainly a context-learning/long-context evaluation, but it can also reflect "omission/drift" when complex constraints are executed in long context. The core idea is to stress-test whether constraints are continuously executed in long-context tasks.
- [MathIF](https://arxiv.org/abs/2505.14810) ([open-source code](https://github.com/TingchenFu/MathIF)): evaluates instruction following in mathematical reasoning. The core idea is to use programmatically verifiable mathematical-task constraints to check whether models satisfy format, inclusion, and procedural requirements while solving problems.
- [LIFEBENCH](https://arxiv.org/abs/2505.16234) ([open-source code](https://github.com/LIFEBench/LIFEBench), [dataset](https://huggingface.co/datasets/LIFEBench/LIFEBench)): evaluates length instruction following. The core idea is to test explicit long-output length constraints, such as word-count or token-count requirements, and expose premature termination, undershooting, and refusal on outputs that should be long but structurally simple.
- [AgentIF](https://arxiv.org/abs/2505.16944) ([open-source code](https://github.com/THU-KEG/AgentIF)): evaluates long system prompts, tool descriptions, and complex constraint following in agentic settings. The core idea is to collect long instructions from real industrial and open-source agent applications and annotate constraints with code/LLM/hybrid evaluators.
- [MARS-Bench](https://arxiv.org/abs/2505.23810) (dataset: [LeeeeTX/MARS-Bench](https://huggingface.co/datasets/LeeeeTX/MARS-Bench)): evaluates instruction following and dialogue quality in multi-turn real-world scenario conversations. The core idea is to measure the stability of constraint execution in a multi-turn setting closer to real interaction.
- [MaXIFE](https://aclanthology.org/2025.acl-long.698/): evaluates multilingual and cross-lingual instruction following. The core idea is to test whether models preserve verifiable constraints when the instruction language, response language, or cross-lingual transfer setting changes.
- [LIFBench](https://aclanthology.org/2025.acl-long.803/): evaluates instruction-following performance and stability in long-context scenarios. The core idea is to test whether constraints remain active after long inputs rather than only measuring retrieval from the same context window.
- [IFBench](https://arxiv.org/abs/2507.02833): evaluates generalization of verifiable instruction following to unseen constraints. The core idea is to add 58 programmatically verifiable out-of-domain constraint types and avoid overfitting to a small set of IFEval-style template constraints.
- [IFScale](https://arxiv.org/abs/2507.11538) ([open-source code](https://github.com/DistylAI/distylai.github.io)): evaluates how constraint following degrades as the number of instructions scales. The core idea is to increase the number of keyword-inclusion instructions that must be satisfied simultaneously from 10 to 500 and observe failure modes under high constraint load.
- [Inverse IFEval](https://arxiv.org/abs/2509.04292) (dataset: [m-a-p/Inverse_IFEval](https://huggingface.co/datasets/m-a-p/Inverse_IFEval)): evaluates whether models still strictly follow instructions under "inverse instructions" or debiasing settings. The core idea is to use inverse-instruction construction to measure resistance to templated-output inertia and instruction robustness.
- [CMT-Eval](https://aclanthology.org/2025.findings-emnlp.992/): Evaluates Chinese multi-turn dialogue under real-world conversational challenges. Core idea: stress whether models preserve context, satisfy evolving user intent, and handle realistic interaction difficulties across dialogue trajectories rather than isolated single-turn instructions.
- [EvolIF](https://arxiv.org/abs/2511.03508): evaluates dynamically evolving multi-turn instruction following. The core idea is to use a query-synthesis agent and a three-layer state-tracking mechanism to simulate continuous constraint additions, state changes, and failure recovery before user patience runs out.
- [LexInstructEval](https://ojs.aaai.org/index.php/AAAI/article/view/39701): evaluates lexical instruction following. The core idea is to test fine-grained word-level and surface-form constraints that are easy to state but often lost in broader semantic instruction-following benchmarks.
- [VIFBENCH](https://arxiv.org/abs/2601.17789): evaluates fine-grained judgment capability for instruction-following verifiers. The core idea is to decompose whether an output follows instructions into labeled constraint-satisfaction judgments, focusing on verifiers rather than only generation models.
- [CL-Bench](https://arxiv.org/abs/2602.03587): also leans toward context learning, but it is useful for diagnosing "whether rules are followed over the long term." The core idea is to expose the boundaries of instruction following through more systematic long-context settings.
- [SEQUOR](https://arxiv.org/abs/2605.06353): evaluates realistic constraint following in long multi-turn dialogue. The core idea is to place added, replaced, and conflicting constraints in the same protocol, specifically testing long-dialogue drift.
- [DMT-RoleBench](https://doi.org/10.1609/aaai.v39i24.34768): Evaluates role-playing LLMs and agents through dynamic multi-turn dialogues. Core idea: generate dialogue trajectories under evaluation intents and topics so role consistency, instruction adherence, and interaction quality are tested closer to real role-play usage than static prompts.
