# 1.9 General Reasoning (Including Visual Puzzles)

> Parent chapter: 1. Foundational Capabilities


## 1.9.1 Leaderboard

- [LiveBench](https://livebench.ai/) ([code](https://github.com/LiveBench/LiveBench)): A continuously updated comprehensive LLM leaderboard with time-sliced reasoning, mathematics, coding, data analysis, and language tasks; suitable as a recent reference for general reasoning models.
- [ARC Prize Leaderboard](https://arcprize.org/leaderboard) ([community leaderboard](https://arcprize.org/leaderboard/community)): The official competition leaderboard for ARC-AGI-2 and ARC-AGI-3, especially suitable for observing the practical effects of `program synthesis + executor + search`, multi-agent trial and error, and interactive agents in game environments.
- [Reasoning Gym Eval](https://github.com/open-thought/reasoning-gym-eval): An open-source evaluation leaderboard and scripts around REASONING GYM, suitable for tracking reasoning and test-time scaling methods on generative and verifiable tasks.

## 1.9.2 Bench

- [ARC (ARC-AGI-1)](https://github.com/fchollet/ARC): What it evaluates: abstract reasoning and induction through small-grid transformations and rule induction; core idea: place tiny data and strong out-of-distribution generalization at the center, forcing methods to rely on program induction/rule extraction rather than language templates.
- [BIG-Bench Hard](https://arxiv.org/abs/2210.09261) ([code](https://github.com/suzgunmirac/BIG-Bench-Hard)): What it evaluates: manually selected hard reasoning subtasks from BIG-Bench; core idea: a common chain-of-thought baseline set covering symbolic, commonsense, algorithmic, and language inference.
- [AGIEval](https://arxiv.org/abs/2304.06364) ([code](https://github.com/ruixiangcui/AGIEval)): What it evaluates: general reasoning from standardized tests and human ability tests; core idea: supplement synthetic tasks with problem types closer to human exams, covering language, mathematics, logic, and professional knowledge.
- [MuSR](https://arxiv.org/abs/2310.16049) ([code](https://github.com/Zayne-sprague/MuSR)): What it evaluates: multi-step soft reasoning, including murder mystery, object placement, and team allocation tasks; core idea: require models to maintain constraints in long prompts and progressively eliminate candidates.
- [GPQA](https://arxiv.org/abs/2311.12022) ([code](https://github.com/idavidrein/gpqa)): What it evaluates: graduate-level, search-resistant scientific QA; core idea: emphasize expert-level reasoning and resistance to data leakage, often used as a hard-problem baseline for general reasoning models.
- [LiveBench](https://arxiv.org/abs/2406.19314) ([code](https://github.com/LiveBench/LiveBench)): What it evaluates: continuously updated tasks including reasoning, mathematics, coding, language, and data analysis; core idea: reduce contamination through temporal updates and automatic grading, making it suitable for recent capability tracking.
- [LogicVista](https://arxiv.org/abs/2407.04973) ([code](https://github.com/Yijia-Xiao/LogicVista)): What it evaluates: visual logical reasoning, closer to "solving logic problems/puzzles from images"; core idea: ground logical constraints in visible structures through visual puzzles, reducing shortcuts in pure-text reasoning.
- [ProcBench](https://arxiv.org/abs/2410.03117) ([code](https://github.com/ifujisawa/proc-bench); [dataset](https://huggingface.co/datasets/ifujisawa/procbench)): What it evaluates: multi-step reasoning and the ability to execute procedures; core idea: make procedural/stepwise correctness the main evaluation target, reducing the accidentality of only checking final answers.
- [ARC-AGI-2 (ARC Prize)](https://github.com/arcprize/ARC-AGI-2): What it evaluates: ARC-family capability with stronger emphasis on generalization and resistance to leaderboard-tuning strategies; core idea: typical effective solutions are tightly bound to a `DSL / program synthesis + executor + scoring/search` benchmark-specific runtime rather than pure conversational prompting.
- [VPCT](https://huggingface.co/datasets/camelCase12/vpct-1): What it evaluates: visual pattern and rule-completion puzzles; core idea: focus on pattern completion/inference and often test whether models can extract generative rules from visual structures.
- [iVISPAR](https://arxiv.org/abs/2502.03214): What it evaluates: interactive visual-spatial reasoning and planning; core idea: adapt sliding puzzles into an interactive environment for VLM agents, measuring spatial planning ability across 2D, 3D, and text modalities.
- [ZEROBench](https://arxiv.org/abs/2502.09696) ([code](https://github.com/jonathan-roberts1/zerobench)): What it evaluates: generalization and robustness on visual puzzles/pattern tasks; core idea: emphasize a "zero-shot transfer" style stress test to check whether models rely on shortcuts from the training distribution.
- [NaturalReasoning](https://arxiv.org/abs/2502.13124) (dataset: [facebook/natural_reasoning](https://huggingface.co/datasets/facebook/natural_reasoning)): What it evaluates: natural reasoning problems from real sources. Core idea: use 2.8 million difficult problems across STEM, economics, social sciences, and other domains to cover more natural reasoning distributions, supporting both training and evaluation.
- [VisualQuest](https://arxiv.org/abs/2503.19936): What it evaluates: abstract visual reasoning and integration of symbolic, cultural, and linguistic knowledge; core idea: use non-photographic, stylized images and targeted questions to check whether models can combine visual recognition with abstract semantic inference.
- [VGRP-Bench](https://arxiv.org/abs/2503.23064): What it evaluates: visual grid reasoning puzzles; core idea: use 20 types of grid puzzles across difficulty levels to systematically control clue count, grid size, and rule complexity, diagnosing LVLM bottlenecks in perception, rule understanding, and logical reasoning.
- [GraphOmni](https://arxiv.org/abs/2504.12764) ([code](https://github.com/GAI-Community/GraphOmni)): What it evaluates: understanding, reasoning, and generation on graph-theoretic tasks. Core idea: organize graph-structure parsing, algorithmic reasoning, and graph-generation tasks into an extensible benchmark framework, filling a gap in general reasoning coverage for structured objects.
- [VisuLogic](https://arxiv.org/abs/2504.15279) ([code](https://github.com/VisuLogic-Benchmark/VisuLogic-Eval)): What it evaluates: visual logic and rule inference; core idea: tightly couple logical reasoning with visual structures and emphasize diagnosable categories of logical errors.
- [SeePhys](https://arxiv.org/abs/2505.19099): What it evaluates: image-based physical reasoning; core idea: make visual elements necessary for solving, using problems across education stages and physics subfields to expose model failures when textual shortcuts are unavailable.
- [REASONING GYM / Reasoning Gym Eval](https://arxiv.org/abs/2505.24760): What it evaluates: programmatic reasoning environments with verifiable rewards; core idea: use generative and gradeable task families covering logical, algorithmic, symbolic, and combinatorial reasoning, suitable as a general harness for reinforcement learning and test-time search.
- [ZebraLogic](https://proceedings.mlr.press/v267/lin25i.html) ([leaderboard](https://huggingface.co/spaces/WildEval/ZebraLogic), [dataset](https://huggingface.co/datasets/allenai/ZebraLogicBench)): What it evaluates: logic-grid puzzles with controllable complexity and CSP-style deductive reasoning. Core idea: observe where model reasoning collapses as the search space grows by controlling the number of variables, constraints, and conflict structures.
- [TurnBench-MS](https://arxiv.org/abs/2506.01341): What it evaluates: state maintenance and constraint updates in multi-turn, multi-step reasoning; core idea: split the reasoning process across successive interaction turns and test whether models maintain consistent decisions as information changes.
- [ENIGMATA-Eval](https://papers.neurips.cc/paper_files/paper/2025/hash/058460c719f190500568b341bd06875f-Abstract-Conference.html) ([project page](https://seed-enigmata.github.io/)): What it evaluates: generative and verifiable logical-puzzle reasoning. Core idea: use 36 puzzle families for both RLVR training and standalone evaluation, emphasizing programmatically generated questions, verifiable answers, and controllable difficulty.
- [LTD-Bench](https://arxiv.org/abs/2511.02347) ([code](https://github.com/walktaster/LTD-Bench), [dataset](https://huggingface.co/datasets/walktaster/LTD_Bench)): What it evaluates: reasoning over language and spatial concepts by asking models to "draw it." Core idea: require models to draw with grids or executable code, placing abstract language understanding, geometric relations, and visual output alignment into one decidable task.
- [ARC-AGI-3](https://arxiv.org/abs/2603.24621) ([official page](https://arcprize.org/arc-agi/3/); [developer tools](https://github.com/arcprize/ARC-AGI-3-Agents)): What it evaluates: interactive program induction and game-like task solving; core idea: move ARC from static grid completion to actionable environments, requiring agents to learn new rules through observation, exploration, state memory, and strategy search.

## 1.9.3 Agent Harness

- [ReAct](https://arxiv.org/abs/2210.03629) ([code](https://github.com/ysymyth/ReAct)) alternates reasoning traces with tool/environment actions, an early strong baseline for general reasoning agents.
- [Reflexion](https://arxiv.org/abs/2303.11366) ([code](https://github.com/noahshinn/reflexion)) converts failed trajectories into language feedback and episodic memory for the next attempt.
- [Tree of Thoughts](https://arxiv.org/abs/2305.10601) ([code](https://github.com/princeton-nlp/tree-of-thought-llm)) is a representative search-style test-time harness that tree-structures the reasoning process.
- ARC-AGI-solution ([code](https://github.com/aviad12g/ARC-AGI-solution); no standalone paper): An engineering-oriented ARC solving agent guided by LLM-based DSL search.
- [RAP](https://arxiv.org/abs/2305.14992) ([code](https://github.com/Ber666/RAP)) places stronger emphasis on reasoning as a planning problem.
- [Graph of Thoughts](https://arxiv.org/abs/2308.09687) ([code](https://github.com/spcl/graph-of-thoughts)) generalizes ToT's tree structure into graph-style intermediate states, supporting merging, aggregation, and more complex reasoning topologies.
- [LATS](https://arxiv.org/abs/2310.04406) ([code](https://github.com/lapisrocks/LanguageAgentTreeSearch)) incorporates planning, evaluation, and search more systematically into the agent loop.
- [PlanGEN](https://arxiv.org/abs/2502.16111): A multi-agent inference-time harness for complex planning and reasoning; design keywords: constraint agent, verification agent, selection agent, adaptive selection among BoN/ToT/REBASE.
- [AB-MCTS for ARC-AGI-2](https://arxiv.org/abs/2503.04412) ([code](https://github.com/SakanaAI/ab-mcts-arc2)): Explicitly models ARC-AGI-2 as a tree-search problem over program space; design keywords: MCTS, program-space search, multi-model adjudication.
- [VerifiAgent](https://arxiv.org/abs/2504.00406) ([code](https://github.com/Jiuzhouh/VerifiAgent)): A unified verification agent that adds meta-verification and tool-adaptive verification to reasoning; design keywords: math/logic/commonsense tool selection, feedback revision, inference scaling.
- [VSA for ARC-AGI](https://arxiv.org/abs/2511.08747) ([code](https://github.com/ijoffe/ARC-VSA-2025)): Recasts ARC-AGI as a more explicit neuro-symbolic program-induction problem; design keywords: neuro-symbolic, verifiable execution.
- [Executable World Models for ARC-AGI-3](https://arxiv.org/abs/2605.05138) ([code](https://github.com/alexisfox7/RGB-Agent)): A Read-Grep-Bash agent for the ARC-AGI-3 leaderboard; design keywords: executable world models, file-based environment observation, shell tool use, maintaining task state through code and logs.

## 1.9.4 Skill

- [skill-with-prompt-engineering](https://github.com/openclaw/skills/tree/main/skills/golofu/skill-with-prompt-engineering) includes directly reusable reasoning patterns such as `CoT / ReAct / self-consistency / multi-path reasoning`.
- [sympy](https://github.com/davila7/claude-code-templates/tree/main/cli-tool/components/skills/scientific/sympy) is suitable for converting intermediate reasoning into executable programs or symbolic expressions.
- [long-context](https://github.com/davila7/claude-code-templates/tree/main/cli-tool/components/skills/ai-research/emerging-techniques-long-context) is suitable for maintaining search-tree summaries, failed branches, and state compression.
