# 3.2 Research

> Parent section: 3. Downstream Applications


## 3.2.1 Leaderboard

- [MLE-bench Leaderboard / Official Results](https://github.com/openai/mle-bench): The official OpenAI MLE-bench repository maintains public results and submission instructions; useful for tracking reproducible performance of ML engineering agents such as AIDE, MLE-STAR, MLEvolve, Famou-Agent, and MARS+ on Kaggle-derived tasks.
- [PaperBench Leaderboard / Official Results](https://github.com/openai/frontier-evals/blob/main/project/paperbench/README.md): The official PaperBench entry in OpenAI Frontier Evals; useful for comparing long-horizon research-coding agents under paper reproduction, code development, and rubric grading.
- [MLRC-Bench Leaderboard](https://huggingface.co/spaces/launch/MLRC_Bench): The official Hugging Face leaderboard for MLRC-Bench; useful for observing agents' ability to advance more open ML research challenges.
- [ResearchCodeBench Leaderboard](https://researchcodebench.github.io/leaderboard/index.html): The official ResearchCodeBench leaderboard; useful for comparing whether models and coding agents can implement unseen research code from recent ML papers.
- [SciArena](https://sciarena.allen.ai/): An open evaluation platform for AI2 scientific-literature tasks; useful for tracking scientific literature understanding, cross-paper synthesis, citation-backed answers, and user-preference evaluation.
- [AstaBench Leaderboard](https://huggingface.co/spaces/allenai/asta-bench-leaderboard): The AI2 AstaBench leaderboard; useful for unifying literature understanding, tool use, and science-research tasks into one science-agent evaluation view.
- [CORE-Bench / CORE-Bench Hard](https://hal.cs.princeton.edu/corebench_hard): HAL's CORE-Bench Hard leaderboard; useful for tracking agents' performance on real paper reproducibility tasks.

## 3.2.2 Bench

- [MLAgentBench](https://arxiv.org/abs/2310.03302) ([open-source code](https://github.com/snap-stanford/MLAgentBench)): Evaluates end-to-end automation of machine-learning research tasks. Core idea: package research tasks, execution environments, and scoring protocols into a reproducible platform, measuring whether agents can actually produce runnable experiments and effective improvements.
- [DiscoveryBench](https://arxiv.org/abs/2407.01725) ([open-source code](https://github.com/allenai/discoverybench)): Evaluates data-driven scientific discovery. Core idea: use real scientific data and hypothesis generation/verification workflows to evaluate whether agents can propose and test meaningful scientific conclusions.
- [SciCode](https://arxiv.org/abs/2407.13168) ([open-source code](https://github.com/scicode-bench/SciCode)): Evaluates scientific coding for real research problems. Core idea: problems are scientist-curated, provide gold solutions/tests, and decompose research problems into subproblems requiring knowledge recall, reasoning, and code synthesis.
- [CORE-Bench / CORE-Bench Hard](https://arxiv.org/abs/2409.11363): Evaluates computational reproducibility of published research. Core idea: convert papers, code, data, and execution environments into reproduction tasks operated by agents, serving as an important baseline for the "research reproduction" line before PaperBench; HAL separately maintains CORE-Bench Hard as an entry for a harder reproducibility subset.
- [MLE-bench](https://arxiv.org/abs/2410.07095) ([open-source code](https://github.com/openai/mle-bench)): Evaluates machine-learning engineering and data-science competition modeling across 75 Kaggle competitions, scored by competition metrics after generating `submission.csv` and aggregated with `Any Medal`. Core idea: put data loading, EDA, feature engineering, model selection, tuning, training, validation, submission-format repair, and long experiment iteration from real ML engineering into one executable benchmark; the official release also provides a 22-task Low/Lite split to reduce the 3.3TB data and 24-hour run cost of full evaluation.
- [RE-Bench](https://arxiv.org/abs/2411.15114) ([open-source code](https://github.com/METR/RE-Bench)): Evaluates real research-engineering tasks in AI R&D automation, covering open-ended R&D work such as algorithm design, experiment execution, and result analysis. Core idea: complement MLE-bench's Kaggle competition protocol by emphasizing research-engineer-style problem solving, code experiments, and research judgment.
- [MLGym](https://arxiv.org/abs/2502.14499) ([open-source code](https://github.com/facebookresearch/MLGym)): Evaluates interactive ML research environments and benchmarks for AI research agents. Core idea: turn open-ended machine-learning research tasks into Gym-style environments so agents can repeatedly experiment, observe results, and improve research plans.
- [BixBench](https://arxiv.org/abs/2503.00096) ([open-source code](https://github.com/Future-House/BixBench), [dataset](https://huggingface.co/datasets/futurehouse/BixBench)): Evaluates agents on real bioinformatics data-analysis tasks. Core idea: derive multi-step open-ended questions from Code Ocean capsules, requiring agents to explore data, run analysis, and explain results, emphasizing scientific data analysis rather than paper QA alone.
- [SciReplicate-Bench](https://arxiv.org/abs/2504.00255) ([open-source code](https://github.com/xyzCS/SciReplicate-Bench)): Evaluates algorithm reproduction from recent research papers. Core idea: require agents to understand algorithm descriptions in papers, retrieve dependencies, and write executable code, jointly measuring research reproduction ability with reasoning graph accuracy and execution accuracy.
- [PaperBench](https://arxiv.org/abs/2504.01848): Evaluates reading papers and reproducing experiments/implementations in a fresh sandbox, followed by rubric grading. Core idea: treat "can actually reproduce/run it" as the core acceptance criterion, emphasizing sandbox reruns and rubric judges rather than superficial similarity of generated code.
- [MLRC-Bench](https://arxiv.org/abs/2504.09702) ([Leaderboard](https://huggingface.co/spaces/launch/MLRC_Bench)): Evaluates agent performance on machine-learning research challenges from more open ML research-challenge scenarios. Core idea: push "can complete competition modeling" further toward "can advance research challenges," making it a transitional evaluation between MLE-bench and MLR-Bench.
- [BAISBench](https://arxiv.org/abs/2505.08341) ([open-source code](https://github.com/ErpaiLuo/BAISBench), [dataset](https://huggingface.co/datasets/ErpaiLuo/BAISBench)): Evaluates biology AI scientists driven by omics data. Core idea: use real single-cell transcriptomics data to construct cell-type annotation and scientific discovery QA, assessing whether agents can derive meaningful biological conclusions from experimental data.
- [MLR-Bench](https://arxiv.org/abs/2505.19955) ([open-source code](https://github.com/chchenhui/mlrbench)): Evaluates open-ended machine-learning research, from idea to proposal to experimentation to paper writing, with both end-to-end and staged evaluation. Core idea: provide `MLR-Judge` and `MLR-Agent` scaffolds to make the research process reproducible and reviewable, explicitly exposing reliability failure modes such as experiment fabrication or invalid results.
- [EXP-Bench](https://arxiv.org/abs/2505.24785) ([open-source code](https://github.com/Just-Curieous/Curie/tree/main/benchmark/exp_bench)): Evaluates whether AI agents can complete full AI research experiments. Core idea: given a research question and incomplete starter code, require agents to propose hypotheses, design experiments, implement, execute, and analyze results, directly evaluating end-to-end experimental ability.
- [ResearchCodeBench](https://arxiv.org/abs/2506.02314) ([project page](https://researchcodebench.github.io/); [open-source code](https://github.com/PatrickHua/ResearchCodeBench)): Evaluates implementation of unseen research code from the latest machine-learning papers. Core idea: construct 212 executable coding challenges from 2024-2025 top-conference papers, specifically testing whether models can translate new research contributions into code.
- [KRAMABENCH](https://arxiv.org/abs/2506.06541) ([project page](https://kramabench.org/); [open-source code](https://github.com/mitdbg/KramaBench), [dataset](https://huggingface.co/datasets/eugenie-y/KramaBench)): Evaluates data-to-insight pipelines over data lakes. Core idea: require agents to perform data discovery, cleaning, integration, statistical inference, and Python pipeline orchestration, covering open data-science research workflows beyond MLE-bench.
- [LLM Speedrunner](https://arxiv.org/abs/2506.22419) ([open-source code](https://github.com/facebookresearch/llm-speedrunner)): Evaluates agents reproducing NanoGPT speedrun improvements. Core idea: turn a living ML systems competition into executable reproduction tasks, requiring agents to understand a previous training script, implement a published speedup, and verify gains under the benchmark harness.
- [RExBench](https://arxiv.org/abs/2506.22598) ([project page](https://rexbench.com/)): Evaluates whether coding agents can implement AI research extensions. Core idea: give agents published papers and original codebases as context, ask them to implement expert-authored new experiments/extensions, and evaluate research-extension ability through automatic execution and metric checks.
- [SciArena](https://sciarena.allen.ai/SciArena_An_Open_Evaluation_Platform_for_Foundation_Models_in_Scientific_Literature_Tasks.pdf) ([platform](https://sciarena.allen.ai/)): Evaluates scientific literature understanding, synthesis, and citation-backed answers. Core idea: use an open evaluation platform to collect model performance on literature tasks, connecting literature-level understanding and user-preference evaluation to research-agent assessment.
- [Sci2Pol-Bench](https://arxiv.org/abs/2509.21493) ([open-source code](https://github.com/WeiminWu2000/Sci2Pol), [dataset](https://huggingface.co/datasets/Northwestern-CSSI/Sci2Pol-Bench)): Evaluates research translation from scientific papers to policy briefs. Core idea: split completion, understanding, summarization, generation, and verification into five-stage writing tasks, measuring whether models can turn scientific evidence into usable material for policy readers.
- [FML-bench](https://arxiv.org/abs/2510.10472) ([open-source code](https://github.com/qrzou/FML-bench)): Evaluates agents' iterative improvement ability on foundational machine-learning research problems. Core idea: provide baseline code, an evaluation harness, and a research-task description, requiring agents to iterate like researchers rather than only optimize application metrics.
- [PaperArena](https://arxiv.org/abs/2510.10909) ([project page](https://paperarena-ai.github.io/); [open-source code](https://github.com/Melmaphother/PaperArena)): Evaluates multi-paper, tool-assisted scientific literature reasoning. Core idea: require agents to call parsing, retrieval, computation, and other tools to integrate multi-format evidence from multiple papers into grounded answers.
- [AstaBench](https://arxiv.org/abs/2510.21652) ([open-source code](https://github.com/allenai/asta-bench); [Leaderboard](https://huggingface.co/spaces/allenai/asta-bench-leaderboard)): Evaluates comprehensive research-agent abilities. Core idea: unify literature retrieval, code execution, data analysis, scientific discovery, and other tasks in the Asta science-agent suite, with standardized tool environments and a public leaderboard for comparing agents.
- [ReplicationBench](https://arxiv.org/abs/2510.24591): Evaluates whether agents can reproduce the core contributions of experimental astrophysics papers. Core idea: split full papers into key tasks co-designed by original authors and evaluate faithfulness and correctness separately, closer to real research reproduction.
- [SGI-Bench](https://arxiv.org/abs/2512.16969) (paper: Probing Scientific General Intelligence of LLMs with Scientist-Aligned Workflows): Evaluates scientific general intelligence aligned with research workflows. Core idea: use scientist-aligned workflows as a unified protocol to assess end-to-end performance in retrieval, reasoning, experiment planning, and result organization.
- [AInsteinBench](https://arxiv.org/abs/2512.21373) ([open-source code](https://github.com/ByteDance-Seed/AInsteinBench)): Evaluates repository-level development ability in scientific computing/research software ecosystems, based on real scientific codebases and maintainer PR-derived tasks. Core idea: place scientific research software development back into the realistic context of executable environments, test verification, and science-semantic failure modes, measuring whether agents have research-grade engineering ability.
- [HeurekaBench](https://arxiv.org/abs/2601.01678) ([open-source code](https://github.com/mlbio-epfl/HeurekaBench), [project page](https://brbiclab.epfl.ch/projects/heurekabench/)): Evaluates AI co-scientists on real experimental-data-driven research problems. Core idea: use open-ended single-cell analysis tasks such as sc-HeurekaBench to evaluate whether co-scientist agents can propose testable hypotheses, execute analyses, and improve scientific conclusions with a critic module.
- [BABE](https://arxiv.org/abs/2602.05857): Evaluates "experimental reasoning" in biology over scientific materials where textual and visual evidence are intertwined. Core idea: emphasize integrating experimental results with contextual knowledge, testing causal reasoning and cross-scale inference rather than rote biological-knowledge QA.
- [AIRS-Bench](https://arxiv.org/abs/2602.06855) ([open-source code](https://github.com/facebookresearch/airs-bench)): Evaluates end-to-end research workflows for frontier AI research agents. Core idea: put idea generation, experiment analysis, and iterative revision into one task set, specifically observing whether agents can advance real AI research workflows.
- [MoSciBench](https://openreview.net/forum?id=kZHSvETWdi) ([open-source code](https://github.com/usail-hkust/MoSciBench)): Evaluates multimodal data-driven scientific discovery. Core idea: require agents to align heterogeneous data, model, explain, and complete hypothesis verification in end-to-end scientific tasks, linking multimodal understanding with scientific analysis workflows.
- [SciAgentGym / SciAgentBench](https://arxiv.org/abs/2602.12984) ([project page](https://www.huayusha.org/publication/SciAgentGym/)): Evaluates multi-step tool use by scientific agents. Core idea: provide 1,780 tasks across natural-science tools and hierarchical evaluation sets, specifically stress-testing tool orchestration from single-step calls to long-horizon workflows.
- [ResearchClawBench](https://github.com/InternScience/ResearchClawBench) ([dataset mirror](https://huggingface.co/datasets/InternScience/ResearchClawBench)): Evaluates end-to-end automated research from re-discovery to new-discovery in the OpenClaw/InternScience ecosystem. Core idea: package target papers, related work, data, figures, and multimodal checklist judging so agents can be scored on whether they match or surpass the original scientific paper rather than only answer literature questions.
- [BixBench-Verified-50](https://huggingface.co/datasets/phylobio/BixBench-Verified-50) (description: [Phylo blog](https://phylo.bio/blog/evaluating-ai-agents-in-biology)): Evaluates an expert-cleaned subset of BixBench. Core idea: remove or correct ambiguous questions and wrong answers so bioinformatics-agent scores are less affected by benchmark noise; recent systems such as BIOS, K-Dense Web, and BioResearcher have reported results on this subset.
- [SciPredict](https://arxiv.org/abs/2604.10718): Evaluates natural-science experiment outcome prediction. Core idea: isolate "can the result be judged before the experiment is run" as a scientific prediction task, testing whether LLMs/agents can move beyond knowledge QA to form verifiable experimental forecasts.
- [AutoResearchBench](https://arxiv.org/abs/2604.25256) ([project page](https://cheryou.github.io/autoresearchbench.github.io/); [open-source code](https://github.com/CherYou/AutoResearchBench)): Evaluates complex scientific literature discovery. Core idea: instantiate Deep Research and Wide Research tasks as 1,000 expert-curated questions, requiring agents either to precisely locate target papers or broadly collect paper sets satisfying conditions.
- [BioMysteryBench](https://www.anthropic.com/research/Evaluating-Claude-For-Bioinformatics-With-BioMysteryBench) ([dataset](https://huggingface.co/datasets/Anthropic/BioMysteryBench-full)): Evaluates open-ended research puzzles on real bioinformatics data. Core idea: experts pose questions objectively verifiable from experimental data, scoring final answers rather than fixed analysis paths, filling a gap for difficult open-ended biological data analysis.
- [BioMedArena](https://arxiv.org/abs/2605.06177) ([open-source code](https://github.com/AI-in-Health/BioMedArena)): Evaluates and trains biomedical deep research agents in a unified platform. Core idea: decouple benchmark loading, tool exposure, execution mode, context management, and scoring, connecting 147 biomedical benchmarks and 75 tools to reduce incomparability caused by inconsistent paper-specific harnesses.
- [PDEAgent-Bench](https://arxiv.org/abs/2605.09636): Evaluates executable numerical solver generation from PDE specifications. Core idea: use professional FEM libraries such as DOLFINx, Firedrake, and deal.II, evaluating scientific coding agents on runnability, numerical accuracy, and efficiency.
- [Ambig-DS](https://arxiv.org/abs/2605.09698): Evaluates whether data-science agents proactively clarify under task-framing ambiguity. Core idea: construct ambiguous target-variable/evaluation-goal tasks based on DSBench and MLE-bench, exposing hidden failures where artifacts run but the task was misunderstood.
- [SciIntegrity-Bench](https://arxiv.org/abs/2605.10246) ([open-source code](https://github.com/liuxingtong/Sci-Integrity-Bench)): Evaluates academic integrity of AI scientists. Core idea: construct dilemmatic scenarios where agents can only honestly admit failure and cannot complete by fabricating data/results, assessing whether agents commit academic misconduct under completion pressure.
- [Collider-Bench](https://arxiv.org/abs/2605.13950) (open-source code and task corpus are described in the paper): Evaluates reproduction of particle-physics experimental analyses. Core idea: require agents to reproduce simulation-and-selection pipelines from LHC papers and public software, scoring with continuous histogram metrics and trajectory audits, complementing real scientific reproducibility tasks.
- [GeneBench](https://cdn.openai.com/pdf/6dc7175d-d9e7-4b8d-96b8-48fe5798cd5b/oai_genebench_benchmark.pdf): Evaluates genetics multi-stage reasoning and data-analysis agents. Core idea: organize tasks with real data files, database queries, and multi-step inference, testing whether agents can form verifiable conclusions from complex life-science evidence.

## 3.2.3 Agent Harness

- [MLAgentBench Research Agent](https://arxiv.org/abs/2310.03302) ([open-source code](https://github.com/snap-stanford/MLAgentBench)) is the baseline research agent used for research-task evaluation in MLAgentBench.
- [BudgetMLAgent](https://arxiv.org/abs/2411.07464) (open-source code: not released) uses multi-agent collaboration, retrieval reuse, and LLM cascades for low-cost research-task automation on MLAgentBench, subject to the paper.
- [AIDE](https://arxiv.org/abs/2502.13138) ([open-source code](https://github.com/WecoAI/aideml)) represents the iterative code-experiment line for research/data-science agents and is one of the central open-source ML engineering agents in the official initial MLE-bench evaluation; its design focus is experiment-tree iteration via `propose experiment -> edit/run code -> inspect metric/log -> refine`, rather than one-shot modeling-script generation.
- [AI co-scientist](https://arxiv.org/abs/2502.18864) (open-source code: not released): Google Research's Gemini 2.0 multi-agent scientific hypothesis-generation system, centered on an asynchronous hypothesis tournament of `generate -> debate -> evolve`; it reports experimentally validated clues in drug repurposing, target discovery, and bacterial evolution mechanisms.
- [AI Scientist v2](https://arxiv.org/abs/2504.08066) ([open-source code](https://github.com/SakanaAI/AI-Scientist-v2)) emphasizes an end-to-end loop from research ideas to experiments and paper drafts.
- [Paper2Code](https://arxiv.org/abs/2504.17192) ([open-source code](https://github.com/going-doer/Paper2Code)) is specialized research-agent work for "paper to code implementation."
- [Robin](https://arxiv.org/abs/2505.13400) ([open-source code](https://github.com/Future-House/robin)) is FutureHouse's lab-in-the-loop multi-agent scientific discovery system; it connects literature search, hypothesis generation, experiment design, data analysis, and subsequent hypothesis updates, and completed experimental validation in a dAMD drug-candidate discovery case.
- [R&D-Agent](https://arxiv.org/abs/2505.14738) ([open-source code](https://github.com/microsoft/RD-Agent)) focuses on role-divided multi-agent workflow orchestration for R&D scenarios.
- [R&D-Agent-Quant](https://arxiv.org/abs/2505.15155) ([open-source code](https://github.com/microsoft/RD-Agent)) extends R&D-Agent to quantitative finance; its core workflow decomposes quant research into hypothesis-driven factor mining, code generation, backtesting feedback, and adaptive scheduling for joint factor-model optimization.
- [MLR-Agent](https://arxiv.org/abs/2505.19955) ([open-source code](https://github.com/chchenhui/mlrbench)) is the modular scaffold provided by the MLR-Bench paper, covering the four stages of idea, proposal, experiment, and writing.
- [MLE-STAR](https://arxiv.org/abs/2506.15692) ([open-source code](https://github.com/google/adk-samples/tree/main/python/agents/machine-learning-engineering)) is Google ADK's machine-learning engineering agent. Its core workflow is `web/search reference solutions -> generate baseline -> targeted refinement around bottlenecks`, making it an important strong open-source baseline after AIDE on MLE-bench.
- [ML-Master](https://arxiv.org/abs/2506.16499) ([open-source code](https://github.com/sjtu-sai-agents/ML-Master)) targets AI-for-AI machine-learning research tasks, integrating exploration and reasoning into a multi-role collaboration workflow; it is a representative research agent on MLE-bench/MLE tasks.
- [STELLA](https://arxiv.org/abs/2507.02004) (open-source code: no stable public repository found) is a self-evolving multi-agent system for biomedical research; its core is an evolving Template Library and dynamic Tool Ocean, allowing tool-creation agents to continuously discover and integrate new bioinformatics tools.
- [AIRA-dojo](https://arxiv.org/abs/2507.02554) ([open-source code](https://github.com/facebookresearch/aira-dojo)) is a "dojo-style research-agent behavior framework" for constructing and evaluating research-agent behaviors.
- [K-Dense Analyst](https://arxiv.org/abs/2508.07043) (open-source code: no stable public repository found) is a hierarchical multi-agent system for bioinformatics analysis. Core idea: connect high-level scientific goals, code execution, and result validation with a planning loop and validated execution loop.
- [RePro](https://arxiv.org/abs/2508.16671) (open-source code: no stable public repository found) emphasizes fine-grained verification and reflective repair, and is representative paper-reproduction-agent work in the PaperBench Code-Dev direction.
- DS-GURU ([open-source code](https://github.com/mitdbg/KramaBench); no standalone paper; the data-science agent paired with KRAMABENCH, decomposing data-lake insight tasks into subtasks and generating executable Python data-processing/analysis pipelines)
- [ToolUniverse](https://arxiv.org/abs/2509.23426) ([open-source code](https://github.com/mims-harvard/ToolUniverse)) is the tool ecosystem and MCP/SDK substrate for building AI scientists; it standardizes 1000+ scientific tools, models, databases, and APIs as callable components, and supports generating/optimizing tool interfaces from natural language.
- [AutoMLGen](https://arxiv.org/abs/2510.08511) ([open-source code](https://github.com/Alpha-Innovator/InternAgent)) provides fine-grained AutoML optimization navigation for coding agents; it reports medal rate and valid-submission metrics on MLE-bench and is a paper-version extension of the InternAgent/MLE engineering line.
- [MOSAIC](https://arxiv.org/abs/2510.08804) (open-source code: the paper says it will be released after acceptance) is a multi-agent scientific coding system for SciCode, decomposing, executing, and verifying scientific coding tasks through task-intelligent orchestration, and reporting main-problem/subproblem performance under the official SciCode protocol.
- [Famou-Agent](https://arxiv.org/abs/2510.26144) ([open-source code](https://github.com/baidubce/FM-Agent)) is a closed-loop coding and experimentation agent for machine-learning engineering tasks; in the MLE-bench context it is closer to a "competition modeling expert harness," emphasizing historical experience, experiment planning, execution feedback, and multi-round model/feature iteration.
- [Kosmos](https://arxiv.org/abs/2511.02824) (open-source code: no stable public repository found) is a long-running AI scientist for data-driven scientific discovery; through a structured world model, it connects literature-search and data-analysis agents and can continuously read papers, write code, generate hypotheses, and output traceable reports over 12-hour-scale runs.
- [ArchPilot](https://arxiv.org/abs/2511.03985) (open-source code: no stable public repository found) is a multi-agent machine-learning engineering framework for MLE-bench; compared with baselines such as AIDE and ML-Master, it emphasizes agent division of labor, model-solution search, and experiment-feedback-driven architecture improvement.
- [AgenticSciML](https://arxiv.org/abs/2511.07262) (open-source code: no stable public repository found) targets scientific machine-learning discovery; 10+ specialized agents jointly design SciML architectures, loss functions, and training strategies through structured debate, method memory, and evolutionary search.
- MLEvolve ([open-source code](https://github.com/InternScience/MLEvolve); no arXiv paper) is an evolutionary ML agent with public code on the MLE-bench leaderboard, emphasizing multiple candidate experiments, evolutionary search, and performance-feedback-driven solution iteration.
- InternAgent ([open-source code](https://github.com/InternScience/InternAgent); no arXiv paper) is an open-source agent system for deep research and ML engineering tasks, with public MLE-bench submissions; it can serve as an experiment-execution harness reference beyond AIDE / R&D-Agent.
- [Prompt-Free Collaborative Agents for Paper2Code](https://arxiv.org/abs/2512.02812) ([open-source code](https://github.com/going-doer/Paper2Code)) proposes a prompt-free collaborative-agent framework for Paper2Code.
- [DeepCode](https://arxiv.org/abs/2512.07921) (open-source code: no stable public repository found) is an open-ended agentic coding system compared with commercial agents and human baselines on PaperBench, representing follow-up work in paper reproduction and long-horizon code generation.
- [ML-Master 2.0 / Cognitive Accumulation](https://arxiv.org/abs/2601.10402) ([open-source code](https://github.com/sjtu-sai-agents/ML-Master)) extends ML-Master to ultra-long-horizon machine-learning engineering, emphasizing cross-stage cognitive accumulation, experience reuse, and long-duration experiment progress.
- [Deep Research](https://arxiv.org/abs/2601.12542) (open-source code: no stable public repository found) comes from "Rethinking the AI Scientist"; its core is specialized agents such as planner, data analysis, literature search, and novelty detection sharing a persistent world state, moving scientific discovery from offline batch processing to minute-scale interactive loops.
- [Execution-Grounded Automated AI Research](https://arxiv.org/abs/2601.14525) (open-source code: no stable public repository found) binds research-idea generation to real execution feedback. Core idea: have agents test ideas by running experiments rather than only generating plausible research proposals.
- [MARS / MARS+](https://arxiv.org/abs/2602.02660) (open-source code: no stable public repository found) is a modular reflective search agent for MLE-bench; the paper decomposes ML modeling into candidate solution generation, experiment execution, result reflection, branch search, ensemble/refinement, and related stages, representing a typical test-time search / reflective ML engineering harness.
- [ArchAgent](https://arxiv.org/abs/2602.22425) (code: no stable public repository found; an agentic computer-architecture discovery system built around automated design-space search; design keywords: cache-policy design, code generation, simulation feedback, competition-style evaluation)
- [SciDER](https://arxiv.org/abs/2603.01421) (open-source code: no stable public repository found) is a data-center-style end-to-end scientific research agent. Core idea: start from raw experimental data and automatically complete data processing, analysis, hypothesis formation, and report generation, complementing research agents focused only on papers or competition data.
- [OrchMAS](https://arxiv.org/abs/2603.03005) (code: no stable public repository found; a heterogeneous scientific-expert multi-agent orchestration framework; design keywords: two-tier orchestration, dynamic role and workflow adaptation, model routing, revision under divergent intermediate reasoning)
- [EvoScientist](https://arxiv.org/abs/2603.08127) ([open-source code](https://github.com/EvoScientist/EvoScientist)) is a self-evolving multi-agent AI scientist; with Researcher Agent, Engineer Agent, and Evolution Manager Agent plus persistent ideation and experimentation memory, it continuously improves research strategy and code-experiment ability from interaction history.
- [AIRA_2](https://arxiv.org/abs/2603.26499) (open-source code: no stable public repository found) is a direct extension of AIRA-dojo. It addresses bottlenecks in throughput, evaluation noise, and fixed operators with asynchronous multi-GPU execution, Hidden Consistent Evaluation, and ReAct operators, and continues reporting long-horizon results on MLE-bench-30.
- UniScientist ([official article](https://unipat.ai/blog/UniScientist), [open-source code](https://github.com/UniPat-AI/UniScientist), [model](https://huggingface.co/UnipatAI/UniScientist-30B-A3B); paper pending) is UniPat AI's scientific-research intelligence model and agentic inference framework; its core is Active Evidence Integration, Model Abduction, Evolving Polymathic Synthesis, and multi-rollout report aggregation.
- [Deep Researcher Agent](https://arxiv.org/abs/2604.05854) ([open-source code](https://github.com/Xiangyue-Zhang/auto-deep-researcher-24x7)) is an execution agent for deep-research-style harnesses, emphasizing multi-round retrieval, evidence compression, and conclusion generation.
- [Toward Autonomous Long-Horizon Engineering for ML Research](https://arxiv.org/abs/2604.13018) (open-source code: no stable public repository found) proposes long-horizon agent mechanisms for ML research engineering, evaluating collaboration/state-management designs such as File-as-Bus on PaperBench and MLE-Bench Lite.
- [AIBuildAI](https://arxiv.org/abs/2604.14455) ([open-source code](https://github.com/aibuildai/AI-Build-AI)) is an agent for automatically building AI models; its implementation focuses on automatically reading data, generating training and inference code, continuously running experiments, and fixing submissions, with automatic modeling results reported on MLE-bench.
- [EvoMaster](https://arxiv.org/abs/2604.17406) (open-source code: no stable public repository found) applies multi-agent collaboration and evolutionary search to scientific problem solving. Core idea: improve performance on difficult scientific reasoning tasks such as FrontierScience through hypothesis generation, candidate evolution, and validation feedback.
- [ARA / Agent-Native Research Artifacts](https://arxiv.org/abs/2604.24658) (open-source code: no stable public repository found) expands research artifacts from linear papers into executable, auditable agent-native artifacts, reporting improvements in review/reproduction workflows on PaperBench and RE-Bench.
- [SciResearcher](https://arxiv.org/abs/2605.01489) (open-source code: no stable public repository found) extends deep research agents to frontier scientific reasoning, emphasizing multi-round evidence integration, task decomposition, and stable gains on frontier scientific reasoning benchmarks.
- [PARNESS](https://arxiv.org/abs/2605.05258) ([open-source code](https://github.com/gtrhythm/PARNESS)) is a paper harness for end-to-end automated research; through dynamic YAML workflows, full-text indexing, code-repository indexing, and cross-run knowledge accumulation, it addresses rigidity in fixed-flow systems such as AI Scientist, AutoSOTA, and DeepResearch.
- [BioResearcher](https://arxiv.org/abs/2605.05985) (open-source code: no stable public repository found) is a scenario-guided multi-agent system for translational medicine, evaluated on biomedical benchmarks such as BixBench-Verified-50 for heterogeneous evidence synthesis, multi-omics analysis, and traceable report generation.
- [DataMaster](https://arxiv.org/abs/2605.10906) (open-source code: no stable public repository found) is a data-centered autonomous AI research agent evaluated on MLE-Bench Lite and PostTrainBench, treating data discovery, cleaning, modeling, and iterative optimization as a unified automated research process.
- [GEAR](https://arxiv.org/abs/2605.13874) (open-source code: no stable public repository found) uses genetic AutoResearch to maintain multiple research states, treating code, reflection, and performance trajectories as genetic units for population-based search; it is an evolutionary follow-up to the AIDE/AIRA/EvoScientist line.
