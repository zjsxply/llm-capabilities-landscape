# 1.8.3 Bench

Note: Mathematical evaluation for current reasoning models has clearly split into two main lines: `informal mathematical answering`, which emphasizes final answers or readable solution traces, and `formal proof`, which emphasizes proof-assistant verifiability and reproducible runtimes. Multimodal mathematics further incorporates problem statements and diagram information into the input, requiring OCR/parsing/diagram reasoning to work with symbolic computation.

- [MATH](https://arxiv.org/abs/2103.03874) ([Papers with Code MATH Leaderboard](https://paperswithcode.com/sota/problem-solving-on-math); [code](https://github.com/hendrycks/math)): What it evaluates: solving competition mathematics problems; core idea: broader coverage and higher difficulty, often paired with subsets such as `MATH-500` for quick comparison, making it suitable for characterizing improvements of reasoning models at competition difficulty.
- [miniF2F](https://arxiv.org/abs/2109.00110) ([code](https://github.com/openai/miniF2F)): What it evaluates: formal olympiad proofs across Lean, Metamath, Isabelle, and HOL Light; core idea: unify formal proofs into verifiable goals, suitable for evaluating end-to-end autoformalization and formal proving.
- [GSM8K](https://arxiv.org/abs/2110.14168) ([code](https://github.com/openai/grade-school-math)): What it evaluates: text-based mathematical reasoning over multi-step grade-school word problems; core idea: use frequent, reproducible elementary problem types to characterize basic arithmetic and multi-step reasoning chains, making it a common starting point for informal mathematics.
- [ProofNet](https://arxiv.org/abs/2302.12433) ([code](https://github.com/zhangir-azerbayev/ProofNet)): What it evaluates: formal proof for undergraduate mathematics problems; core idea: cover more proof patterns through systematic course-level problems, often used in combined "drafting to formalization" evaluation.
- [TheoremQA](https://arxiv.org/abs/2305.12524) ([code](https://github.com/wenhuchen/TheoremQA)): What it evaluates: theorem-driven mathematics and science QA; core idea: require models to identify applicable theorems and complete symbolic or numerical reasoning, making it an important bridge from word problems to theorem-grounded reasoning.
- [MathVista](https://arxiv.org/abs/2310.02255) ([leaderboard](https://mathvista.github.io/#leaderboard); [code](https://github.com/lupantech/MathVista)): What it evaluates: mathematical reasoning over charts, geometry, and visual problem statements; core idea: integrate visual-textual information into the mathematical solving chain, emphasizing coupling between visual parsing and symbolic reasoning.
- [CHAMP: A Competition-level Dataset for Fine-Grained Analyses of LLMs' Mathematical Reasoning Capabilities](https://arxiv.org/abs/2401.06961): Evaluates competition-level mathematical reasoning with fine-grained annotations over problem types and solution skills, enabling diagnosis beyond aggregate accuracy.
- [Evaluating LLMs' Mathematical and Coding Competency through Ontology-guided Interventions](https://arxiv.org/abs/2401.09395): Stress-tests math reward models on robustness to solution perturbations, exposing when verifier preferences fail to track correct reasoning.

- [$k$-server-bench: Automating Potential Discovery for the $k$-Server Conjecture](https://arxiv.org/abs/2604.07240): A code-based benchmark for automated mathematical discovery around the $k$-server conjecture. Core idea: ask agents to discover potential functions and use graph-structured linear-inequality checks as executable refutation signals.
- [Too long; didn't solve](https://arxiv.org/abs/2604.07593): Adds a benchmark or evaluation suite for math, centered on Too long; didn't solve.
- [MathNet](https://arxiv.org/abs/2604.18584) ([project page and results](https://mathnet.mit.edu/#results); [dataset](https://huggingface.co/datasets/shaden/MathNet)): What it evaluates: multilingual, multimodal olympiad problems and mathematical retrieval; core idea: put `problem solving + mathematical semantic retrieval + RAG` into one protocol, specifically testing both "can solve problems" and "can find similar problems."
- [Do LLMs Game Formalization? Evaluating Faithfulness in Logical Reasoning](https://arxiv.org/abs/2604.19459): Evaluates faithfulness in LLM logical formalization.
- [MathDuels](https://arxiv.org/abs/2604.21916): Evaluates LLMs as both problem posers and solvers. Core idea: move beyond fixed mathematical problem sets by testing whether models can generate challenging problems and solve opponent-generated ones, exposing capabilities hidden by near-saturated static benchmarks.
- [Benchmarking Testing in Automated Theorem Proving](https://arxiv.org/abs/2604.23698): Adds a benchmark or evaluation suite for math, centered on Benchmarking Testing in Automated Theorem Proving.
- [MATH-PT](https://arxiv.org/abs/2604.25926): A math-reasoning benchmark for European and Brazilian Portuguese. Core idea: evaluate mathematical reasoning in Portuguese variants instead of relying on English-only or translated math datasets.
- USAMO 2026 (reported in the [Claude Opus 4.7 system card](https://cdn.sanity.io/files/4zrzovbb/website/037f06850df7fbe871e206dad004c3db5fd50340.pdf)): What it evaluates: proof-based olympiad mathematics from the 2026 USA Mathematical Olympiad. Core idea: use recent proof-writing contest problems as a high-difficulty, lower-contamination complement to short-answer AIME-style tasks; this is a model-card evaluation reference rather than a standalone public benchmark package in this repository.
- [Beyond Benchmarks: MathArena as an Evaluation Platform](https://arxiv.org/abs/2605.00674): What it evaluates: extending MathArena from a one-off benchmark into a continuous mathematics evaluation platform; core idea: continuously add new competitions, new problem types, and unified protocols so the leaderboard rotates difficulty as model capabilities improve.
- [MathHalu](https://doi.org/10.1109/icassp55912.2026.11460764): What it evaluates: hallucination detection in mathematical reasoning processes. Core idea: score intermediate solution steps so plausible-looking but unsupported mathematical chains are visible before final-answer grading.
- [MathlibPR](https://arxiv.org/abs/2605.07147): A pull-request merge-readiness benchmark for formal mathematical libraries. Core idea: use real Mathlib4 PR histories to test whether models and agents can distinguish build-passing PRs that are ready to merge from those needing revision or rejection.
- [MathConstraint](https://arxiv.org/abs/2605.08498): Evaluates combinatorial reasoning with solver-verified, adaptively generated instances. Core idea: use parameterized constraint-satisfaction problems whose difficulty can scale with models, and test how sandboxed SAT/SMT tool access changes performance.
- [Soohak](https://arxiv.org/abs/2605.09063): A mathematician-curated benchmark for research-level mathematical reasoning. Core idea: use newly authored problems and a refusal subset for ill-posed questions to test whether models can reason at research level and decline unsupported problem statements; note that public dataset release is planned for late 2026.
- [Strategy Diversity Evaluation](https://arxiv.org/abs/2605.09292): Evaluates mathematical reasoning beyond final-answer accuracy. Core idea: annotate model solutions against AoPS-derived strategy families to measure whether models recover diverse valid solution approaches, not only correct answers.
- [FormalRewardBench: A Benchmark for Formal Theorem Proving Reward Models](https://arxiv.org/abs/2605.10141): Evaluates reward models for formal theorem proving. Core idea: measure whether learned reward models provide useful intermediate credit in proof-search settings where binary verifier rewards are sparse.
- [GeoBuildBench: A Benchmark for Interactive and Executable Geometry Construction from Natural Language](https://arxiv.org/abs/2605.13167): What it evaluates: interactive and executable geometry construction from natural language; core idea: ground informal geometry problems into checkable construction programs.
- [Formal Conjectures](https://arxiv.org/abs/2605.13171): An open and evolving Lean 4 benchmark for verified mathematical discovery. Core idea: formalize active research conjectures and solved problems so AI systems can attempt proof discovery and proof autoformalization under verifier-backed protocols.
- [MathAtlas: A Benchmark for Autoformalization in the Wild](https://arxiv.org/abs/2605.14061): Evaluates autoformalization in graduate and research-level mathematics. Core idea: build large-scale formalization tasks from real mathematical textbooks and materials rather than only olympiad-style problems.
- [CSLibPremiseBench: Structure-Guided Premise Retrieval and Label Robustness for Lean 4 Computer-Science Theorems](https://arxiv.org/abs/2605.14549): Evaluates premise retrieval and label robustness for Lean 4 computer-science theorems. Core idea: pin a real CSLib version and test source-visible theorem and lemma retrieval in a reproducible formal-proving setting.
- [First Proof Second Batch](https://arxiv.org/abs/2606.18119): The evaluation tests AI systems on ten research-level mathematics problems submitted by mathematicians across varied fields and publishes the problem statements, human solutions, AI outputs, referee reports, and execution logs, making correctness judgments inspectable beyond a single score.
- [FormalRx: Rectify and eXamine Semantic Failures in Autoformalization](https://arxiv.org/abs/2607.04655): Turns autoformalization from opaque pass-fail scoring into diagnostics with a 28-class SCI Error Taxonomy and FormalRx-Test; the supporting FormalRx-8B reaches 0.88 verdict F1, 0.71 categorization F1, 0.75 localization accuracy, and 0.73 correction accuracy.
- [MILPBench: A Large-scale Benchmark Test Suite for Mixed Integer Linear Programming Problems](https://doi.org/10.1145/3712256.3726324): Provides a large-scale mixed-integer linear programming test suite for comparing optimization solvers and learning-assisted MILP methods.
- [FGeo-Eval: Evaluation System for Plane Geometry Problem Solving](https://doi.org/10.3390/sym17060902): Evaluates plane-geometry problem solving with a dedicated system for parsing, solving, and scoring geometric tasks.
- [MathemaTikZ: A Dataset and Benchmark for Mathematical Diagram Generation](https://doi.org/10.1145/3698205.3729558): Benchmarks mathematical diagram generation by mapping problem descriptions to TikZ-style diagrams and scoring visual-symbolic fidelity.
- [A Multimodal AI System: Comparing LLMs and Theorem Proving Systems](https://doi.org/10.3390/electronics15040892): Compares LLMs with theorem-proving systems in a multimodal mathematical setting, using the comparison itself as an evaluation protocol.
- [MathEval: A Comprehensive Benchmark for Evaluating Large Language Models on Mathematical Reasoning Capabilities](https://doi.org/10.1007/s44366-025-0053-z): Evaluates comprehensive mathematical-reasoning evaluation. Core idea: make mathematical reasoning measurable with task-specific data, protocols, metrics, or diagnostic environments rather than generic aggregate scores.
- [Rethinking and Improving Autoformalization: Towards a Faithful Metric and a Dependency Retrieval-based Approach](): Provides a reusable evaluation target, leaderboard, or measurement protocol for mathematical reasoning.
- [Hot off the Press: Pareto-Optimal Fronts for Benchmarking Symbolic Regression Algorithms](https://doi.org/10.1145/3795101.3814639): Constructs absolute Pareto-optimal accuracy-complexity fronts for 34 SRBench datasets by exhaustive short-expression search and constant fitting, showing many methods remain far from the attainable frontier.
