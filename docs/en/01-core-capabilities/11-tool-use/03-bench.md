# 1.11.3 Bench

- [API-Bank](https://arxiv.org/abs/2304.08244) ([code](https://github.com/AlibabaResearch/DAMO-ConvAI/tree/main/api-bank)): What it evaluates: tool selection, argument filling, and multi-step calls by tool-augmented LLMs; core idea: protocolize tool sets and tasks, emphasizing executable call trajectories rather than pure-text answers.
- [Gorilla](https://arxiv.org/abs/2305.15334) ([code](https://github.com/ShishirPatil/gorilla)): What it evaluates: function/tool-calling capability under large-scale API connections; core idea: emphasize alignment with massive APIs and executable calls under function-signature constraints.
- [ToolQA](https://arxiv.org/abs/2306.13304) ([code](https://github.com/night-chen/ToolQA)): What it evaluates: correctness of answering questions through external tools, including multi-turn calls and use of tool returns; core idea: include the information gain from tool use in the evaluation protocol rather than only comparing fluency of language output.
- [ToolBench](https://github.com/OpenBMB/ToolBench) (source work: [ToolLLM](https://arxiv.org/abs/2307.16789); [official leaderboard](https://openbmb.github.io/ToolBench/)): What it evaluates: tool calling and multi-step execution over a large-scale set of real APIs; core idea: use API scale and executable evaluation as sources of pressure, covering tool retrieval, argument alignment, and execution-feedback loops.
- [ToolEyes: Fine-Grained Evaluation for Tool Learning Capabilities of Large Language Models in Real-world Scenarios](https://arxiv.org/abs/2401.00741): Evaluates real-world tool learning at fine granularity, separating tool selection, parameter filling, execution, and error modes instead of reporting only aggregate task success.
- [InfiAgent-DABench: Evaluating Agents on Data Analysis Tasks](https://arxiv.org/abs/2401.05507): Tests agents on data-analysis workflows that require reading datasets, invoking analysis tools, producing intermediate artifacts, and returning grounded analytic conclusions.
- [RoTBench: A Multi-Level Benchmark for Evaluating the Robustness of Large Language Models in Tool Learning](https://arxiv.org/abs/2401.08326): Stresses tool-learning robustness with multi-level perturbations, so models are judged on stable tool choice and argument use rather than performance on clean tool descriptions alone.
- [Planning, Creation, Usage: Benchmarking LLMs for Comprehensive Tool Utilization in Real-World Complex Scenarios](https://arxiv.org/abs/2401.17167): Splits comprehensive tool utilization into planning, tool creation, and tool usage, evaluating whether an LLM can move from task decomposition to usable tool execution in realistic scenarios.
- [BIRCO: A Benchmark of Information Retrieval Tasks with Complex Objectives](https://arxiv.org/abs/2402.14151): Evaluates retrieval systems on objectives more complex than topical relevance, making it useful for RAG agents that must satisfy constraints such as diversity, specificity, or evidence coverage.
- [R3: “This is My SQL, Are You With Me?” A Consensus-Based Multi-Agent System for Text-to-SQL Tasks](https://arxiv.org/abs/2402.14851): Borderline harness entry: the core artifact is a consensus multi-agent text-to-SQL system, with evaluation value coming from how agents reconcile SQL plans and execution results.
- [API-BLEND: A Comprehensive Corpora for Training and Benchmarking API LLMs](https://arxiv.org/abs/2402.15491): Provides API-oriented corpora for both training and benchmarking API LLMs, tying invocation tasks to API signatures and usage examples.
- [Retrieval Augmented Generation Systems: Automatic Dataset Creation, Evaluation and Boolean Agent Setup](https://arxiv.org/abs/2403.00820): Packages automatic RAG dataset creation with evaluation and a Boolean-agent setup, turning retrieval configuration and answer verification into the measured artifact.
- [Fine Tuning vs. Retrieval Augmented Generation for Less Popular Knowledge](https://arxiv.org/abs/2403.01432): Compares fine-tuning and retrieval augmentation on long-tail knowledge, making the tool-use signal the point at which external retrieval beats memorized parametric knowledge.
- [m&m's: A Benchmark to Evaluate Tool-Use for multi-step multi-modal Tasks](https://arxiv.org/abs/2403.11085): Evaluates multi-step multimodal tool use, requiring models to choose and sequence tools across image, text, and intermediate reasoning operations.
- [InspectorRAGet: An Introspection Platform for RAG Evaluation](https://arxiv.org/abs/2404.17347): Provides an introspection platform for RAG evaluation, exposing retrieval, context construction, and generation components so failures can be attributed to a specific pipeline stage.
- [FREB-TQA: A Fine-Grained Robustness Evaluation Benchmark for Table Question Answering](https://arxiv.org/abs/2404.18585): Tests table-question-answering robustness with fine-grained perturbations, relevant to tool use when table parsers or structured-query tools feed the final answer.
- [Assessing and Verifying Task Utility in LLM-Powered Applications](https://arxiv.org/abs/2405.02178): Evaluates whether LLM-powered applications actually deliver task utility, emphasizing verification of useful outcomes rather than only model-level response quality.
- [ALI-Agent: Assessing LLMs' Alignment with Human Values via Agent-based Evaluation](https://arxiv.org/abs/2405.14125): Uses agent-based evaluation to probe value alignment, making it a broader agent-evaluation item rather than a narrow function-calling benchmark.
- [Designing an Evaluation Framework for Large Language Models in Astronomy Research](https://arxiv.org/abs/2405.20389): Designs an astronomy-oriented LLM evaluation framework where domain retrieval, calculation, and research-question handling are evaluated as research-assistant capabilities.
- [DB-GPT-Hub: Towards Open Benchmarking Text-to-SQL Empowered by Large Language Models](https://arxiv.org/abs/2406.11434): Provides open benchmarking infrastructure for LLM-powered text-to-SQL, covering dataset handling, model comparison, and structured-query execution evaluation.
- [R-Eval: A Unified Toolkit for Evaluating Domain Knowledge of Retrieval Augmented Large Language Models](https://arxiv.org/abs/2406.11681): Offers a toolkit for evaluating domain knowledge in RAG systems, separating retrieval-backed grounding from ordinary closed-book answering.
- [FlowBench: Revisiting and Benchmarking Workflow-Guided Planning for LLM-based Agents](https://arxiv.org/abs/2406.14884): Evaluates workflow-guided planning, checking whether agents can follow decomposed process structures before invoking tools or producing final outputs.
- [ShortcutsBench: A Large-Scale Real-world Benchmark for API-based Agents](https://arxiv.org/abs/2407.00132): Uses real API-based shortcut tasks to evaluate whether agents can map user goals to executable API plans in a large and practical tool space.
- [What Affects the Stability of Tool Learning? An Empirical Study on the Robustness of Tool Learning Frameworks](https://arxiv.org/abs/2407.03007): Empirically measures how tool-learning frameworks degrade under changes to tool descriptions, demonstrations, or task settings, making stability itself the evaluation target.
- [GTA: A Benchmark for General Tool Agents](https://arxiv.org/abs/2407.08713) ([official leaderboard](https://open-compass.github.io/GTA/)): Evaluates general tool agents across diverse tasks and tool categories, with leaderboard-style comparison focused on planning and execution rather than single API calls.
- [VLMEvalKit: An Open-Source ToolKit for Evaluating Large Multi-Modality Models](https://arxiv.org/abs/2407.11691): Mainly an evaluation toolkit for VLM benchmarks; keep as adjacent tooling because it standardizes multimodal evaluation execution rather than defining a tool-use task by itself.
- [I Need Help! Evaluating LLM’s Ability to Ask for Users’ Support: A Case Study on Text-to-SQL Generation](https://arxiv.org/abs/2407.14767): Evaluates when a text-to-SQL system should request user support, turning ambiguity detection and clarification into part of the tool-use protocol.
- [Customized Retrieval Augmented Generation and Benchmarking for EDA Tool Documentation QA](https://arxiv.org/abs/2407.15353): Uses OpenROAD-style EDA documentation as a QA setting, comparing customized retrieval and answer generation for specialized tool manuals rather than generic web knowledge.
- [ConfReady: A RAG based Assistant and Dataset for Conference Checklist Responses](https://arxiv.org/abs/2408.04675): Releases a dataset and RAG assistant for conference-checklist responses, evaluating whether retrieval-backed systems can answer submission-compliance questions from official checklist text.
- [API-Guided Dataset Synthesis to Finetune Large Code Models](https://arxiv.org/abs/2408.08343): Primarily a data-synthesis and fine-tuning route for API-aware code models; its benchmark value is in generated API-usage examples and downstream invocation tests.
- [BFCL / Berkeley Function-Calling Leaderboard](https://arxiv.org/abs/2409.00608): What it evaluates: accuracy and robustness of function calling, including tool selection, argument alignment, and schema constraints. Core idea: use standardized function signatures and a unified leaderboard to isolate language ability from invocation correctness. ([official leaderboard](https://gorilla.cs.berkeley.edu/leaderboard.html))
- [NESTFUL: A Benchmark for Evaluating LLMs on Nested Sequences of API Calls](https://arxiv.org/abs/2409.03797): Benchmarks large language models on nested sequences of API calls, testing structured tool-use planning.
- [Revolutionizing Database Q&A with Large Language Models: Comprehensive Benchmark and Evaluation](https://arxiv.org/abs/2409.04475): Benchmarks database question answering with large language models.
- [Measuring and Enhancing Trustworthiness of LLMs in RAG through Grounded Attributions and Learning to Refuse](https://arxiv.org/abs/2409.11242): Evaluates whether RAG answers cite grounded evidence and refuse unsupported questions, using ASQA, QAMPARI, and ELI5-style settings to separate retrieval grounding from fluent fabrication.
- [RAD-Bench: Evaluating Large Language Models Capabilities in Retrieval Augmented Dialogues](https://arxiv.org/abs/2409.12558): Turns retrieval-augmented dialogue into a multi-turn benchmark, testing whether models can use retrieved context consistently across follow-up turns rather than answering each turn in isolation.
- [SEAL: Suite for Evaluating API-use of LLMs](https://arxiv.org/abs/2409.15523): Standardizes API-use evaluation with API retrieval, call planning, and a GPT-4-backed API simulator/cache so models can be compared without relying on live API availability.
- [IRSC: A Zero-shot Evaluation Benchmark for Information Retrieval through Semantic Comprehension in Retrieval-Augmented Generation Scenarios](https://arxiv.org/abs/2409.15763): Provides multilingual RAG retrieval tasks and semantic-comprehension metrics, including SSCI and RCCI, to check whether retrievers surface meaningfully usable evidence.
- [Automated test generation to evaluate tool-augmented LLMs as conversational AI agents](https://arxiv.org/abs/2409.15934): Generates procedure-grounded conversational tests from intermediate graphs, targeting customer-support agents whose tool calls must follow business process constraints.
- [Benchmarking Agentic Workflow Generation](https://arxiv.org/abs/2410.07869): Introduces WorfBench and WorfEval for workflow graphs, scoring generated workflows with subsequence and subgraph matching rather than only final natural-language answers.
- [NesTools: A Dataset for Evaluating Nested Tool Learning Abilities of Large Language Models](https://arxiv.org/abs/2410.11805): Focuses on nested tool calls where one call output parameterizes another, combining automatic task generation with manual refinement to expose failures hidden by flat function-calling tests.
- [Optimizing and Evaluating Enterprise Retrieval-Augmented Generation (RAG): A Content Design Perspective](https://arxiv.org/abs/2410.12812): Treats enterprise RAG evaluation as a content-design problem, showing how document structure, monitoring, and answer review change retrieval quality in deployed knowledge systems.
- [Benchmarking Floworks against OpenAI & Anthropic: A Novel Framework for Enhanced LLM Function Calling](https://arxiv.org/abs/2410.17950): Uses HubSpot CRM tasks to compare single-API and multi-API function calling, reporting accuracy together with reliability, latency, and cost for production-style API agents.
- [AppBench: Planning of Multiple APIs from Various APPs for Complex User Instruction](https://arxiv.org/abs/2410.19743): Tests multi-application API planning with graph execution order and permission constraints, so success depends on choosing the right cross-app call sequence.
- [Telco-DPR: A Hybrid Dataset for Evaluating Retrieval Models of 3GPP Technical Specifications](https://arxiv.org/abs/2410.19790): Builds a 3GPP technical-spec retrieval corpus with text and tables, synthetic QA pairs, and top-k accuracy or MRR scoring for telecom RAG systems.
- [Advancing Agentic Systems: Dynamic Task Decomposition, Tool Integration and Evaluation using Novel Metrics and Dataset](https://arxiv.org/abs/2410.22457): Evaluates task graphs with Node F1, step-sequence similarity, and Tool F1 on AsyncHow, making decomposition and tool integration explicit scoring targets.
- [ToolScan: A Benchmark for Characterizing Errors in Tool-Use LLMs](https://arxiv.org/abs/2411.13547): Characterizes seven tool-use error patterns across environments, turning failure diagnosis into the benchmark objective rather than only counting solved tasks.
- [Multi-modal Retrieval Augmented Multi-modal Generation: Datasets, Evaluation Metrics and Strong Baselines](https://arxiv.org/abs/2411.16365): Defines M2RAG for multimodal retrieval-augmented multimodal generation, pairing a curation pipeline with metrics that judge both retrieved multimodal evidence and generated outputs.
- [Multi-Reranker: Maximizing performance of retrieval-augmented generation in the FinanceRAG challenge](https://arxiv.org/abs/2411.16732): Documents a FinanceRAG competition system built from query expansion, corpus refinement, reranking, and long-context generation, useful as a retrieval-pipeline benchmark reference.
- [ConQRet: Benchmarking Fine-Grained Evaluation of Retrieval Augmented Argumentation with LLM Judges](https://arxiv.org/abs/2412.05206): Evaluates retrieval-augmented argumentation on controversial questions, using LLM judges to inspect evidence quality and fine-grained argument support.
- [HammerBench: Fine-Grained Function-Calling Evaluation in Real Mobile Device Scenarios](https://arxiv.org/abs/2412.16516): Uses mobile-device scenarios to diagnose function-call selection, parameter construction, and execution errors in a setting closer to phone-control assistants than synthetic API lists.
- [The HalluRAG Dataset: Detecting Closed-Domain Hallucinations in RAG Applications Using an LLM's Internal States](https://arxiv.org/abs/2412.17056): Provides sentence-level closed-domain RAG hallucination cases that include recency-sensitive evidence and internal-state signals for detecting unsupported answer spans.
- [An Evaluation Mechanism of LLM-based Agents on Manipulating APIs](https://doi.org/10.18653/v1/2024.findings-emnlp.267): Defines an API-manipulation evaluation mechanism for LLM agents, emphasizing endpoint choice, argument construction, and whether the manipulated API state matches the task.
- [RAGSQL: Context Retrieval Evaluation on Augmenting Text-to-SQL Prompts](https://doi.org/10.1109/is61756.2024.10705186): Evaluates retrieval as a text-to-SQL prompt augmentation step, isolating whether retrieved schema or context improves downstream SQL generation.
- [ToolComp: A Multi-Tool Reasoning & Process Supervision Benchmark](https://arxiv.org/abs/2501.01290): Introduces ToolComp for multi-tool reasoning and process supervision.
- [ToolHop: A Query-Driven Benchmark for Evaluating Large Language Models in Multi-Hop Tool Use](https://arxiv.org/abs/2501.02506): Provides 995 queries and 3,912 tools to evaluate interdependent multi-hop tool use with detailed feedback.
- [CallNavi, A challenge and empirical study on LLM function calling and routing](https://arxiv.org/abs/2501.05255): Bench candidate for tool use. Core idea: CallNavi, A challenge and empirical study on LLM function calling and routing.
- [ComplexFuncBench: Exploring Multi-Step and Constrained Function Calling under Long-Context Scenario](https://arxiv.org/abs/2501.10132): Benchmarks real-world complex function calling with multi-step constraints, long parameters, and 128K context.
- [ACEBench: Who Wins the Match Point in Tool Usage?](https://arxiv.org/abs/2501.12851): Evaluates tool usage in realistic multi-turn dialogue and broad scenarios. Core idea: make this capability comparable through a defined task set, protocol, or scoring interface.
- [RAG vs. GraphRAG: A Systematic Evaluation and Key Insights](https://arxiv.org/abs/2502.11371): Systematically evaluates retrieval-augmented generation against graph-structured retrieval variants, clarifying when graph retrieval helps tool-use systems.
- [MT-RAIG: Novel Benchmark and Evaluation Framework for Retrieval-Augmented Insight Generation over Multiple Tables](https://arxiv.org/abs/2502.11735): Introduces MT-RAIG for retrieval-augmented insight generation over multiple tables.
- [Evaluating Personalized Tool-Augmented LLMs from the Perspectives of Personalization and Proactivity](https://arxiv.org/abs/2503.00771): Benchmark/evaluation candidate for tool use and retrieval-augmented execution: Evaluates personalized and proactive tool-augmented LLMs.
- [Retrieval Models Aren't Tool-Savvy: Benchmarking Tool Retrieval for Large Language Models](https://arxiv.org/abs/2503.01763): Evaluates tool-retrieval evaluation for large language models. Core idea: make tool use measurable with task-specific data, protocols, metrics, or diagnostic environments rather than generic aggregate scores.

- [On the Robustness of Agentic Function Calling](https://arxiv.org/abs/2504.00914): Evaluates function-calling robustness in autonomous agents. Core idea: test natural query variation and toolkit expansion with semantically related tools.

- [ToolSpectrum : Towards Personalized Tool Utilization for Large Language Models](https://arxiv.org/abs/2505.13176): Evaluates personalized tool utilization by LLMs. Core idea: test tool selection under user-profile and environmental factors, not only functional matching to an explicit instruction.
- [Rethinking Stateful Tool Use in Multi-Turn Dialogues: Benchmarks and Challenges](https://arxiv.org/abs/2505.13328): Adds a benchmark or evaluation suite for tool use, centered on Rethinking Stateful Tool Use in Multi-Turn Dialogues: Benchmarks and Challenges.

- [MCP-RADAR](https://arxiv.org/abs/2505.16700): What it evaluates: tool-use capability under the MCP framework across six task categories: mathematics, search, email, calendar, files, and terminal; core idea: jointly measure answer correctness, operation accuracy, call turns, and resource efficiency, moving MCP from protocol support to quantifiable execution evaluation.

- [When2Tool](https://arxiv.org/abs/2605.09252) ([code](https://github.com/Trustworthy-ML-Lab/when2tool)): What it evaluates: when an agent should call tools and when it should answer directly; core idea: make tool necessity an explicit evaluation boundary, avoiding the mistaken interpretation that more tool calls mean stronger tool-use capability.
- [ComplexMCP](https://arxiv.org/abs/2605.10787): What it evaluates: LLM agents in dynamic, interdependent, large-scale tool sandboxes; core idea: include tool state, cross-tool dependencies, and environment changes in scoring, specifically testing fragile points in long-chain MCP tool execution.
- [MIRA: An LLM-Assisted Benchmark for Multi-Category Integrated Retrieval](https://arxiv.org/abs/2605.11254): Evaluates integrated retrieval across multiple content categories, using LLM assistance to build queries and labels that require category selection plus evidence aggregation.
- [When Simulation Lies: A Sim-to-Real Benchmark and Domain-Randomized RL Recipe for Tool-Use Agents](https://arxiv.org/abs/2605.11928): What it evaluates: sim-to-real transfer for tool-use agents. Core idea: stress agents whose policies work in simulated tool environments but fail when tool behavior shifts in real execution.
- [CodeGen-3D](https://doi.org/10.1109/ACCESS.2026.3654948): Evaluates zero-shot and iterative 3D modeling in Blender. Core idea: score executable modeling code, iteration reliability, and human-aligned 3D quality rather than only direct mesh or image generation.
- [Model-Adaptive Tool Necessity Reveals the Knowing-Doing Gap in LLM Tool Use](https://arxiv.org/abs/2605.14038): A bench candidate for tool use, with the title/abstract indicating a benchmark-style task, dataset, diagnostic protocol, or evaluation suite.
- [From Text to Voice: A Reproducible and Verifiable Framework for Evaluating Tool Calling LLM Agents](https://arxiv.org/abs/2605.15104): A reproducible evaluation framework for tool-calling agents in text-to-voice settings; core idea: test whether agents preserve tool selection, argument grounding, and verification when interaction moves beyond pure text.
- [TOBench / MM-ToolBench](https://arxiv.org/abs/2605.16909): Evaluates task-oriented omni-modal tool use across realistic professional workflows. Core idea: combine 27 MCP servers, 324 tools, rendered artifacts, and closed-loop multimodal verification so agents must execute tools, inspect outputs, and self-correct rather than only emit API calls.
- [τ³-Bench](https://sierra.ai/uk/resources/research/tau-3-bench): What it evaluates: agentic customer-interaction tasks that extend tau-style stateful tool use toward knowledge retrieval and voice settings. Core idea: keep realistic policies, state, and tool constraints while adding knowledge and voice-agent pressure beyond the original text/API tau-bench setup.
Note: This line is more about whether agents can correctly select tools, fill arguments, and handle multi-turn API orchestration, not just function-call accuracy.
- [HAL / Holistic Agent Leaderboard](https://hal.cs.princeton.edu/): What it evaluates: cross-benchmark agent capability, including tool-mediated tasks such as τ-bench alongside web, computer-use, and software settings. Core idea: aggregate public benchmark results into a transfer-oriented leaderboard so tool-use performance can be compared against broader agent execution.
- [Notation Matters](https://arxiv.org/abs/2605.29676): Evaluates token-optimized structured formats for agentic tool I/O. Core idea: compare JSON, TOON, TRON, and related notations inside tool schemas, execution results, and invocations, measuring whether format choice changes reliability and efficiency rather than treating serialization as a neutral implementation detail.
- [RedundancyBench](https://arxiv.org/abs/2605.29893): Evaluates redundant-step detection in agent trajectories. Core idea: annotate each trajectory step by contribution to task completion, making execution efficiency measurable instead of judging tool-using agents only by final success.
- [Diagnosing Knowledge Gaps in LLM Tool Use](https://arxiv.org/abs/2606.03657): Introduces NovelAPIBench for novel API acquisition. Core idea: automatically discover new APIs, extract knowledge packages, generate executable coding tasks, and separate retrieval gaps from parametric-adaptation gaps when agents face APIs outside their prior knowledge.
- [ToolMenuBench](https://arxiv.org/abs/2606.15508): Benchmarks tool-menu filtering for reliable and efficient agents. Core idea: vary menu size, distractor type, state-dependent structure, and risk exposure while reporting both filter-level metrics and downstream agent performance, so pruning a tool menu is judged by execution consequences.
- [Evaluating document chunking approaches for retrieval augmented generation in editorial content](https://doi.org/10.11591/ijai.v15.i2.pp1909-1918): Compares fixed, recursive, semantic, and LLM-based chunking for SaaS editorial-content RAG over 2,419 QA pairs, reporting retrieval and generation metrics.
- [Leveraging Large Language Models for Semantic Evaluation of RDF Triples](https://doi.org/10.5220/0013837600004000): Uses LLMs to judge semantic correctness of RDF triples, adjacent to structured-query tooling because it evaluates graph facts rather than API-call execution.
- [Design and Performance Evaluation of LLM-Based RAG Pipelines for Chatbot Services in International Student Admissions](https://doi.org/10.3390/electronics14153095): Compares dense, MMR, and hybrid retrieval with semantic and recursive chunking for admissions-chatbot RAG, measuring relevancy, faithfulness, context precision or recall, and latency.
- [TACO: A Benchmark for Open-Domain Text-to-SQL with Ambiguous and Cross-Database Queries](https://doi.org/10.14778/3797919.3797942): Provides 1,500 real and 13,000 synthetic open-domain text-to-SQL examples across smart-city and open-data portals, stressing ambiguous and cross-database queries.
- [Evaluation of LLM Performance in Tool Selection: A Feasibility Study on AI-Based Tool Development](https://doi.org/10.1007/s12541-026-01477-w): Feasibility study of LLM tool selection for AI-based tool development, useful as a low-confidence signal on routing among candidate tools rather than a mature benchmark suite.
